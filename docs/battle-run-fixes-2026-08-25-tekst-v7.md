# Правки машинерии по первому боевому прогону /seo-tekst v7.1

**Статус:** внесено 2026-08-25, четыре волны + финальный аудит. Не раскатано клиентам.
**Источник:** отчет прогона `texts/001-save-arch-soft` (saveschool.online, tier=basic, `--from-analysis`),
дошедшего до тон-гейта, ревизия 3. Все находки отчета воспроизведены на живой задаче.
**Тесты:** 86 -> 121 в наборе `/seo-tekst`; девять наборов машинерии зеленые (315 тестов).

## Волна 0 - P0: порча данных и выдуманные факты

| Дефект | Как выглядел | Решение |
|---|---|---|
| ИНН склеивался из всех цифр строки | факт «ИНН 240405032019 - в подвале прошлого лендинга (подтверждено 23.08.2026, ответ на вопрос 3)» давал `inn: "240405032019230820263"` | вычленяется единственная группа нужной длины (10/12, 13/15); ноль или несколько кандидатов - поле пустое, сырая строка в `jur.requisites_unresolved` |

**Почему это не поймали раньше:** верификаторы читают `page.json`, а выдумка жила в ОБОЛОЧКЕ, куда не смотрел никто.

## Волна 1 - кит и оболочка

`postfix-shell.mjs` (шесть заплаток поверх собранного html, написанных на прогоне) больше не нужен - все переехало в кит:
адрес ссылки стал слотом (`cta_href`, `items[].url`, дефолт `#lead` подставляет сборщик по `slot_defaults`),
кнопка под сеткой (`section_cta_label`/`section_cta_href`), плейсхолдеры изображений (`media_alt`),
слайдер отзывов (`opts.slider`), шеврон вместо кривой стрелки, меню с подменю из `site_manifest`,
бренд шапки отдельно от юрлица подвала, надпись кнопки оболочки параметризована.

**Мертвые ссылки - два класса, оба закрыты инвариантом:**
- якорь `#lead` зашит в ките, а форму можно снять по waiver F3 - сцепка двух корректных правил давала страницу, где ВСЕ кнопки ведут в никуда. Ассемблер переводит такие ссылки на `pt-shell-cta`;
- относительные адреса (`/arhitektura/`) в одностраничном документе уводят из файла - переводятся в `#p/<slug>` по `site_manifest.pages[].url`.
`verify-prototype` не пропускает ни те, ни другие и научен читать waiver F3 (раньше страница, сделанная строго по решению заказчика, рапортовала брак).

## Волна 2 - контракты

- **FAQ при tier=basic.** Слово «FAQ» покрывало две разные работы. Введен блок **33к «Вопросы и ответы (конверсионный)»** - вопросы из `audience.json`, без Schema.org и без подбора запросов, разрешен при любом tier. SEO-FAQ остается платной работой `/seo-faq`.
- **`limits` структурой** `{min, max, exactly, count, skip, note}`: `note` не парсится никогда. Раньше валидатор вычитывал числа из ПОЯСНЕНИЯ и блокировал блок, из которого заказчик элементы прямо убрал.
- **`verbatim`**: формулировка заказчика лимиту не подчиняется («Обучение» - 8 знаков при каталожном 20-60).
- **Буквальность правки гейта**: расширение области - вопрос, а не решение агента.
- **18 алиасов имен блоков** + нормализованный лукап.
- **Сортировка docx**: позиционное потребление `order_hint` вместо `indexOf`; клиентское имя блока - `title_client`. Планировщику больше не надо врать каталожными именами ради порядка.

## Волна 3 - вес промтов

Замер прогона: 27 запусков субагентов, ~3 350 000 токенов, ~3 часа 47 минут на ОДНУ страницу в трех тон-вариантах.

- **`BLOCKS.md` разрезан по шву «решения / механика» (ADR-036):** `BLOCKS.md` (30k, block-planner - индекс «имя -> форма», применимость, скелеты, рецепты, режимы) и `BLOCKS-METRICS.md` (30k, slot-mapper - каталог с метриками, правила H2/H3, пороговые правила). Было 56k у обоих.
- **Потолки в знаках** на 15 файлов и на 3 связки «агент + его методички». Проверка сработала сразу: поймала правку +1233 в `pages-planner`.
- **`SKILL.md` разделен**: три справочных блока (словарь проекта, Drive, pre-commit) вынесены в `assets/ORCHESTRATOR-REF.md` - файл уперся в собственный потолок (57 235 из 57 500).
- **`task-context.md`**: расшифровки, решения гейтов и ограничения оркестратор пишет ОДИН раз, путь передает строкой в промте (раньше - копипаст в каждый промт веера).

## Финальный аудит (сквозная проверка перед раскаткой)

Написана сквозная сверка кита, которой не было. Нашла то, чего отчет видел только край:

> **21 блок каталога из 45 не имел записи в `block_to_fragment`.** Сборщик молча брал фолбэк `cards` - для «CTA промежуточный», «Карта и контакты», «До / после» и трех карточек товара это ЧУЖАЯ форма, а не просто фолбэк. Достроено 28 записей прямо по индексу каталога.

Проверки закреплены тестами (не разовым скриптом): слоты манифеста против разметки в обе стороны, покрытие каталога, `slot_defaults` и маркеры shell, типографика кита. Плюс новый инвариант в `verify-prototype`: **в собранном документе не осталось маркеров кита** (неподставленный маркер невидим в браузере, но блок, который он нес, просто не появляется).

Пограничные случаи прогнаны отдельно: цикл `parent` в меню (меню не собирается, сборка не падает), атрибут со спецсимволом, шесть форм записи реквизита, идемпотентность пересборки (байт в байт).

## Что осталось открытым

1. **Обновление файла в Drive на месте невозможно** - в подключенных инструментах его нет (`updateTextFile` требует передать содержимое строкой; для прототипа в сотни килобайт неприменимо). Ссылка при перезаливке меняется. Компенсация: перед перезаливкой Skeletons снимаются комментарии заказчика (`listComments`), прежняя ссылка уходит в `revisions[]`. Радикальное решение (строить документ скелетов нативным Google Doc и обновлять на месте) не делалось - отдельная работа.
2. **Рендер-проверки кита не гонялись** - playwright не установлен, набор честно печатает SKIP. Новое меню и плашки изображений проверены только по коду.
3. **Выигрыш по весу промтов структурный, не замеренный** - реальные токены и минуты покажет следующий боевой прогон.
4. **`share.json` унифицирован только в `/seo-tekst`.** У `/seo-analiz`, `/seo-faq`, `/seo-metategi` и прочих свои схемы записи - сведение к одной не делалось (отдельное решение).
5. **Раскатка:** `/sync-from-template --apply`. В клиентском проекте после синка: заполнить `task-context.md`, проставить `url`/`parent` в `site_manifest.json` (без них не будет меню и маршрутизации ссылок), руками поправить склеенный ИНН в `facts.json` - мост его не пересевает (файл уже существует), но теперь его поймает `verify-copy`.
