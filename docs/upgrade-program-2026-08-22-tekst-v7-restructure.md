# Программа v7: перестройка конвейера текстов (2026-08-22)

Статус: ПЛАН (утверждается владельцем). Источник истины реализации - этот файл.
Ветка: `claude/text-writing-algorithm-621fac` (worktree template-project).

## 1. Диагноз

Три попытки починки (v4 08.06, v6 19-20.08, selling-frame 21-22.08) правили ПРАВИЛА письма,
но не трогали архитектурную причину: /seo-tekst несет внутри себя целое аналитическое крыло
(intake-analyst, pages-planner, leader-block-scanner, direction-scanner, audience-analyst,
offer-strategist - шаги 1.5-4 из 9), которое дублирует агентов /seo-analiz:

- direction-scanner ~ leader-scanner (блоки/посылы/фишки) и ~ serp-verdict (типизация топ-10);
- leader-block-scanner пересканирует тех же лидеров, что leader-scanner, в другом словаре;
- pages-planner ~ brief-structurer + serp-verdict (типизация сайта);
- черный список агрегаторов продублирован в 3 агентах;
- анализа ЦА в /seo-analiz НЕТ (одна строка ca_data) - вся ЦА живет в текстах.

Итог: перегруз (13 агентов, ~99 делегирований, ~22 МБ чтения на проект), два места истины
о конкурентах, и невозможность продать анализ отдельно клиенту без SEO.

## 2. Целевая архитектура

### 2.1. /seo-analiz - ступенчатый (для всех клиентов)

```
Ступень 0  Интейк         intake-analyst (единый профиль, объединение analysis+tekst словарей)
Ступень 1  Анализ брифа   brief-structurer: 16 параметров + directions[] (направления, с url
                          живой страницы); при tier=seo здесь же Keyso-поля как сейчас,
                          при basic - client_pages сканом сайта без метрик
Ступень 2  Анализ ЦА      audience-analyst (ПЕРЕЕЗД из /seo-tekst) -> analyses/NNN/audience.json
Ступень 3  Конкуренты     competitor-finder (seo: Keyso-путь как сейчас; basic: бриф + SERP
                          без метрик) + leader-scanner v2 (ОБЪЕДИНЕНИЕ с leader-block-scanner:
                          один скан лидеров -> посылы + блок-матрица «блок x тип» в словаре
                          BLOCKS.md) + direction-scanner (ПЕРЕЕЗД: разведка направлений,
                          вкл. own_page живой страницы -> analyses/NNN/recon/)
Ступень 4  SEO (опция)    serp-verdict + A3-стоп-лист + stop_list_detailed; только tier=seo
```

Tier определяет ИНСТРУМЕНТЫ ступеней 1 и 3, а не их состав (ревизия 2 контрактов).

- Запуск: `/seo-analiz [--seo | --no-seo]`; без флага - вопрос «SEO куплено?».
- Дозапуск: `/seo-analiz <NNN> --add-seo` - докупили SEO, добираем ступень 4 поверх готовых 1-3.
- A2.md переструктурируется по ступеням (новый раздел «Целевая аудитория»); questions.json,
  revising-цикл, verifier - сохраняются (движок генерический, меняется словарь rerun_hint).
- SERP-раздел A2 становится условным на уровне analysis-writer и analysis-verifier
  (docx-скрипт к отсутствию serp.json уже толерантен).
- validate-analysis-inputs.mjs: схема расширяется (audience.json, tier), /seo-struktura
  по-прежнему требует полный SEO-набор (brief+competitors+serp+A3) - ее вход не меняется.

### 2.2. /seo-struktura - без изменений

Требует анализ со ступенью 4. Опционально начинает читать audience.json (не обязательное).

### 2.3. /seo-tekst v7 - «только пишет»

Источники: `--from-structure NNN` (SEO) | `--from-analysis NNN` (без SEO) | `--from-table`
(аварийный ручной). `--from-brief` УДАЛЯЕТСЯ (решение владельца 22.08) - его путь теперь:
/seo-analiz --no-seo -> /seo-tekst --from-analysis (вето владельца на проверки спроса
сохраняется: ступени 1-3 без частотностей).

                             (blueprints/main.json к тон-гейту); такт 2 остальных страниц -
                             после выбора тона (шаг 6). slot-mapper без изменений (ADR-036).
Шаг 5  ТОН-ГЕЙТ              Главная пишется в 3 вариантах тона (3 запуска page-writer с разными
                             register-осями ADR-034; оттенки подбирает offer-strategist под

### 2.4. Прототип v2 - один файл

- Сборка двухфазная: веер prototype-builder сохраняется (пишет per-page рендер + manifest.json,
  manifest остается источником истины) -> детерминированный `assemble-prototype.mjs`:
  shell + служебная стартовая страница (список всех страниц: тип, название, ссылка) + страницы
  как секции с неймспейсом по slug (id: `<slug>__lead`, `<slug>__hero`...) + генерируемый
  hash-роутер (механизм в prototype.js уже есть, карта перестает быть захардкоженной) + плашка
  «к списку страниц» над шапкой.
- Попап удаляется полностью (6 мест: PROTOTYPE-MASTER.html, prototype.js, prototype.css,
  build-prototype.mjs, KIT-SPEC.md, prototype-builder.md). Transitions убираются (8 мест в css).
- Тема: только wireframe, флаг --theme и 6 цветных тем уходят из потока (файлы тем - в архив).
- verify-prototype v2: вход = texts_dir, проверки per-page по манифестам + глобальные
  (контракт-плашка, полнота навигации, «ровно 1 форма НА СТРАНИЦУ-секцию»).
- /seo-tekst-fix v2: правка page.json/manifest страницы -> пересборка общего файла ассемблером
  -> дифф по секции. Expected-маркеры и хук - на новый путь выхода.
- HANDOFF.md остается; build-handoff.mjs правится точечно (состав файлов, registerLine
  под новую форму регистра, литерал состояния).

## 3. Инварианты (переезжают нетронутыми)

- Продающий пол F1-F4 + waiver-механика + калибровка «машине - грепаемое, суждение -
  верификатору» (ADR-037, контракт).
- Числа только из facts.json, запрет выдуманных цифр - абсолютный; lexicon locked/translate/
  canonical (ADR-033), «заказчик важнее свода»; locked не пробивает машинные инварианты.
- Регистр ADR-034 (3 оси, chosen -> axes_from -> recommended -> деловой) - тон-гейт меняет
  ТОЧКУ выбора, не контракт.
- Функции блоков Р/Д/К/В + режимы рабочий/шаблон/заглушка (ADR-032/035).
- Диета писателя в знаках с тестами (ADR-020: VOICE <= 20500, +page-writer <= 33000).
- «Деградация только отсутствием данных, никогда флагом режима» (ADR-031) - переезжает на новый
  мост анализ -> тексты: страница без recon-направления просто не имеет recon.
- Анти-ИИ не применяется к коммерческим текстам (ADR-022).
- ORCHESTRATION: сводки <= 8 строк, expected-маркеры, verify-скрипты, фактура путями.
- Типографика: дефис вместо тире, е вместо е-с-точками.
- «Новое правило - только с ответами кто исполняет и в какой единице замерим» (урок v6).
