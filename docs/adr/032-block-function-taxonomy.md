# ADR-032: Функция блока (Р/Д/К/В) вместо требования «каждый блок закрывает боль»

**Статус:** Принято

**Дата:** 2026-08-20

## Контекст

В `/seo-tekst` блок попадает в структуру страницы только при якоре из боли или возражения.
Требование записано сразу в трех местах и потому работает как аксиома:

- `VOICE.md` - «каждый блок закрывает конкретную боль/страх/возражение»;
- `block-planner` - «каждый блок включается только при якоре из боли/CJM»;
- `COPY-AUDIT.md`, П.1 - «блок про нас без привязки к боли -> переписать под боль».

Следствие видно на готовых страницах: они получаются **оборонительными**. Каждый блок что-то
снимает - страх, сомнение, недоверие, - и ни один не показывает того, ради чего человек вообще
пришел: результат, который он получит. Блок доверия (лицензия, состав команды с именами, цифры
компании) под описание «про нас» попадает буквально и по П.1 переписывается «под боль», теряя
силу: вместо предъявления факта получается оправдание.

Источник разбора - референсный скил `seo-prototype-v6` той же методологической линии, где эта
же ошибка была допущена и затем исправлена: там прямо зафиксировано, что требование «каждый
блок закрывает возражение» было ошибкой предыдущей редакции.

Второй пласт контекста - подбор блоков по покрытию лидеров (ADR-017): порог «покрытие >= 50%
= блок обязателен» заставляет копировать то, что есть у всего рынка и не делает ничего.
Покрытие показывает, что блок принят в нише, но не показывает, зачем он на этой странице.

## Решение

**1. У каждого блока в blueprint есть функция - закрытый список из четырех значений.**

`function`: **Р** (результат) / **Д** (доказательство) / **К** (квалификация) / **В**
(возражение), плюс однострочное `function_why` - обоснование, зачем блок на этой странице.
Блок оправдан, если выполняет **хотя бы одну** функцию. Поля добавляются к существующей схеме
blueprint, старые поля (включая `covers`) не переименовываются и не удаляются.

**2. Баланс страницы: оборона не больше половины.**

Блоков функции **В** - не больше половины содержательных блоков страницы. Ориентир для
типовых 10-12 блоков: 2-3 Р, 2-3 Д, 1-2 К, остальное В.

Отдельно фиксируется, что **нехватка материалов на Р и Д не дает права добить страницу
возражениями**. Если нечем показать результат и нечем доказать - это запрос материалов
заказчику (кейсы, цифры, фото работ, состав команды), а не повод развернуть страницу в
сплошную оборону.

**3. Статус блока: гигиена / отстройка / мусор / не решено.**

Покрытие лидеров **поднимает** кандидата (блок есть у рынка - вероятно, гигиена), функция
**допускает**. Блок без функции не ставится, даже если он есть у всех лидеров. Так порог
покрытия перестает быть автоматическим включателем и становится одним из двух сигналов.

**4. Владельцы.**

- `block-planner` - заполняет `function` и `function_why`, держит баланс страницы. Он
  единственный, кто видит все блоки страницы разом, поэтому квота - его зона.
- `copy-auditor` - проверяет привязку. Блок считается привязанным, если непуст любой из
  `covers.pains | covers.objections | covers.triggers`. Блок без функции - **сигналить**, а не
  переписывать под боль. Правка состава - решение планировщика, а не аудитора одной страницы.
- `page-writer` - получает функцию готовой в blueprint. Каталоги (`BLOCKS.md`, `COPY.md`) он
  по-прежнему не читает, ADR-020 не затронут.

**5. Правило одинаково во всех источниках страниц.**

ADR-031 не затронут: ветвления по источнику нет. Функция и баланс не зависят от того, пришли
страницы из структуры, таблицы, анализа или брифа. Деградация, как и раньше, выражается только
отсутствием данных.

## Альтернативы

- **Оставить «каждый блок закрывает боль» и лечить перекос вычиткой.** Отвергнуто: аудитор
  видит одну страницу и не может судить о балансе состава, а перекос - свойство состава, а не
  формулировок. Вычитка правит слова там, где сломан набор блоков.
- **Ввести функцию как свободный текст без закрытого списка.** Отвергнуто: без закрытого
  списка нельзя посчитать квоту и нельзя проверить механически - получится еще одно поле-эссе,
  которое никто не читает.
- **Считать квоту в валидаторе как жесткое нарушение (exit 2).** Отвергнуто на этом этапе:
  баланс - смысловое суждение, и у отдельных типов страниц (например карточка товара) он
  законно другой. Начинаем с предупреждения и правила у планировщика; ужесточение до
  блокирующей проверки - после боевых прогонов.

## Последствия

**Хорошо:** страницы перестают быть сплошной обороной - у каждой есть блоки, показывающие
результат и доказательства; блоки доверия перестают переписываться «под боль» и предъявляются
как факт; появляется механическая опора для проверки (закрытый список + считаемая квота), а не
только вкусовое суждение.

**Плохо:** blueprint растет на два поля; `block-planner` получает еще одно обязательное решение
по каждому блоку (и риск формального проставления функции ради галочки); нужен боевой прогон,
чтобы убедиться, что квота не мешает типам страниц с законным перекосом в сторону возражений.
