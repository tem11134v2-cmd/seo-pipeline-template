# ADR-038: Ступенчатый предпроектный анализ и разделение «анализ / письмо»

**Статус:** Принято

**Дата:** 2026-08-22

## Контекст

Три попытки починить качество коммерческих текстов (v4 08.06, программа v6 19-20.08,
продающий пол 21-22.08) правили правила письма, но не архитектуру. Аудит-разведка 22.08
показала архитектурную причину нестабильности:

- /seo-tekst несет внутри себя аналитическое крыло из 6 агентов (intake-analyst,
  pages-planner, leader-block-scanner, direction-scanner, audience-analyst,
  offer-strategist) - шаги 1.5-4 из 9;
- это крыло дублирует агентов /seo-analiz: direction-scanner ~ leader-scanner
  (блоки/посылы/фишки) и ~ serp-verdict (типизация топ-10), leader-block-scanner
  пересканирует тех же лидеров в другом словаре, pages-planner ~ brief-structurer,
  черный список агрегаторов повторен в 3 агентах;
- анализа ЦА в /seo-analiz нет вообще (одна строка brief.ca_data) - вся ЦА живет
  внутри текстового конвейера и не продается клиенту отдельным артефактом;
- итоговая цена: 13 агентов, ~99 делегирований, ~22 МБ чтения на проект из 18 страниц,
  и два независимых места истины о конкурентах.

Бизнес-требование владельца: анализ должен работать и для клиентов БЕЗ SEO
(сайты партнера-разработчика, лендинги), а конвейер текстов - «просто писать».

## Решение

### 1. /seo-analiz становится ступенчатым - для всех клиентов

```
Ступень 0  Интейк       intake-analyst (единый словарь полей, слияние профилей analysis+tekst)
Ступень 1  Бриф         brief-structurer: 16 параметров + directions[] (направления
                        ассортимента - новый канон, с url живой страницы клиента);
                        при tier=seo здесь же Keyso-поля (keyso_base, путь А-Г, метрики) -
                        как сейчас; при tier=basic Keyso-ключи отсутствуют, client_pages
                        собираются сканом сайта (sitemap/меню через seo_fetch)
Ступень 2  ЦА           audience-analyst (ПЕРЕЕЗД из /seo-tekst) -> analyses/NNN/audience.json;
                        сегменты привязываются к направлениям (dir_slugs), не к страницам
Ступень 3  Конкуренты   competitor-finder (при seo - Keyso-путь с метриками как сейчас;
                        при basic - кандидаты из брифа + SERP, без метрик)
                        + leader-scanner v2 (ПОГЛОЩАЕТ leader-block-scanner: один скан
                        лидеров -> посылы И матрица «блок x тип» в словаре BLOCKS.md)
                        + direction-scanner (ПЕРЕЕЗД: разведка по направлениям, вкл.
                        own_page живой страницы направления -> analyses/NNN/recon/)
Ступень 4  SEO (опция)  serp-verdict (вердикт, SERP-таблица) + A3-стоп-лист +
                        stop_list_detailed; только при tier=seo
```

Важно: tier определяет ИНСТРУМЕНТЫ ступеней 1 и 3, а не их состав; ступень 4 - это
только SERP-вердикт и стоп-лист. При basic A3.md/stop_list_detailed не создаются,
recommendations.json усечен, Executive Summary без вердикта.

- Запуск: `/seo-analiz [--seo | --no-seo]`; без флага - вопрос «SEO куплено?».
  Ступень записывается в meta.json.tier (`seo` | `basic`).
- Дозакупка: `/seo-analiz <NNN> --add-seo`: tier -> seo, прогон дообогащения -
  brief-structurer (Keyso-поля), competitor-finder (метрики + пересмотр leaders_top3),
  serp-verdict, затем writer -> verifier -> docx -> re-upload. ЦА и directions
  не перезапускаются.
- A2.md перестраивается по ступеням (новый раздел «Целевая аудитория»); questions.json,
  revising-цикл и analysis-verifier сохраняются; словарь rerun_hint расширяется
  (intake|brief|audience|competitors|leaders|directions|serp|writer|edit).
- validate-analysis-inputs.mjs становится tier-aware (serp.json и Keyso-поля
  обязательны только при tier=seo); условность SERP-раздела A2 реализуется в
  analysis-writer/analysis-verifier (docx-скрипт уже толерантен к отсутствию serp.json).
- Проверок поискового спроса в ступенях 0-3 НЕТ (вето владельца из ADR-031 переезжает
  на уровень tier=basic целиком: никаких частотностей).

### 2. /seo-tekst «только пишет»

Источники: `--from-structure NNN` (SEO-путь) | `--from-analysis NNN` (путь без SEO) |
`--from-table` (аварийный ручной). **`--from-brief` удаляется** - его сценарий теперь:
`/seo-analiz --no-seo` -> `/seo-tekst --from-analysis`. Судьба остальных флагов:
`--review/--auto` остаются; `--mode A|B` удален (own_page снимается на ступени 3
по данным directions[].url, не флагом); `--scan-leaders` и `--recon` переезжают
опциями ступени 3 /seo-analiz; `--theme` удален (ADR-039).

Аналитические шаги 1.5-4 из /seo-tekst удаляются. Остается:

- **Мост данных** (шаг 1, скрипт read-tekst-input.mjs v2): детерминированный маппинг
  артефактов анализа в папку задачи (pages.json с dir_slug, leader_blocks.json - выжимка
  из leader_scan v2, facts.json - семена из intake, inputs.json). Большие артефакты
  (audience.json, recon/) читаются агентами по analysis_dir, не копируются.
- **Быстрая структура** (шаг 2, только если нет structures/NNN): pages-planner v2 -
  расширение существующего агента: состав страниц из анализа (ассортимент + страницы
  конкурентов + ЦА), сугубо конверсионный, без SEO; гейт согласования с заказчиком.
  Отдельной услугой не выносится (владелец: большинство не-SEO клиентов - лендинги).
- **Оффер-слой** (шаг 3): offer-strategist остается в текстах (это продающие директивы,
  не исследование), но тоньше - ЦА готова из анализа. Отдельного docx-гейта стратегии
  больше нет (решение владельца 22.08: согласование = ступени /seo-analiz);
  facts-gate/materials-gate до планировщика сохраняются - недостающая фактура
  запрашивается в чате и вместе с тон-превью.
- **Тон-гейт**: после скелетов блок-планировщик и slot-mapper собирают blueprint
  ГЛАВНОЙ (штатный blueprints/main.json), page-writer пишет ее в 3 вариантах тона
  (по осям 3 tone_candidates от offer-strategist), каждый проходит механический
  verify-copy и лайт-прогон copy-auditor; заказчик выбирает по одному html-файлу
  с 3 полными главными (движок ADR-039). Выбор пишется в decisions.register
  НОВОЙ формы {tone_id, axes, source} - все читатели регистра (агенты + verify-copy.mjs
  + build-handoff.mjs) правятся в этапе B, врезка в ADR-034. Остальные страницы
  планируются (такт 2) и пишутся веером уже в выбранном тоне.
- Пишущая цепочка block-planner (двухтактный: скелеты по типам страниц ->
  per-page blueprints) -> slot-mapper -> page-writer -> copy-auditor -> site-reviewer
  -> tekst-verifier сохраняет все инварианты (ADR-020/031/032/033/034/035/036/037).

Скил переписывается С НУЛЯ (решение владельца 22.08): новая концепция и state machine,
без легаси-веток; выверенные правила переносятся через обязательную таблицу трассировки
(старое правило -> новое место | снято + причина).

### 3. Принцип моста: деградация только отсутствием данных

Главный предохранитель ADR-031 переезжает на новый шов между скилами: страница без
спаренного направления просто не имеет recon; проект без ступени 2 - без audience.json;
`--from-table` без анализа - без всего аналитического слоя. Ни один пишущий агент
не ветвится по источнику или tier.

Полные схемы артефактов и таблица «кто пишет - кто читает» - в приложении
[upgrade-program-2026-08-22-tekst-v7-contracts.md](../upgrade-program-2026-08-22-tekst-v7-contracts.md).

## Альтернативы

- **Оставить анализ внутри /seo-tekst, дочистив дубли точечно.** Отвергнуто: два места
  истины о конкурентах остаются, ЦА не продается отдельно, перегруз конвейера
  сохраняется - три попытки уже показали предел точечных правок.
- **Вынести и offer-strategist в /seo-analiz.** Отвергнуто: формула оффера, тезисы и
  канон - продающие директивы для писателя, они зависят от состава страниц и живут
  в такт с письмом; анализ - факты, тексты - решения «как продавать» + письмо.
- **Быстрая структура как отдельная услуга.** Отвергнуто владельцем: большинство
  не-SEO клиентов - лендинги, отдельный пункт сметы порождает лишние объяснения.
- **Оставить --from-brief аварийным.** Отвергнуто владельцем: пришлось бы держать
  в текстах урезанную копию интейка и ЦА - часть дублей выжила бы.
- **direction-scanner оставить в текстах (сканировать по страницам).** Отвергнуто:
  разведка по направлениям ассортимента доступна уже на этапе анализа и нужна
  ступени 3; страницы спариваются с направлениями детерминированно.

## Последствия

**Хорошо:** один источник истины по конкурентам и ЦА; анализ продается клиентам без SEO
(3 ступени) и дозакупается (--add-seo); /seo-tekst сокращается с 13 до ~8 агентов
в задаче; выбор тона происходит на живой странице ценой одной главной, а не всего сайта.

**Плохо / цена:** шов между скилами удлиняется - контракты данных между /seo-analiz и
/seo-tekst становятся критическими (митигация: приложение-контракты, сверка «писалось -
но-не-читалось» на этапе D); клиенты без анализа теряют автономный путь --from-brief
(митигация: /seo-analiz --no-seo дешев - без SERP и Keyso); intake-analyst становится
агентом только /seo-analiz; /seo-struktura требует tier=seo (иначе стоп с подсказкой
--add-seo); старые незавершенные задачи /seo-tekst довершаются старым скилом до синка.

**Удаляются:** агент leader-block-scanner (поглощен leader-scanner v2), источник
--from-brief, шаги 1.5-4 старого /seo-tekst, клиентский Analysis.docx-гейт в текстах.
