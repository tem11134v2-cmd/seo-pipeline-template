# ADR-045: Анализ КФ и КНДР лидеров в `/site-tekst`, оболочка по пересечениям, аудитор готового прототипа и таблица для заказчика

**Статус:** Принято

**Дата:** 2026-10-05

> Дополняет [ADR-044](044-site-tekst-no-gates-and-site-prototype.md) (финал для заказчика, правило «модуля без данных в
> файле нет», состав фазы 8) и [ADR-041](041-v9-site-analiz-single-entry-and-site-tekst.md) (разбор лидеров - один раз, в
> фазе 2 текстов). Остальное в них в силе.

## Контекст

- **Тексты сильные, сайт слабее рынка.** Прототип `/site-tekst` строится только из данных проекта: элемента, на который
  нет данных, в нем нет. Ручной анализ коммерческих факторов (КФ: телефон, корзина, цены, доставка, реквизиты) и
  контента, необходимого для ранжирования (КНДР: элементы и блоки, которые массово используют лидеры ниши), по кейсу
  клиента показал, что лидеры ниши почти поголовно держат в шапке, подвале и на первом экране элементы, которых у нас
  не было, а заказчик об этих пробелах не узнавал.
- **Отбор лидеров был слабым.** Верификатор брал конкурентов из затравки анализа и своей выдачи, без метрик: в разбор
  попадали заметные, но не сильнейшие сайты, молодые быстрорастущие лидеры не отличались от старых.
- **Аудит текстов идет по странице.** Судьи фазы 6 не видят сайт целиком: одно действие с пятью разными надписями,
  один и тот же факт доверия на всех страницах, клоны страниц одного типа, меню и подвал против H1.
- Материалы владельца: промт «анализ кф», майнд-карты курса, кейс ручного анализа; решения владельца - раздел 0
  программы `docs/upgrade-program-2026-10-05-kf-kndr.md` (версия 2, после аудита спецификации).

## Решение

### 1. Этап КФ/КНДР живет в фазе 2 `/site-tekst`

- Отбор лидеров и снятие КФ/КНДР - в `wf-02` (тот же воркфлоу, args `types`). `/site-analiz`, контракт `project.json` и
  `seo-base` не меняются: список лидеров анализа - затравка.
- **Отбор.** Скаут (`02-competitor-scout`, light) собирает длинный список в `work/competitors/pool.json`: выдача ниши
  (Арсенкин, регион бизнеса, при нехватке - Москва), Keys.so (видимость, трафик, история, добор похожих), ИКС и возраст
  домена (whois). Платные данные - при любом tier (внутренний расход, единицы вызовов). Ранжирование - чистая функция
  `rank-competitors.mjs`: стоп-лист, SEO-вес по метрикам в лог-шкале от лидера, тип сайта против `site_kind` проекта,
  возраст (молодой важнее старого при близком весе) и рост; хотя бы один сильнейший старый лидер остается эталоном.
  Верификатор идет по `ranking.order` до 5 годных. Повтор wf-02 платный отбор не повторяет (`--check` fresh, в узкой
  нише - `exhausted`).
- **Снятие.** Свой процесс Chrome или Edge через CDP (`capture-pages.mjs`, встроенный `WebSocket` Node, без npm и
  скачивания браузера): кадры фиксированной высоты, мобильный первый экран, DOM-находки по зонам с доказательством и
  текстовый контур секций. Браузер агентов - только при отказе CDP. Нет браузера - деградация `no_chrome`.
- **Наблюдение и матрица.** Наблюдатель (`02-kf-observer`, light) по домену пишет только видимое или подтвержденное DOM,
  сомнительное - «?». Словарь kit (`config/kf-elements.json`, около 130 общих элементов, 13 категорий) - подсказка, а не
  фильтр: элемент не из словаря (`x-<латиница>`, в том числе нишевый) проходит тот же путь - сведение синонимов
  (`02-kf-normalizer`), перепроверка у всех лидеров по ключу `<scope>|<zone>|<id>`, тот же счет охвата. Матрица
  `kf-matrix.mjs` - **абсолютные пороги** охвата: от 4 из 5 - «обязательно», 2-3 - «рекомендовано», 1 - «по желанию»;
  есть на сайте клиента - пометка «уже есть». Нишевые находки живут только в данных задачи; проект пополняет словарь
  через `overrides/config/kf-elements.json`.
- **Правило включения.** Этап проведен, только если есть `work/kf/matrix.json`; иначе (задача до этапа, `skipKf`, без
  конкурентов) все работает как раньше, причина - `work/kf/status.json`.

### 2. Путь элемента в типы, брифы и прототип

- Агрегатор типов покрывает каждую строку «обязательно» и «рекомендовано» своего типа (`kf_coverage`: блок, элемент
  блока, `shell` - рисует оболочка, или `skip` с причиной из закрытого списка); аудитор типов первым шагом запускает
  `kf-coverage.mjs` (непокрытая строка «обязательно» - blocker, «рекомендовано» - major).
- **Исключение из урока «блоки без фактов дали пустые секции»** (LESSONS, пилот IBG): КФ-блок, выпавший с «нет фактов»
  или «нет числовых фактов», становится заглушкой `brief.stubs` (вне `brief.blocks`, писатель, линтер и готовность ее не
  видят) с вопросом заказчику вместо вопроса о выпадении. Только КФ-блок и только «нет фактов»: снятие стратегом,
  STALE/HOMED - как раньше. «Есть у лидеров» не порождает выдумку: содержание - только из фактов.
- **Оболочка по пересечениям** (`work/shell.json`, элементы шапки, подвала, мобильной панели и закрепленные от
  «рекомендовано»): слот с данными - на месте; слот без данных - серый чип «нужны данные: <что>» и вопрос заказчику;
  функция интерфейса - по пересечению, без страницы модуля - кнопка-тост «функция вне прототипа»; страницы нет в карте -
  тост и рекомендация; поле, снятое заказчиком, - ничего. Это **исключение из правила «модуля без данных в файле нет»**
  ADR-044 §3 - только для оболочки по пересечениям лидеров; ключи живых модулей `prototype.modules.json` (`search`,
  `cart`, `account`) по-прежнему описывают только живые модули. Подписи - только шаблоны `ui.json`, подпись конкурента в
  прототип не переносится. Без `shell.json` разметка совпадает с прежней байт в байт (эталон в тестах).

### 3. Аудитор готового прототипа (фаза 8, `wf-08`)

- Новый state `site-audited` между `catalog-done` и `built`. После первой удачной сборки - снимок данных и `wf-08`:
  дайджест сайта без LLM, аудитор `08-site-auditor` (strong) ищет то, что видно только на сайте целиком, один круг
  фиксера сужения не больше чем на 8 страницах (`fix-diff` откатывает блок, который правка сломала), одна надпись одного
  действия - скриптом `cta-unify.mjs` (только вариант, который уже стоит на сайте). Затем сборка заново; поломка - откат
  правок wf-08 по снимку и сборка на прежних данных.
- Пауз нет; сбой wf-08 целиком - один повтор, затем строка в отчете (`meta.skips`), **не автостоп** (исключение «кроме
  wf-08» в таблице автостопов SKILL.md). Судьи после фиксера нет: правки wf-08 - в «Правки без проверки судьей».

### 4. Таблица КФ/КНДР - часть финала для заказчика

- `build-kf-xlsx.mjs` -> `work/output/kf-kndr.xlsx` (листы «Как читать», «Отбор конкурентов», «Сравнение» по образцу
  ручного кейса, «Ограничения»), публикация Google Таблицей в папку текстов (`uploadFile` с конверсией), только при новом
  `data_sha`; прежний файл - «(устарело)». Таблица - показать работу, а не на согласование. Дополнение к ADR-044
  («заказчик видит только финальный прототип»): **финал - прототип, отчет и таблица**. Ссылка - строка «Таблица КФ/КНДР»
  отчета и итога сдачи.

### 5. Принятые отклонения реализации от спецификации

Перечень - раздел 7 программы. Существенные для архитектуры: ответ перепроверки по ключу scope и зоны (не по id);
`--status skip` снимает матрицу и оболочку; `--check` fresh с `exhausted` в узкой нише; ограничение веса Keys.so только
для города без своей базы и не федерального рынка; `declined` с `reason: "off"` для модуля, выключенного оператором;
подписи оболочки в разделе `kf` словаря `ui.json` (не в `ui`) и вырезаемые метками стили оболочки - ради эталона без
`shell.json`.

## Альтернативы

- **Отбор и КФ в `/site-analiz`.** Отвергнуто владельцем: ADR-041 - разбор лидеров один раз, в фазе 2 текстов; анализ
  и его гейт не меняются.
- **Словарь как фильтр (учитываем только известные элементы).** Отвергнуто: нишевые элементы лидеров - главная находка
  ручного анализа; словарь дает только устойчивые id и отрисовку.
- **Пороги долями («80% лидеров»).** Отвергнуто: при малом N доли искажают уровни; абсолютные пороги - как в кейсе.
- **Монолитный скриншот страницы, playwright или puppeteer.** Отвергнуто: длинный кадр модель не читает, а зависимость
  и скачивание браузера противоречат доводу ADR-035 (`playwright` и браузер не становятся зависимостью каждого
  клиентского клона); CDP к установленному браузеру и кадры + контур.
- **Блоки «сверх рынка» по разрыву E-E-A-T и автоматическое добавление страниц.** Отвергнуто: путь к выдумке; недостающие
  страницы - рекомендация в таблице и отчете, в прототипе - кнопка-тост.
- **Пауза или автостоп на аудиторе прототипа.** Отвергнуто: решение владельца - один круг, спорное в отчет.

## Последствия

**Хорошо:** прототип несет элементы, которые есть у лидеров, честно показывает пробелы данных чипами и вопросами;
лидеры отбираются по метрикам, с эталоном и учетом молодых сайтов; сайт проверяется целиком, одно действие получает одну
надпись; заказчик видит таблицу сравнения с лидерами.

**Плохо / цена:** фаза 2 дольше и дороже (снятие, наблюдатель по домену, единицы платных вызовов MCP); нужен
установленный Chrome или Edge (иначе наблюдение по тексту, `no_chrome`); правки аудитора прототипа не проверяются судьей
(они в отчете); оболочка по пересечениям - второе исключение из «модуля без данных нет» (рядом с Р6 ADR-044). Задачи до апгрейда: типы,
брифы и прототип без этапа КФ, wf-08 не запускается (`skip_reason` «аудитор прототипа - для новых задач»), таблица не
строится.

**Проверка:** наборы `tests/site-tekst` (`cases-kf-select`, `cases-kf-capture`, `cases-kf-matrix`, `cases-kf-types`,
`cases-kf-site` с эталоном сборки без `shell.json`, `cases-kf-xlsx`, `cases-site-audit`, `workflow-models.mjs`, поток в
`cases-flow`), приемка на живом прогоне по разделу 6 программы.
