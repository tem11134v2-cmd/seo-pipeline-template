# ADR-039: Прототип одним html-файлом (wireframe-only, без попапов и анимаций)

**Статус:** Принято

**Дата:** 2026-08-22

## Контекст

Сейчас прототип - «один манифест = одна страница = один прототип» (KIT-SPEC §2):
веер prototype-builder собирает pages/<slug>/prototype.html, каждый self-contained
(~64 КБ общего оверхеда инлайнится в каждый файл). Заказчик получает пачку файлов
без навигации между ними - это не похоже на сайт.

Решения владельца 22.08: (1) все страницы прототипа - в ОДНОМ html-файле со служебной
стартовой страницей-списком и плашкой возврата; (2) текущие попапы удалить; (3) без
анимаций; (4) прототип всегда ч/б wireframe - дизайн не проектируется вовсе;
(5) для каталогов фильтратор и листинг товаров обязаны быть видны в скелете блоков
и полноценно показаны в прототипе; (6) тон-гейт (3 варианта главной, ADR-038)
доставляется тем же одно-файловым движком.

Разведка кита 22.08: hash-роутер уже существует (prototype.js, захардкожен на 4
служебные секции); фрагмент product-listing с рейлом фильтров уже есть; попапы живут
ровно в 6 местах; в css нет @keyframes, но есть 8 transition; на мультифайле
гарантированно падает verify-prototype.mjs (правило «ровно 1 форма», один manifest,
один H1/hero/title) и ломается контракт /seo-tekst-fix (пересборка по page_dir).
Размер одного файла на 10-30 страниц - 160 КБ-1 МБ, технически безопасно.

## Решение

### 1. Двухфазная сборка

Веер prototype-builder сохраняется (1 вызов = 1 страница), но его выход становится
промежуточным: `pages/<slug>/render.html` (отрендеренные блоки страницы БЕЗ shell) +
`pages/<slug>/manifest.json` (без изменений - источник истины страницы).

Новый детерминированный скрипт **assemble-prototype.mjs** (без агента) собирает
`texts/NNN/prototype.html` из всех render.html + `site_manifest.json` (порядок,
названия, типы страниц; пишет оркестратор шагом сборки):

- служебная стартовая страница: список всех страниц (тип, название, ссылка) -
  открывается по умолчанию;
- каждая страница - секция `<section class="pt-page" data-page="<slug>">`;
- неймспейс id: все id внутри секции получают префикс `<slug>__`, и переписываются
  ВСЕ ссылки на id - `href="#..."` И `label for="..."` (aria-атрибутов с id в ките
  нет - проверено). ИСКЛЮЧЕНИЕ - закрытый список сервисных якорей БЕЗ префикса:
  `privacy`, `person-data-consent`, `cookie`, `thanks` (юр-страницы и «спасибо» -
  одни на документ; ссылки на них из форм секций остаются глобальными);
- документ-уровневые данные (legal-блок с phone-placeholder логикой, титул/мета
  документа, тема wireframe, логотип/график) ассемблер берет из manifest.json
  ГЛАВНОЙ страницы; shell-подстановки, ранее выполнявшиеся build-prototype.mjs
  по manifest, переезжают в ассемблер;
- финальные пост-проходы normYoFinal (е-с-точками -> е) и bindHanging (висячие
  предлоги) выполняет АССЕМБЛЕР по итоговому документу (включая стартовую страницу
  и плашку); канарейка в verify v2 указывает на ассемблер;
- hash-роутер ГЕНЕРИРУЕТСЯ ассемблером из site_manifest (карта в prototype.js
  перестает быть захардкоженной); показ одной страницы за раз; НЕ-страничный hash
  (якорь формы/блока) секцию не переключает; возврат «Вернуться» из юр-страниц
  ведет на последнюю активную секцию (legal/page-*.html правятся - сейчас там
  href="#mainContent");
- плашка возврата - ОДНА, документ-уровневая, в shell над header: «К списку
  страниц» + название текущей страницы (текст подставляет роутер); на стартовой
  странице плашка скрыта;
- шапка/подвал/cookie-баннер/юр-страницы - по одному на документ; CTA самого shell
  (шапка, бургер, мобильная фикс-панель - сейчас href="#lead") ведут на форму
  АКТИВНОЙ секции (обработчик в prototype.js);
- форма захвата - в каждой странице-секции (CTA секции ведет на свою `<slug>__lead`);
  чекбокс-гейт в prototype.js УЖЕ работает в пределах формы (querySelectorAll('form'))
  и правки не требует - правятся проверки verify (id f-agree/f-submit -> пер-секция);
- контракт передачи ADR-035 сохраняется: комментарий-контракт в head (после meta
  charset) и видимая плашка .pt-contract первым элементом body - по ОДНОМУ на документ.
  build-handoff.mjs правится точечно: строка «Состав файлов на страницу» (теперь
  один prototype.html на сайт + render.html/page.json на страницу), registerLine
  под новую форму decisions.register, литерал состояния prototype-built.

### 2. Wireframe-only, без попапов и анимаций

- Оба попапа (#popupTime, #popupExit) удаляются из всех 6 мест: PROTOTYPE-MASTER.html,
  prototype.js, prototype.css, build-prototype.mjs (POPUP_*-подстановки и поле
  manifest.popups), KIT-SPEC.md, prototype-builder.md (+ поле popups в strategy.json).
- Все transition удаляются из prototype.css (8 мест); @keyframes нет и не появляется.
- Тема всегда wireframe: флаг --theme и strategy.design_theme удаляются из потока
  (offer-strategist перестает писать design_theme), 6 цветных тем удаляются из
  assets/themes/ (история остается в git); фолбэк `manifest.theme || "b2b"`
  в build-prototype.mjs меняется на wireframe.

### 3. Каталог: фильтратор и листинг обязаны быть видны

- В скелете типа «категория» (type_skeletons.json, ADR-038) блок «Листинг товаров»
  с opts.filter=true - обязательный (required); в скелете типа «товар» обязателен
  product-gallery. Правило исполняет block-planner (такт 1), проверяет verify-prototype v2.
- Фильтр остается статичным плейсхолдером (wireframe, без интерактива) - это
  сознательно: прототип согласует состав и тексты, не UX фильтрации.

### 4. verify-prototype v2 и /seo-tekst-fix v2

- verify-prototype.mjs v2: вход - texts_dir (не page_dir). Пер-страничные проверки
  идут по каждому manifest.json против его секции (лимиты, стоп-формулы, H1+маркер,
  featured, «ровно 1 форма НА СЕКЦИЮ», обязательные блоки каталожных типов);
  глобальные - по документу (один контракт-плашка, стартовая страница, полнота
  навигации = все страницы site_manifest достижимы, отсутствие голых дублей id,
  тире/е-с-точками, попапов и transition нет). Обязательное требование этапа C:
  ПОЛНАЯ таблица переноса действующих проверок verify-prototype (осталась /
  перенесена в глобальные / снята + причина) - как таблица трассировки правил
  письма; неперечисленная проверка не считается перенесенной.
- /seo-tekst-fix v2: prototype-fixer правит manifest.json/page.json страницы,
  пересобирает render.html этой страницы, затем зовет assemble-prototype.mjs
  (дешевая детерминированная пересборка общего файла) и verify v2; дифф остается
  пер-страничным (по секции). Expected-маркер хука: texts/NNN/prototype.html.
- Тон-превью (ADR-038): тот же ассемблер, вход - 3 варианта главной как 3 «страницы»
  (tone/site_manifest со списком вариантов) -> texts/NNN/tone/tone-preview.html.

## Альтернативы

- **Оставить 1 файл = 1 страница + отдельная index.html со ссылками.** Отвергнуто:
  ссылки между локальными файлами ломаются при пересылке (мессенджеры/Drive отдают
  файлы по одному), заказчик теряет «ощущение сайта» - главная цель решения.
- **iframe-склейка страниц.** Отвергнуто: file:// + iframe капризны в браузерах,
  печать/поиск по документу ломаются.
- **Настоящий роутинг без секций (динамическая подгрузка).** Отвергнуто: file://
  без сервера, self-contained - жесткое требование (Tilda/WP-совместимость шаблона
  передачи).
- **Оставить цветные темы как опцию.** Отвергнуто владельцем: прототип - всегда
  wireframe, дизайн не обсуждается на этом этапе (ADR-021 это уже фиксировал
  дефолтом; теперь опция снимается совсем).

## Последствия

**Хорошо:** заказчик получает «почти сайт» одной ссылкой/файлом со стартовым
оглавлением; общий оверхед платится один раз (~64 КБ на документ вместо каждого
файла); тон-гейт и прототип используют один движок; попапы и анимации перестают
отвлекать от текста.

**Плохо / цена:** переписываются verify-prototype.mjs, prototype.js (роутер,
shell-CTA), build-prototype.mjs (режим render-фрагмента), build-handoff.mjs
(точечно), KIT-SPEC.md, legal/page-*.html (возврат), агенты prototype-builder/
prototype-fixer, скил /seo-tekst-fix, expected-маркеры; тесты: kit-mobile/run.mjs
(вызовы build/verify на новые контракты, фикстура site_manifest, шаг ассемблера,
пересчет KIT_BASELINE после удаления попапов/transitions) и tests/seo-tekst/run.mjs
(секции сборки/verify на render+assemble). Райдер: правка одной страницы теперь
пересобирает общий файл (митигация: ассемблер детерминирован и дешев, верстка
страницы кешируется в render.html).
