## 0. Решения владельца (05.10)

1. **Где живет этап.** Отбор лидеров и снятие КФ/КНДР - в фазе 2 `/site-tekst` (ADR-041: разбор лидеров один раз, в
   фазе 2 текстов). `/site-analiz`, контракт `project.json` и `seo-base` не меняются; список лидеров анализа - затравка.
2. **Платные данные.** Keys.so и Арсенкин в отборе - при любом tier (внутренний расход, единицы вызовов на прогон).
3. **Отбор.** SEO-вес по набору метрик (как в кейсе MANSBAND: доля в выдаче ниши, ТОП-10/50, их отношение, трафик, ИКС,
   рост) плюс тип сайта. Возраст домена - один из факторов: при близком весе молодой сайт важнее старого. Итог - смесь
   «быстрорастущие + авторитетные»: хотя бы один самый сильный старый лидер остается эталоном.
4. **Пороги охвата** (абсолютные, из кейса): 4-5 из 5 - «обязательно», 2-3 - «рекомендовано», 1 - «по желанию», 0 - «не
   нужно»; есть на текущем сайте клиента - пометка «уже есть». В прототип идут «обязательно» и «рекомендовано» (все
   пересечения 2+).
5. **Без данных.** Слот (телефон, мессенджер, адрес, часы, реквизиты, рейтинг, документы, лицензии, соцсети, описание
   деятельности) - серый чип «нужны данные: <что>» на своем месте и вопрос заказчику. Функция интерфейса (поиск,
   корзина, избранное, кабинет, сравнение, обратный звонок, кнопка вверх, закрепленная кнопка, чат, подписка) данных
   заказчика не требует и рисуется по пересечению (без страницы модуля - кнопка-тост «функция вне прототипа»); часть
   функции, которая без бизнес-данных не работает (цены калькулятора, кто отвечает в чате, условия бонусов, список
   городов), - чип и вопрос. Это исключение из правила «модуля без данных в файле нет» (ADR-044 §3, программа 27.09
   §0 п.2) - только для оболочки по пересечениям лидеров; ключи живых модулей в `prototype.modules.json` (`search`,
   `cart`, `account`) по-прежнему описывают только живые модули.
6. **Библиотека элементов не ограничивает проход.** Словарь kit дает устойчивые id и подсказки отрисовки, но ничего не
   отсекает: x-элемент (в том числе нишевый блок или элемент), найденный у конкурентов, учитывается наравне со
   словарными: свое id `x-<латиница>`, вид от наблюдателя, сведение синонимов, перепроверка у всех лидеров, тот же счет
   охвата, те же пороги, тот же путь в типы, таблицу и прототип. Нишевые находки живут только в данных задачи; в kit
   не записываются (проект может пополнить свой словарь через `overrides/config/kf-elements.json`).
7. **Аудитор прототипа** правит один круг (суживающий фиксер по текстовым находкам, единая надпись одного действия -
   скриптом), остальное и спорное - в отчет. Пауз нет; сбой аудитора - строка в отчете, не автостоп.
8. **Таблица для заказчика.** Результат анализа КФ/КНДР - Google Таблица (не на согласование, а показать работу),
   ссылка среди итоговых файлов вместе с прототипом. Дополнение к §0 п.5 программы 27.09 и ADR-044 («заказчик видит
   только финал»): финал теперь - прототип, отчет и таблица.
9. **Рамки брифа (не пересматриваются):** без кастомных ТЗ заказчика и нишевой конкретики в kit; прогон без пауз,
   автостоп только по аномалии; «пересекается - у нас» не порождает выдумку (элемент берется в структуру, содержание -
   только из фактов, иначе плашка и вопрос); расширять существующее; стиль без «е с точками» и длинных тире, кавычки
   «елочки»; коммит, мерж, push и `/sync-all` - только по явному «да» владельца.

## 1. Разбор материалов (что берем и что нет)

**Промт «анализ кф».** Берем: только наблюдаемое, «?» для сомнительного и отдельный список неоднозначностей; не
смешивать наблюдение, сравнение и рекомендацию; нормализация и дедупликация названий; три зоны (плюс мобильная версия и
закрепленные элементы); не сравнивать страницы разных типов; не добавлять элементы «по умолчанию»; охват «N из M»;
чек-лист (~45 элементов) и 13 категорий - в словарь; четыре стороны E-E-A-T - признак элемента в словаре.
Не берем: ручную подстановку адресов и скриншотов, один тип страницы за запуск, вывод таблицами в чат, роль
«Senior-аудитор», семь таблиц, субъективный «уровень дефицита», автоматическое добавление блоков «сверх рынка» по
разрыву E-E-A-T (путь к выдумке: только при факте проекта, иначе вопрос заказчику).

**Майнд-карты курса.** Берем: 5 конкурентов, сила по присутствию в выдаче ниши, фильтры (не агрегатор, не маркетплейс,
не инфосайт, тот же тип бизнеса и ассортимент), разбивка по типам страниц, снимок страницы целиком, «идеальная
структура блоков» по зонам, добор из Москвы для регионального бизнеса, чек-листы контактов, реквизитов и 152-ФЗ - в
словарь. Не берем: «баллы» сервиса курса (формулы нет), GoFullPage руками, статьи и блог (kit их не пишет), темы вне
задачи (Тильда, домены, тех. аудит, ссылки).

**Кейс MANSBAND.** Берем: длинный список по выдаче семантики ниши с долей (лист «Поиск конкурентов»), метрики лидеров
(лист «Оценка лидеров»), смесь молодых и авторитетных, абсолютные пороги решения по охвату и колонку «продвигаемый
сайт» («уже есть»), «сумму баллов» сайта (число найденных элементов), группы строк по зонам и типам страниц (лист
«Анализ КФ»), общий чек-лист (лист «Функционал», без нишевых строк вроде «Двигатель», «Запчасти», «Trade-in»).
Не берем: рекламные метрики (объявления, бюджет контекста) - к отбору по органике не относятся.

### 3.1. Отбор (пакет A)

**Домены.** Канон `candidates[].domain` - хост в нижнем регистре, без протокола, `www`, порта и точки в конце, в ASCII
(punycode), как в `seed.json`; поддомены не схлопываются, кроме `www`. Поле `domain_unicode` - для Keys.so (по punycode он
отвечает «не найден») и для таблицы. Нормализация - общая функция модуля kit `scripts/domains.mjs` (вынести из
`import-project.mjs` ~1040 на `url.domainToASCII/domainToUnicode`; импорт пользуется ею же). Скаут сырые домены не
нормализует руками: `rank-competitors.mjs --merge-pool <raw.json>` сводит дубли (punycode и кириллица, `www`) и сливает
`sources`. **Домены клиента** (`config.site_url`, `competitors.own_domains` проекта для зеркал и старых доменов, их
поддомены) - стоп «сайт клиента»; скаут их в кандидаты не пишет, верификатор отбрасывает как подстраховку.

**Регион.** `scripts/regions.mjs` - копия таблиц `CITIES`/`FEDERAL` из `.claude/scripts/validate-project-input.mjs` без
CLI и функция `parseRegion(text)` -> `{city, keyso_base, yandex_id, federal, city_not_in_keyso, yandex_fallback_213}`;
тест сверяет литералы копии с оригиналом текстом (скрипт не запускается). `import-project.mjs` пишет `niche.yandex_id`
и `niche.keyso_base` в config задачи; скаут берет регион оттуда (нет - Москва 213, msk). `city_not_in_keyso` - метрики
Keys.so только для разрыва равенства, в W не входят, предупреждение «рынок оценен по выдаче без Keys.so» в отчет.

**Запросы.** `node scripts/rank-competitors.mjs --queries` (детерминированно): `sources.key_phrases`, затем маркеры
(`key_phrase`/`marker` страницы) hub, category, service по уровню и порядку карты, затем их `subject`; без product,
шаблонов и `status: skip`; без дублей; до `serp_queries_max` (15). Пустой список - код 0, `{queries: []}`, скаут
пропускает выдачу со строкой в `errors`.

**`work/competitors/pool.json`** (пишет скаут, схема `schemas/kf-pool.schema.json`; скаут дописывает часть после
каждого источника и проверяет схему, а не держит сырые ответы в памяти):
```
{ "generated_at", "input_sha", "region": {...parseRegion}, "queries": [""], "queries_msk": [""],
  "candidates": [{ "domain", "domain_unicode", "sources": ["analysis"|"serp"|"serp_msk"|"structure"|"keyso"],
     "serp": {"top1","top3","top5","top10","queries","share"} | null,      // share = top10/queries по выдаче ниши
     "keyso": {"top10","top50","traffic","pages", "top1?","top3?","top5?","dr?"} | null, "keyso_status": "ok"|"not_found"|"error",
     "history": {"it50_now","it50_12m"} | null, "iks": N | null, "created": "YYYY-MM-DD" | null, "notes": "" }],
  "rejected": [{"raw","reason"}], "method": "", "errors": [""] }
```
- Выдача: `arsenkin_top` одним вызовом по всем запросам, регион бизнеса, глубина 10. Меньше `target` кандидатов с долей
  от 10% после стоп-листа и `yandex_id != 213` - второй вызов по Москве (`serp_msk`).
- Keys.so: `domains_batch` одним вызовом (до 40 кандидатов, `domain_unicode`); «не найден» - один повтор в другой форме,
  иначе `keyso_status: not_found` (это не ноль). `domain_dashboard include_history` - до `history_max` (8) кандидатов по
  предварительному весу (`rank-competitors.mjs --prelim`, без возраста): рост it50 (последний месяц против месяца 12
  месяцев назад), ТОП-1/3/5, DR. `domain_competitors` по домену клиента (есть видимость) или по сильнейшему домену
  затравки - добор кандидатов (`keyso`).
- ИКС и возраст: `arsenkin_domains` `mode=iks` и `mode=whois` пакетом; `created` - поле `creation` ответа whois
  (DD.MM.YYYY -> YYYY-MM-DD), нет поля - null. Даты «первого появления в выдаче» нет (надежного источника нет).
- Затравка: `seed.json` (режим project) или раздел конкурентов `inputs/analysis.md` (режим doc, как у верификатора);
  строки `rejected` затравки - поиск домена по названию в выдаче. При структуре - `work/competitors/structure-competitors.json`.
- Сбой инструмента - источник пропускается, причина в `errors`. Все источники пусты и затравки нет - как сейчас
  («нет доступных конкурентов»).
- `--check`: fresh, если `pool.json` проходит схему, `input_sha` совпадает (запросы, регион, seed, structure-competitors),
  `errors` пуст и годных кандидатов не меньше `target`; иначе stale с причиной (частичные `errors` - перезапрос только
  упавших источников с сохранением полученного).

**`work/competitors/structure-competitors.json`** - копирует `import-project.mjs` (единственный владелец): если рядом с
`sources.structure_input` лежит `competitors.json` seo-base - `{source, direct[], indirect[], excluded[{domain, reason}]}`
плюс `serp.json.stop_list` с причинами; нет файла (tier basic, `--structure-file` без соседа, режим doc) - молча пропуск.
Отпечаток копии - в список инвалидации рядом с `competitors-seed`. В ranking домены `excluded`/`stop_list` - стоп
«исключен структурой: <причина>», кроме доменов, названных в затравке анализа (побеждает затравка, пометка в `reason`).

**`work/competitors/ranking.json`** (`rank-competitors.mjs`, чистая функция `pool.json` + параметры; схема
`schemas/kf-ranking.schema.json`):
```
{ "generated_at", "params": {...}, "order": ["домен"], "anchors": ["домен"], "warnings": [""],
  "candidates": [{ "domain", "stop": ""|"<причина>", "weight": 0-100|null, "effective": N|null, "coverage": 0-1,
     "age_years", "age_class": "young"|"mid"|"old"|"unknown", "growth": "up"|"flat"|"down"|"unknown",
     "site_type": "multipage_leader"|"medium"|"small"|"landing"|"unknown", "metrics_used": [""], "reason": "" }] }
```
Формула (параметры - `config/project.json` -> `competitors.selection`, умолчания в скрипте):
- Стоп-лист: `config/kf-stoplist.json` (общие агрегаторы, маркетплейсы, соцсети, СМИ, карты, справочники; без нишевых
  доменов, не больше 40 записей) + `competitors.aggregators_stoplist` проекта + поддомены + домены клиента + исключенные
  структурой. Агрегаторы вне списка ловит верификатор по снимку (статус `aggregator`).
- Метрики (вес): доля в выдаче ниши (3), ТОП-10 (1), ТОП-50 (1), ТОП-10/ТОП-50 при ТОП-50 от 50 (0,5), трафик (1), ИКС
  (1). Нормировка - доля от лидера в лог-шкале: `s = log1p(x)/log1p(max_x)*100` среди кандидатов без стопа; `max_x = 0`
  - метрика исключается для всех. Нет метрики у кандидата - она исключается из его среднего, веса нормируются по
  доступным; покрытие (доля доступного веса) ниже 0,5 - W умножается на `coverage/0,5`, кроме случая «нет только
  метрик Keys.so, а доля выдачи и ИКС есть» (молодые и региональные сайты не топим). `reason` перечисляет пропуски.
- Тип сайта `site_type` - по таблице `seo-base.md` (страницы и DR Keys.so); без Keys.so - `unknown`. Совпадение с
  `business.site_kind` проекта (лендинг - landing/small; многостраничник - medium/multipage_leader) - множитель
  `1 + site_type_bonus` (0,15), несовпадение - `1 - site_type_penalty` (0,15), `unknown` - 1. Несовпадающих не отсекаем.
- Возраст: `young` - до `young_years` (7) лет, `old` - от `old_years` (12), между - `mid`, нет даты - `unknown`.
- E = W x тип x (1 + `young_bonus` 0,15 для young) x (1 + `growth_bonus` 0,05 при росте it50 от 20%; минус 0,05 при
  падении от 20%). Молодой встает выше старого при W_young >= W_old/1,15 (при равном типе и росте). Числовой пример на
  данных Goldax 05.10 - в тесте `cases-kf-select.mjs`.
- `anchors` - кандидаты-эталоны без стопа по убыванию W: сначала `old`, затем `mid`; ни одного - `unknown` с пометкой
  «эталон без подтвержденного возраста» в `warnings`. `order` - по E; если ни одного из `anchors` нет в первых `target`,
  первый из `anchors` ставится на место `target`, остальные сдвигаются.
- Без метрик вообще: W = null, `order` - по источникам (analysis+serp, analysis, structure, keyso, serp), `warnings` -
  «отбор без метрик».

**Верификатор** (`02-competitor-verifier`, правка). При `ranking.json`: шаг 1 (своя выдача и разбор `rejected`) не
выполняется - это сделал скаут; берет кандидатов строго по `order`, проверяет живость и тип (тот же тип бизнеса и
ассортимента, не агрегатор, не инфосайт, по снимку главной), исключенных пишет с причиной, идет по `order` дальше, пока
не наберет `target` годных или не кончится список (shortlist - не предел). Правило эталона: среди годных нет ни одного
из `anchors` - проверяет следующих из `anchors` и первым годным заменяет годного с наименьшим E, который не эталон
(«вытеснен эталоном»); годного эталона нет - строка в `method` и таблице, без автостопа. `target` - из
`competitors.selection.target` (5); `max_domains` - только старый путь без `ranking.json` (у старых задач там 8; при
ranking игнорируется с пометкой в `method`). Без `ranking.json` - поведение как сейчас. В `competitors.json` у конкурента
дописываются `rank`, `weight`, `age_years`, `age_class`, `growth`, `site_type`, `anchor: true|false`; `source` -
расширить enum: `analysis`, `serp`, `both`, `structure`, `keyso`.

### 3.2. Снятие страниц (пакет B)

**`scripts/capture-pages.mjs`** - мини-клиент CDP на встроенном `WebSocket` Node 24 к установленному Chrome или Edge
(`--headless=new`; пути Windows по умолчанию, переменная `SITE_TEKST_CHROME`). Без npm-зависимостей и скачивания
браузера (довод ADR-035 не нарушен). Свой процесс браузера на поток со своим `--user-data-dir` во временной папке
(префикс `site-tekst-cdp-`; осиротевшие профили старше часа удаляются при старте); MCP-браузер агентов не трогается.
- Вход: `--domain <d>` (страницы домена из `competitors.json`: `ok`/`browser`/`js_only`/`antibot`; для `own` - главная
  `site_url`), `--url <u> --domain <d> --name <имя снимка>` (одна страница), `--file <html> --routes "#/,#/x" --out <папка>`
  (прототип для аудитора). Флаги: `--concurrency` (2), `--resume` (готовое не переснимать; переснимается
  `error`/`skipped` и новый домен), `--max-seconds` (480: по дедлайну новые страницы не берутся, текущие доснимаются,
  браузеры закрываются, `partial: true`, код 0).
- Выход на страницу, папка `work/competitors/shots/<домен>/<имя снимка>/` (не в git): `top.jpg` (0-1100 px), `bottom.jpg`
  (последние 1400 px), `body-01.jpg`..`body-NN.jpg` (тело кадрами 1366x1600, не больше 8; не хватило - `truncated` в
  `limits`), `mobile.jpg` (первый экран 390x844, мобильный UA), `kf.json` (DOM-находки и контур секций, ниже),
  `render.html` (отрисованный DOM). Монолитный снимок всей страницы не делается. Сводка - `work/competitors/capture.json`
  (слияние вызовов по доменам скриптом): `{chrome: "<путь>"|null, pages: [{domain, name, url, type, role:
  "competitor"|"own", status: "ok"|"antibot"|"error"|"skipped", reason, height, ms, files: [{file, y0, y1}], partial}]}`.
  Домены не из `competitors.json` (устаревшие после пересбора) - `skipped`, причина `stale`.
- Поведение: ожидание проверки антибота до 12 с; прокрутка для ленивой загрузки; прокрутка во внутреннем контейнере
  (высота документа равна окну) - снятие ограничений высоты (`html, body` и самый прокручиваемый контейнер) перед
  кадрами; статусы - те же функции, что в `fetch-page.mjs` (коды и видимый текст). Куки-баннер не закрывается.
- Нет Chrome и Edge - код 0, `chrome: null`, страницы `skipped` (`work/kf/status.json` получит `no_chrome`). Код 1 -
  только внутренняя ошибка.
- В wf-02: run-агент `capture` на домен (параллельно; на `own` - отдельный), в промте «в Bash, timeout 600000»; при
  `partial` - повтор того же вызова с `--resume` не больше 2 раз; остаток - `skipped` с причиной `timeout`.

**DOM-находки** (`scripts/kf-dom.mjs` - одна функция обхода для CDP и для jsdom по статическому html; jsdom - через
`deps.mjs`, нет его - без DOM-находок со строкой ограничения). `kf.json`:
`{zones: {header, footer, body, fixed, mobile: [{id, evidence: {selector, text, href}}]}, outline: [{level, heading,
text80, y, tile, has: ["table"|"list"|"form"|"img"|"video"|"map"]}], schema: ["@type"]}`. Зоны: `header` (первый
`header`/`[role=banner]`, иначе верхние 200 px), `footer` (последний `footer`/`[role=contentinfo]`, иначе нижние
элементы), `fixed` (видимые `position: fixed|sticky`), `mobile` (то же на 390 px). Детекторы - id словаря с
доказательством: `tel:`, `mailto:`, мессенджеры, соцсети, формы и поля, поиск, корзина и избранное, кабинет, крошки,
iframe карт и видео, чат-виджеты (общий список src), куки-баннер, ИНН/ОГРН/КПП, юридические ссылки, цены, рейтинг,
Schema.org. Детектор - доказательство, решение по видимости - у наблюдателя. `outline` - текстовый контур секций тела:
по нему наблюдатель находит нишевые блоки даже там, где кадры не смотрел.

**Отрисованный html для текстового снимка.** `fetch-page.mjs <url> <raw> --html-from <render.html>` - снимок из
отрисованного html (тот же разбор секций, `status: browser`, `verbatim: true`, `via: "cdp"`). Если CDP получил страницу
проверки (правила антибота `fetch-page`), она сохраняется следом `<raw без .json>.cdp.html`, снимок не заменяется, и
это окончательный ответ сайта: браузер агента после этого не запускается. Браузер агента - только при отказе CDP (нет
Chrome, таймаут, код не 0). `prep-args.mjs --check-degraded` принимает след CDP наравне с `.browser.md`. Верификатор
(шаг 3, в части CDP) и классификатор: для `js_only`/`antibot`/`error` сначала `capture-pages.mjs --url` + `--html-from`.

- Агрегатор получает `--compact` своего типа и покрывает каждую строку «обязательно»/«рекомендовано»: блоком (рыночным

## 7. Отклонения реализации (приняты, 05.10)

Исполнители пакетов отступили от букв разделов 2-3 там, где буква противоречила замыслу или оставляла случай

**A. Отбор.**
- `pool.json`: у `keyso_status` значение `none` (Keys.so еще не спрашивали) - иначе «не спрашивали» не отличить от «не
  найден», а `--prelim` строит по статусу список для `domains_batch`. Новые необязательные поля: `serp_results`/
  `serp_msk_results` (выдача, сжатая скриптом; `serp` пересчитывается у всех кандидатов, добранные позже получают 0, а не

  `serp.region`, `sources_done[]`.

  213, `keyso_batch`, `keyso`) - `fresh` с `exhausted: true`, а не stale: иначе в узкой нише каждый повтор wf-02 снова
  платит (противоречие с разделом 2). Pool без `sources_done` ведет себя как раньше.

  покрытие, в `reason` «ratio не применяется: ТОП-50 < 50» (это не пропуск данных).
- Выдача: домен становится кандидатом при попадании в ТОП-10 не меньше чем по ceil(`serp_share_min` x число запросов)

Первый живой прогон фазы 2 на копии Goldax (остановлен на снятии) показал перекос отбора: в пятерку попали федеральные
сети и часовой магазин, а мастерские из анализа (mkastom, fuzailov) оказались внизу. Причины и правки:
- **Однословные запросы.** Предметы разделов карты («Кольца», «Браслеты») - неоднозначные запросы: выдача смешивает
  соседние категории (часы по «Браслетам»). `--queries` берет предмет только от 2 до 6 слов, часть до двоеточия, без слов
  навигации («Каталог», «Услуги») и без названия компании.
- **Кандидаты без ниши.** Добор `domain_competitors` Keys.so приносил большие домены без единого попадания в выдачу
  ниши (энциклопедия, часовые и ломбардные сайты, домен другой страны): общий вес домена в Keys.so их поднимал. Стоп
  «нет в выдаче ниши» - кандидат не из анализа и не из структуры без попаданий в ТОП-10 по запросам.
- **Тип бизнеса.** Затравка анализа и структуры получает надбавку `source_bonus` 0,25 (тип бизнеса уже сверен анализом),
  верификатор сверяет профиль строже: основное предложение - те же направления (не соседняя категория), модель - та же
  (мастерская, производство, частная компания против федеральной сети или площадки чужих товаров).
- **Запасной вход `--doc`.** Без `key_phrases` запросы строились из длинных названий страниц с брендом клиента. Теперь в
  режиме doc без фраз первыми идут маркерные и целевые запросы из строк анализа (`analysisQueries`), предметы страниц -
  по правилу выше. В режиме doc конфиг не знает `site_url`, `niche.geo`, `business_type` - это ограничение запасного
  входа (для приемки kadrovy_element_rf их задал оператор).
- Тесты: `cases-kf-select.mjs` (+6 проверок).
- **Оболочка: вид nav.** Прогон kadrovy_element_rf показал, что логотип, главное меню, бургер, меню подвала и копирайт
  лидеров (вид `nav` словаря) по правилу «nav - как slot» превращались в чипы «нужны данные». Это части оболочки,
  которые прототип рисует всегда: теперь `render: "native"` (`kf-matrix --shell`), сборка ставит `shown` без новой
  разметки и без вопроса. Копирайт в словаре - вид `nav`. Тесты: `cases-kf-site.mjs`, `cases-kf-matrix.mjs`.
- **Съемка: сетевой отказ.** На двух доменах kadrovy_element_rf Chrome получил `ERR_CONNECTION_REFUSED` на всех страницах
  сразу после статического снимка (повтор через минуту - открывается: защита сайта режет частые запросы). Съемка теперь
  по одной странице домена за раз (`--concurrency` по умолчанию 1) и с одним повтором сетевого отказа в конце очереди
  после паузы 20 с (`SITE_TEKST_CAPTURE_RETRY_MS`). Тест: `cases-kf-capture.mjs`.
- **Возраст без Арсенкина.** В обоих живых прогонах whois Арсенкина ответил «Too Many Requests» (два скаута сразу):
  у всех кандидатов возраст `unknown`, фактор молодости не работал. Добавлен бесплатный запасной путь
  `rank-competitors.mjs --whois` (whois-сервер зоны на порту 43: .ru, .su, .рф - tcinet; .com, .net - verisign; .org -
  pir; поддомен - по основному домену; последовательно с паузой); wf-02 зовет его перед ранжированием. На пуле Goldax
  заполнил 18 дат за 28 с - в пятерку поднимаются молодые kolvika.ru и whitelake-shop.ru. Тест: `cases-kf-select.mjs`
  (поддельный whois-сервер).
- **Устаревшие разборы.** После пересбора отбора агрегатор категорий Goldax подхватил разборы домена прежнего отбора
  (585zolotoy.ru). wf-02 после верификатора зовет `prep-args.mjs --prune-stale` (разборы блоков не годных доменов - в
  `work/competitors/_stale/`, снимки raw не трогаются), `measure-blocks.mjs` меряет только годных. Тест:
  `cases-kf-capture.mjs`.
- **Верификатор и порядок.** Во втором прогоне Goldax `ranking.json` с возрастом поставил молодые kolvika.ru и
  whitelake-shop.ru на 6 и 8 места, но верификатор обновил метаданные прежнего `competitors.json` и оставил старую
  пятерку (не проверил и не исключил их). Детерминированная страховка: `rank-competitors.mjs --verify-order` (домены
  порядка выше последнего годного, которых нет в файле), wf-02 при пропусках зовет верификатор повторно с параметром
  `recheck` (метка `verify:2`); в промте верификатора - «прежний competitors.json не готовый список». Тесты:
  `cases-kf-select.mjs` (orderGaps), `cases-kf-matrix.mjs` (wf-02 с подставными агентами).
- **Сопоставление страниц оболочки.** Пробная сборка Goldax дала ложные «страницы вне карты»: политика конфиденциальности
  есть в карте без `ui_role: legal`, а поиск, корзина и кабинет - страницами без `ui_role`. В `page_match` роль и
  название теперь альтернативы (тип - обязательное условие); поиск, корзина, кабинет, избранное и сравнение без
  страницы с `ui_role` ищут страницу по названию (`page_match` словаря) и дают на нее ссылку, живой модуль не
  включается. Наблюдатель помечает меню и списки разделов видом `nav` (оболочка рисует их всегда). Тест:
  `cases-kf-site.mjs` (раздел 3б).
  Страховка сборки: элемент `shell.json` без `page_match` (оболочка снята до появления поля) берет его из словаря
  (`build-html.mjs`, не для элементов ниши).
- **Шапка без пустых кнопок.** Ссылки шапки на страницы вне карты (`page_missing`) делали шапку Goldax длинной строкой
  неактивных кнопок. Теперь они уходят в колонку «Информация» подвала (без дублей), в шапке и мобильном меню их нет;
  вопрос заказчику остается. Тест: `cases-kf-site.mjs`.
- **Имена элементов.** Служебная пометка в скобках в конце названия («Отзывы (ссылка)», «Гарантии (блок)») попадала в
  подписи прототипа и строки таблицы. Подписи прототипа - `shellName` (без скобки в конце), таблица и отчет - `elName`
  (без пометки вида: ссылка, блок, кнопка, иконка, меню, раздел, страница, форма, виджет; пояснение «Реквизиты (ИНН,
  ОГРН)» остается); в словаре такие имена переписаны («Ссылка на отзывы», «Блок гарантий»). Тесты: `cases-kf-site.mjs`,
  `cases-kf-xlsx.mjs`.
- **Итог приемки Goldax (копия задачи, полная цепочка).** Отбор с возрастом (whitelake-shop.ru в пятерке, kolvika.ru
  исключен верификатором как поставщик), wf-03 - 0 открытых находок, 3 страницы переписаны по охвату КФ (главная,
  изготовление, каталог колец: блоки проверки по отзывам и витрина появились, повторы ушли, объем 1896 -> 2127 слов),
  wf-06 - 0 открытых, wf-08 - 20 находок, правки на 4 страницах, пересборка: скелетов 0, check-html pass, check-site-js
  pass; таблица «КФ и КНДР - Goldax» опубликована в папку задачи (4 листа, «Сравнение» 425 строк), отчет собран,
  state `built`. Вопросов заказчику в отчете 164, из них от КФ - 7; остальные - `needs_fact` писателей (механизм до
  программы, много повторов одного вопроса по страницам) - отдельная задача. Два чипа Goldax («Список разделов каталога
  в подвале», «Изготовление на заказ») - элементы ниши, которые наблюдатель старого промта назвал видом `slot`; с видом
  `nav` в промте они станут частью оболочки, на живых данных не перепроверено (повтор наблюдения - дорогая фаза 2).
- **Приемка kadrovy_element_rf.** Фазы 0-3 прошли (отбор: 1 давний эталон + 4 молодых, матрица с элементами ниши).
  wf-04 остановлен: общий стратег отказался работать с нишей (военный рекрутинг) - это отказ модели по теме, не сбой
  kit. Полная цепочка на сайте услуг - на другом проекте.
