# Программа 06.10.2026: /seo-strategiya v2 - новая линейка, прогноз по кейсам, стратегия без тарифов, дизайн

Запрос владельца (06.10.2026, ночь, автономно): обновить линейку услуг, добавить разработку сайта и акции, полностью
пересмотреть декомпозицию и ROMI (почти всегда минус), откалибровать прогноз по кейсам cases.timur-seo.ru, сделать
стратегию короткими тезисными блоками без тарифов (тарифы - только в смете) и красивый дизайн документа.

Исследование (сырые отчеты - в scratchpad сессии, выводы - здесь): кейсы (13 проектов с помесячными рядами Метрики),
разбор 45 реальных смет (почему минус), Timary (разработка сайта и цены), описания услуг по алгоритмам скилов, карта
машинерии, дизайн docx с проверкой конверсии в Google Docs.

## 1. Диагноз старой экономики (45 реальных смет)

- ROMI Роста за 12 мес: минус в 21 из 45 (47%), ниже 100% в 32 из 45, медиана +8%; в ядре (чек до 300 тыс) минус в
  17 из 25. Плюс - почти всегда артефакт (чек 3-12 млн по 3-50 сделкам или засчитанный SEO текущий трафик).
- Причины по силе: (1) окно 12 мес на J-кривой при плоской абонентке с 1-го месяца; (2) ROMI от маржи при конверсии
  2%, хотя кейсы агентства дают 7-13% визит -> обращение; (3) плоский масштаб тарифов x0,6 / x1,0 / x1,3 против цены
  x2,1 / x2,2 - Рост хуже Старта по ROMI в 42 из 44 смет ТОЖДЕСТВЕННО; (4) засчитывание SEO текущего трафика m0;
  (5) сценарий «Вход 3-6 мес» бьет «Год» и смета сама это пишет.
- Кейсы: сайт с нормальной базой + ПФ: m3 x2,14, m6 x2,36 (медианы); новые сайты услуг - 8-9 визитов/мес на страницу
  в индексе; разгон нового сайта 45-75% уровня к m3, 75-95% к m6; ПФ после остановки держится на 0,7 от пика.

## 2. Решения (базовые решения принимает агент; владелец может переиграть)

| # | Решение |
|---|---|
| Р1 | Новые ID: `KP` (КФ/КНДР + ч/б прототип с текстами, 25к, 5-7 дн), `FQ` (n-граммы + FAQ, 25к, 3-5 дн, до 30 стр), `YM` («Продвижение в Яндекс Картах» с v2.2, было «Яндекс Карты: активность»; 25к/мес), `DEV` (разработка сайта, отдельный блок). `NG`, `KF`, `BR`, `YB` выведены, остаются в легаси-словаре сметы. |
| Р2 | `PA` обязателен при `SY` или `KP` (алгоритмы так устроены: `/seo-struktura` и `/site-tekst` без гейта анализа не стартуют). Порядок PA -> SY -> KP -> FQ. |
| Р3 | Тариф выше включает тариф ниже (Рост ⊇ Старт, Максимум ⊇ Рост, с апгрейдами PF->PFP, LB->LA, ART->AR). |
| Р4 | Кривая трафика у каждого тарифа своя - из вклада услуг (`_forecast-model.mjs`). Калибровка (модель v2.2): кейсы агентства с поправкой x0,8-0,9 на отбор + портфель ПФ (Monstro + Метрика) + практика владельца (ПФ ускоряет выход в топ, Карты усиливают ПФ в 1,5 раза, ссылки и техаудит - см. раздел 9). Плоский масштаб удален. |
| Р5 | Деньги - только с прироста над текущим трафиком; конверсия по умолчанию 5% для услуг (кейсы: медиана 9,1%); ROMI - от валовой прибыли; окно 24 мес (ROMI 12 мес - заголовок, второй год - отдельной строкой). Сценарий «Вход 3-6 мес» удален. |
| Р6 | Экономический гейт после тарифов: ROMI Роста за 12 мес > 0 и чистый результат Роста >= Старта - иначе один круг пересборки тарифов; цель ROMI Роста 100%+ и ROMI Роста >= Старта - предупреждения. |
| Р7 | Акции: «ПФ 1=2» (сайт без позиций, моложе 6 мес, или разработка у нас) - минус ПФ во 2-м мес; «Тестовая статья в подарок» (ART за 0 в тарифе без AR). |
| Р8 | Разработка сайта - отдельная вкладка сметы: база по формуле калькулятора MK (лендинг 80 000 при 10 блоках; многостраничник 6 000 x блоков + прототип 25 000 + подстраницы ступенями с полом), опции строками без суммы. При `KP` в тарифе - зачет стоимости прототипа. |
| Р9 | Стратегия docx: 4 раздела тезисами (Где вы сейчас / Кто в топе / Что нужно, чтобы обогнать / Прогноз) + обложка и «Коротко»; ни цен, ни тарифов, ни слова «тариф»; все деньги клиента (потери, прогноз выручки) рендерит сборщик из `forecast.json`, писатель денег не пишет. |
| Р10 | Новый шаг state machine `forecast-done` между `tariffs-done` и `content-done` (скрипт `build-forecast.mjs`). |
| Р11 | Старые стратегии пересобираются старыми путями: content без `format: "v2"` - старый рендер docx; data без `forecast_inputs` - старые листы сметы (`_forecast-money.mjs` не трогаем). |
| Р12 | Выкатка: TARIFFS.md/RULES.md глобальные и уже обновлены; машинерия - мерж в main и push (новые проекты клонируют шаблон с GitHub); `/sync-all` на старые клоны - только по команде владельца. |

## 4. Контракты

### 4.1. `seo-strategiya_data.json` -> `forecast_inputs` (пишет growth-strategist, $version 4.0)

```json
"forecast_inputs": {
  "business_type": "services | medical | b2b | high_ticket | ecommerce | info",
  "competition": "low | medium | high",
  "t0": 40,
  "t0_source": "metrika | keyso | estimated",
  "pages": {
    "existing_commercial": 8,
    "planned_new": 40,
    "catalog_cards": 0
  },
  "demand": {
    "commercial_month": 15000,
    "info_month": 5000,
    "basis": "сумма ТОЧНЫХ частот (\"!\") N маркеров коммерческих кластеров по региону <id>: ..."
  },
  "local": true,
  "maps_card": "none | unverified | verified | unknown",
  "tech_critical": false,
  "has_positions": true,
  "site_age_months": 30,
  "implementation_lag_shift": 0,
  "competitors_traffic": { "median": 1800, "leader": 6000, "basis": "Keyso domains_batch, база msk" },
  "economics": {
    "avg_check": 32000, "avg_check_source": "client | site | estimated",
    "conversion_rate": 0.05, "close_rate": 0.3, "margin": 0.4,
    "model": "two_step | one_step",
    "basis": "почему такие значения"
  }
}
```
- `existing_commercial` - коммерческие посадочные в индексе (не статьи, не служебные). `planned_new` - сколько новых
  коммерческих страниц даст структура (разрыв с конкурентами по направлениям/услугам; для нового сайта - весь план
  страниц). `catalog_cards` - карточки товаров (магазин).
- `demand.commercial_month` - сумма точных частот маркеров коммерческих кластеров (одним пакетным `jm_wordstat`, регион
  клиента). Не сумма широких частот.
- Экономика: клиентские значения из `inputs.json` перекрывают оценку агента (делает скрипт). Дефолты по типу бизнеса -
  `ECON_DEFAULTS` в `_forecast-model.mjs` (services 5% / 30% / 40%; medical 5% / 50% / 40%; b2b 3% / 20% / 35%;
  high_ticket 2% / 5% / 20%; ecommerce 1,5% заказ / 25%; info 1%).
- `forecast_scenarios` и `decomposition` больше не пишутся (только у старых файлов). `forecast[]` (ТОП-10/50, DR) - не
  пишется: прогноз трафика и денег считает скрипт.

`special`, `checks`), плюс:

  "onetime": [ {"id": "PA", "price": 5000}, {"id": "ART", "price": 0, "regular_price": 3000, "promo": true} ],
  "monthly": [ {"id": "PF", "price": 25000}, {"id": "YM", "price": 25000}, {"id": "RP", "price": 0} ],
  "promos": [ {"type": "pf_2for1", "reason": "сайт без позиций - второй месяц ПФ в подарок"} ],
  "...": "..."
},
"site_dev": {
  "recommended": true,
  "format": "multipage",
  "pages": 30,
  "home_blocks": 10,
  "reason": "сайта нет / лендинг без страниц услуг / ...",
  "promo_note": "при заказе разработки у нас - акция ПФ 1=2"

- `economics_round` - номер круга пересборки по гейту (0 - первый, 1 - после exit 3).

### 4.3. `forecast.json` (пишет build-forecast.mjs)

`model_version`, `horizon_months` (24), `recommended` ("growth" - по его составу план работ docx), `recommended_offer`
(что выделяет смета: "growth"; при проваленном экономическом гейте - тариф с лучшим чистым результатом за 12 мес, если
он в плюсе, иначе `null`), `inputs` (разрешенные входы + экономика,
`economics_from_client`), `assumptions_note` (строка для сметы и docx), `baseline` (t0, обращения и выручка сейчас),
`lost_now` ({traffic_month, leads_month, leads_maps_month, sales_month, revenue_month, revenue_year,
competitors_traffic_*}; обращения и продажи - с десятыми из 12-го месяца Роста),
`plan_series` (m0..m12: traffic, leads, revenue, baseline - для графика docx), `tariffs.{start,growth,max}`
({ids, checkpoints m0..m24, drivers_m12, year1, year2, payback_month, m12, runrate_m12, months[1..24]}),
`checks` ({hard[], soft[]}).

`niche` (v2.2, запрос владельца 06.10: «не хватает конкретных метрик - какого качества конкуренты и какие услуги нужны,
чтобы достичь их качества; какой трафик получают конкуренты в топе, чтобы понимать, чего можем достичь») - карточка
ниши, чистая функция `nicheCard` из `_niche.mjs` по уже собранным `competitors.json`, `metrics.json` и
`forecast_inputs` (без MCP; нет файла - строки без данных пропускаются; ошибка расчета - `niche: null` и строка
«niche: пропущен» в stdout, шаг не падает). На модель прогноза не влияет.
- `volume`: `demand_exact`, `demand_basis` (спрос по главным запросам), `leader {domain, traffic}`,
  `median_top3_traffic`, `top3[] {domain, traffic, top10, commercial_pages, dr}` (топ-3 прямых по трафику, без трафика
  - по ТОП-10; медиана и лидер без данных - из `forecast_inputs.competitors_traffic`), `client_now` (t0),
  `reachable_12` (трафик тарифа плана к 12 мес), `share_of_median_12`, `share_of_leader_12` (%), `ceiling` (потолок
  модели), `traffic_basis`;
- `competition`: `level` (low / medium / high из `forecast_inputs.competition`), `basis` (строка-основание),
  `factors[] {key, label, top3_median, client, gap, services[], note, examples?}` - `pages` (страницы под спрос -> SY +
  KP/FQ), `visibility` (запросы в ТОП-10 -> PF/PFP, при local + YM), `traffic` (справочно, без работ), `links` (DR:
  разница от 8 пунктов big, 4-7 some -> LB/LA), `ref_domains` (доноры, справочно), `commercial` (элементы лидеров из
  `leader_pages_summary.client_missing`: 5+ big, 2-4 some -> KP, `examples` до 4), `blog` (лидеры растут статьями ->
  AR), `maps` (local: карточки нет / не подтверждена -> big, подтверждена -> some, YM); `gap` с медианой топ-3: big -
  у клиента меньше 50%, some - меньше 80%, none, unknown - сравнить не с чем;
- `to_parity[] {id, factors[], in_plan, in_max}` - работы, закрывающие разрывы big / some, и есть ли они в тарифе плана
  и в Максимуме.

### 4.4. `seo-strategiya_content.json` v2 (пишет strategy-writer)

```json
{
  "format": "v2",
  "title_page": { "title": "SEO-стратегия", "domain": "...", "niche_oneliner": "...", "region": "...", "date": "Октябрь 2026", "author": "TIMUR SEO" },
  "summary": { "headline": "одна фраза-вывод", "points": ["тезис 1", "тезис 2", "тезис 3"] },
  "sections": [
    { "key": "situation",   "title": "Где вы сейчас",                     "blocks": [ ... ] },
    { "key": "competitors", "title": "Кто в топе и почему",               "blocks": [ ... ] },
    { "key": "plan",        "title": "Что нужно, чтобы обогнать конкурентов", "blocks": [ ... ] },
    { "key": "forecast",    "title": "Прогноз",                           "blocks": [ ... ] }
  ],
  "next_step": "одна фраза: что дальше (без цен)"
}
```
Обложку и «Главное за одну минуту» собирает сборщик: баннер (домен, ниша), строка «Регион / Дата / Подготовил»,
3 KPI-плитки из `forecast.json` (рост трафика за 12 мес по плану xN; ~N обращений в месяц уходят конкурентам; ~N руб
выручки в месяц недополучаете) и выноска «Коротко» из `summary.points` писателя.

Типы блоков (все поля - строки без цен и без денежных сумм; `**жирный**` внутри строки допускается - сборщик делает
жирным):
- `subheading {text}`, `paragraph {text}` (первый `paragraph` раздела - лид крупнее)
- `kpi_row {items: [{value, label, tone?: "neutral|good|bad|accent"}]}` - 2-4 плитки
- `issues {title?, items: [{title, text, severity: "high|medium|low"}]}` - проблемы карточками
- `bullets {title?, style?: "check|cross|arrow|dot", items: [строки]}`
- `callout {tone: "info|warning|good", title, text}` - выноска
- `table {columns: [...], rows: [[...]]}`
- `compare {columns: ["Элемент", "<конкурент 1>", "<конкурент 2>", ..., "Вы"], rows: [{label, values: [true|false|"частично"]}]}` - матрица «у них есть / у вас»
- `bars {title, unit, items: [{label, value, highlight?: true}]}` - горизонтальные столбики (например трафик конкурентов против клиента)
- `plan_item {title, problem, solution, effect, services: ["SY","KP"]}` - карточка «01 / ПРОБЛЕМА / РЕШЕНИЕ / ЭФФЕКТ»;
  `services` - ID услуг рекомендованного тарифа (для проверки; в docx не выводятся), `solution` - человеческими словами
  с коротким названием услуги (`short` из `_services.mjs`), `effect` - без денег (трафик/обращения/позиции из
  `forecast.json` и данных)
- `quick_wins {items: [строки]}` - «можно сделать уже сейчас» (2-3 пункта)
- `conditions {items: [строки]}` - условия прогноза (2-3 пункта)
- маркеры, которые заполняет сборщик (из `forecast.json`, `tariffs.json`, `_services.mjs`):
  `{"type": "money_lost"}` (раздел situation: заголовок «Деньги, которые вы теряете» + воронка переходы -> обращения ->
  продажи -> выручка в месяц + допущения), `{"type": "plan_timeline"}` (раздел plan: план работ по месяцам 1-12 по
  составу рекомендованного тарифа - разовые этапы в порядке PA -> SY -> KP -> FQ, ежемесячные полосой),
  `{"type": "forecast_chart"}` (столбики трафика m1..m12 по плану), `{"type": "forecast_table"}` (Сейчас / 3 / 6 / 12
  мес: трафик, обращения, выручка - с планом и без работ), `{"type": "forecast_drivers"}` (за счет чего растем к 12 мес),
  `{"type": "niche_card"}` (v2.2, раздел competitors сразу после лида: «Объем и конкурентность ниши» по
  `forecast.json niche` - плитки объема, уровень конкуренции, таблица «Показатель / Топ-3 (медиана) / У вас / Что
  сделаем» с работами под разрывы, строка «Чтобы дотянуться до топа»).

Обязательно: 4 раздела с ключами `situation`, `competitors`, `plan`, `forecast`; в situation - `money_lost`; в plan -
хотя бы 2 `plan_item` и `plan_timeline`; в forecast - `forecast_chart` и `forecast_table`. Объем docx - 4-6 страниц A4.
С v2.2 писатель ставит и `niche_card` (норма competitors: лид, `niche_card`, `compare`, `callout`; `bars` и `table` -
только без `niche` в `forecast.json`). Числа карточки в прозе не дублируются; на разрывы проза ссылается словами («у
лидеров в 5 раз больше страниц под спрос»: `big` - отношение `top3_median / client` с округлением вниз, `some` - без
числа, `none` - не разрыв, `unknown` - не упоминается) в лиде competitors, лиде plan и `problem` карточек плана, чьи
работы закрывают этот разрыв (`to_parity`, `in_plan`). Нет маркера - предупреждение гейта, не блок: content v2,
написанный до карточки, собирается без нее.

## 6. Смета xlsx

Листы: «Сравнение тарифов» (первым) / «Старт» / «Рост» / «Максимум» / «Разработка сайта» / «Окупаемость».
- «Сравнение тарифов»: 3 колонки тарифов: разово, ежемесячно, состав коротко, акции, трафик к 3/6/12 мес, обращений в
  мес к 12 мес, вложения за 12 мес, чистый результат 12 мес, ROMI 12 мес, окупаемость, ROMI 24 мес; рекомендованный
  выделен.
- Тарифные листы: как было (+ строка-подсказка «почему этот вариант» из `hint`, акции строками, ART с зачеркнутой
  обычной ценой текстом «3 000 ₽ -> 0 ₽ (акция)», порядок оплаты с учетом ПФ 1=2).
- «Разработка сайта»: формат, база по строкам `devPrice().parts`, итог; блок «Что входит» (`DEV_BASE_ITEMS`); опции
  (`DEV_OPTIONS`, цена или «по расчету», не в итог); зачет прототипа при KP в Росте; акция ПФ 1=2; пометка
  «рекомендуем» / «по запросу» из `site_dev.recommended`.

### 9.1. Боевые прогоны и модели v2.1 / v2.2 (06.10.2026)

Пять клиентов разного профиля: lazermedrostov.ru (медицина, Ростов-на-Дону, сайт с базой), potolki-sochi (натяжные
потолки, Сочи, сайта нет), топдом.рф (дома под ключ, Москва, чек ~12 млн), burols.ru (ландшафтное проектирование,
Санкт-Петербург, сайт без трафика), goldenagro.by (саженцы и яблоки, магазин, Минск). Артефакты -
`.claude/tmp/live-v2/<slug>` (`_old` - смета до v2, `_round1` / `_round2` - сохраненные круги).

**Круг 1 (модель v2.0): потолок спроса и плоские кривые.** Потолок был жестким - 20% суммы точных частот маркеров
коммерческого спроса (при высокой конкуренции 12%). А сумма точных частот главных фраз в 5-10 раз меньше реального
спроса (нет хвостов, форм с городом, области), и потолок обрезал прогноз к 3-4-му мес у всех 5 клиентов: дальше кривые
плоские, трафик трех тарифов к 12 мес почти одинаковый - тарифы различались ценой, а не результатом. Попутно: у дорогих
услуг без цикла сделки окупаемость выходила «1 мес» (топдом.рф); обращения из Карт (0,2% спроса, 18 в мес у
медцентра) держали на себе плюс Роста; мощность маленького бизнеса не ограничивалась (дизайнеру-одиночке модель
давала 6 новых проектов в мес); в Google Docs жесткий разрыв перед каждым разделом давал почти пустые страницы.

**Модель v2.1 (коммит db06041) - правки по кругу 1; на ней прогнан круг 2.**
- **Мягкий потолок** (`softCap`: до 60% потолка без среза, дальше плавно к потолку) = максимум из: точный спрос x доля
  (low 1,0 / medium 0,8 / high 0,6), трафик лидера прямых конкурентов x1,5, медиана прямых x1,5, текущий трафик x2,5.
  Лидер x1,5 - потому что Keys.so занижает трафик примерно вдвое против Метрики (медиана 0,6 по 9 сайтам).
- **Запуск нового сайта:** `launch_month` (разработка у нас - 2-й мес, у разработчика клиента - 3-й); новые страницы и
  ежемесячные работы (и их оплата) - с месяца запуска, бесплатный месяц «ПФ 1=2» - следующий за запуском; в docx -
  строка «Разработка и запуск сайта» и подпись «Сайт выходит в поиск к N-му месяцу».
- **Цикл сделки** `sales_lag_months` (high_ticket 3 мес, b2b 2): обращение месяца становится продажей через N мес,
  окупаемость - не раньше первой продажи.
- **LTV** `ltv_factor` (покупок одного клиента за 12 мес: medical 1,8, ecommerce 1,3, остальные 1; агент может задать
  свое с basis): выручка с продажи = чек x `ltv_factor`, в смете - формулой.
- **Мощность бизнеса:** growth-strategist сверяет базовые продажи с поиска с масштабом компании (`economics.scale`:
  продажи в мес по цифрам сайта, для одиночки или 1-2 бригад - `capacity_month`; видят проверка и писатель). В модели
  есть необязательный предел `forecast_inputs.capacity_sales_month` (дополнительных продаж в мес не больше свободной
  мощности сверх текущих), но агент его пока не пишет - модель мощностью не ограничивает.
- **Потери от конкурентов** `lost_now`: разрыв с конкурентами (`basis: competitors` - ориентир max(медиана, половина
  лидера), не выше уровня плана к 12 мес; без конкурентов - `basis: plan`) по БАЗОВОЙ конверсии, без прототипа и Карт -
  воронка сходится с допущениями.
- Бусты на странице (FA, BS, MT, FQ, KP) - только на существующие страницы и слабее на большой базе
  (f = (400 / t0)^0,25, пол 0,45); обращения из Карт - 0,15% спроса, при уже существующей карточке - только прирост
  (x0,7).
- docx и смета: план, график и потери - по тарифу плана `plan_tariff`; абсолютной выручки «без работ» нет; в смете LTV
  и цикл сделки формулами, точка безубыточности («Окупится за 12 мес, если»), ROMI с разработкой. Агенты: спрос по
  кластерам, одна база Keys.so, драйвер Роста - только если окупается, акция «ПФ 1=2» - по числовому порогу позиций по
  локальной базе. Тесты 104/104.

**Модель v2.2 (коммит b7252ab) - факты владельца (практика, 06.10).** Первые стратегии v2 владелец счел слишком
скептичными: на Росте с ПФ и Картами около 250 переходов реально уже к 3-4-му мес. Факты и как они легли в `CAL`:
- **ПФ ускоряет выход новых страниц в топ:** уровень, который без ПФ берется за 12+ мес, с ПФ - примерно за 6 мес.
  `new_pages_ramp_pf.tau` 2,5 -> 2,0 (86% уровня через 4 мес после лага), без ПФ `tau` 3 -> 4,5 (90% только к ~13-му
  мес); штраф уровня без ПФ мягче (`nopf_level_factor` low / medium / high: 1,0 / 0,9 / 0,75 вместо 0,9 / 0,7 / 0,5) -
  без ПФ главное отличие в скорости, а не в уровне.
- **Карты (`YM`, теперь «Продвижение в Яндекс Картах») усиливают ПФ в 1,5 раза** (`pf_ym_synergy`): эффект ПФ на
  существующих страницах x1,5 и разгон в 1,5 раза быстрее - и существующих, и новых страниц. Отдельный буст `YM`
  (x1,08, перенос веса карточки на сайт) - только в тарифе без ПФ.
- **Новому сайту на новом домене ПФ без Карт почти не дает первых переходов** (в 1-й мес после запуска меньше 100):
  разгон новых страниц на полмесяца позже и в 1,5 раза медленнее (`new_domain_no_ym`; новый домен - запуск позже 1-го
  мес или сайту меньше 6 мес). При адресе ПФ и `YM` ставятся парой - у нового сайта уже в Старте (`tariff-architect`,
  RULES раздел 3).
- **Ссылки дают эффект не раньше 3-4 мес и в основном в Google:** `LB` x1,06 / `LA` x1,12 (было 1,08 / 1,15), лаг 4 мес
  (было 3). При акценте на Яндекс в начале полезнее статьи: драйвер Роста без Карт - `AR + IT`, `LB` - только при
  Google-акценте заказчика или лучшей отдаче; в Максимуме ссылки - вторым драйвером.
- **Техаудит дает буст только при серьезных тех. ошибках** (`tech_critical`: ошибки индексации, robots закрывает
  коммерческие разделы, noindex или чужой canonical, контент только после JS): x1,12; без них x1,02, и `FA` в тариф не
  ставится.
- Пример: lazermedrostov.ru (t0 125) - Рост с Картами к 3-му мес 440 переходов (Рост без Карт в круге 2 - 337).

**Калибровка ПФ - портфель агентства, а не витрина кейсов** (Monstro + Метрика, 13 сайтов на ПФ, 06.10.2026). База от
100 переходов: m1 x1,03, m2 x1,42, m3 x1,72 (Q1 1,47 - Q3 1,88), m6 x2,38 (n=4), m12 x2,58 (n=3, с параллельными
факторами). Модель: m1 ~1,1, m2 ~1,45, m3 ~1,74, m6 ~2,08, плато x2,2 (`pf_mult_max`) - по m3 как портфель, дальше
чуть ниже. Витрина кейсов (m3 x2,14) не берется - это лучшие проекты. Без ПФ портфель дает m3 x0,88-1,03 (часть сайтов
падала до старта) -> `nopf_mult_max` 1,25. Удержание после остановки ПФ: 0,7 + 0,3 x exp(-t / 1,5) (через месяц ~0,9

Открытые вопросы владельцу:
- Порог конверсии клиента 30% (выше - предупреждение, не блок) - устраивает?

  нет («дадим после уточнения чека и маржи»), docx описывает план Роста. Оставить так, предлагать таким клиентам только

  (Яндекс Карты: активность)»). Имя окончательное? Если да - поправить эти две строки (глобальные файлы, из шаблона не
