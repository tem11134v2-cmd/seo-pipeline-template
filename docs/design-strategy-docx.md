# Дизайн документа SEO-стратегии (docx -> Google Docs)

Дизайн-система стратегии `/seo-strategiya` v2: что переживает конверсию docx -> Google Docs, палитра, шрифты,
компоненты и правила «что нельзя». Код всех компонентов - `.claude/scripts/build-strategy-docx.mjs` (блок
«v2: ДИЗАЙН-СИСТЕМА»), контракт контента - `docs/upgrade-program-2026-10-06-strategy-v2.md`, разделы 4.4 и 5.

Все выводы про конверсию проверены экспериментом 06.10.2026, а не по памяти: docx загружался в личный Drive через
`gdrive-piotr uploadFile` с `convertToGoogleFormat: true` (без расшаривания), результат выгружался из Drive как PDF
(рендер Google Docs, `Producer: Skia/PDF Google Docs Renderer`) и как docx (то, что Docs реально хранит), страницы
смотрелись картинками (`pdftoppm`), XML разбирался. Тестовые файлы после проверки - в корзину Drive (`deleteItem`).
Проверены: матрица из 40 приемов, демо-документ из всех компонентов, затем сборка `build-strategy-docx.mjs` v2 на
фикстуре (6 страниц) и на краевых случаях (новый сайт, магазин, неизвестные блоки).

## 2. Что ломается при конверсии docx -> Google Docs (проверено)

1. **Две таблицы подряд без абзаца между ними Docs склеивает в одну таблицу с общей сеткой.** Главная ловушка: баннер
   обложки (1 колонка) прилип к строке «Регион / Дата / Подготовил» (3 колонки) и схлопнулся до трети ширины. Лечится
   пустым абзацем между таблицами (`spacer(0)`). Сборщик в конце дополнительно вставляет `spacer(0)` между любыми двумя
   соседними таблицами. Таблица первым элементом документа - нормально.
2. **Ширина таблицы в процентах** (`WidthType.PERCENTAGE`) - таблица схлопывается до 200 twips. Только DXA + `columnWidths`.
3. **Textbox (VML)** - пропадает без следа. Плавающие фигуры и надписи не использовать.
4. **SVG** - Docs берет PNG-фолбэк. SVG бессмысленен.
5. **Табуляция с лидером** - точки пропадают. Раскладку «слева-справа» делать таблицей 2 колонки.
6. **Разрядка** (`characterSpacing`) - пропадает.
7. **allCaps** - ненадежен. Прописные писать буквами («КОРОТКО», «ПРОБЛЕМА»).
8. **Высота EXACT** -> становится atLeast. Пустая ячейка-заливка должна быть низкой сама: пустой абзац с
   `run: {size: 2}` и `spacing {before:0, after:0}` (`tiny()`).
9. **Шрифт не из Google Fonts** подменяется (Segoe UI -> Quattrocento Sans).
10. **pageBreakBefore + keepNext у ПРЕДЫДУЩЕГО абзаца** - абзац с keepNext уезжает на отдельную страницу.
11. **Отдельный абзац с PageBreak после раздела, заполнившего страницу ровно,** дает пустую страницу (абзац-разрыв
    переезжает на новую страницу и рвет еще раз; проверено на сборке v2).
12. **Жесткий разрыв перед КАЖДЫМ разделом** (`pageBreakBefore` у всех H1) в Google Docs дает почти пустые страницы:
    Docs верстает плотнее или свободнее Word, и хвост раздела в 2-3 строки уезжает на свою страницу (приемка Drive
    боевого прогона 06.10.2026). Поэтому с v2.1 жесткий разрыв - только один: после первой страницы (обложка +
    «Главное за одну минуту»), `pageBreakBefore` у первого H1. Остальные разделы идут потоком: разделитель (синяя линейка
    3pt сверху у H1 + отбивка 26pt) и `keepNext` у заголовков. В конце раздела нет хвостового абзаца-отбивки. Предыдущий
    элемент перед H1 - таблица, заметка или список без keepNext, так что ловушка п. 10 не возникает.
13. **keepNext в строках таблицы Docs не держит** (Word держит таблицу целиком, если у абзацев всех строк, кроме
    последней, стоит keepNext). Надежно в обоих - одноячеечная таблица-обертка без границ со строкой `cantSplit`
    (`keepTogether()`): строку нельзя рвать, и блок целиком переезжает на следующую страницу. Блок должен быть заметно
    меньше страницы.

**Переживает без потерь:** заливка абзаца; левая граница абзаца (полоса-акцент); одноячеечная таблица с заливкой и
левой границей 4.5pt; полоса отдельной узкой ячейкой; левая граница ячейки 1.5 / 3 / 6 / 12 pt; карточки с зазорами
пустыми колонками или белыми границами; цветная верхняя граница ячейки; вложенная таблица; colSpan/rowSpan;
вертикальное выравнивание; таблица только с горизонтальными линейками + повтор шапки + cantSplit; двухколоночная
раскладка таблицей без границ; столбики-таблицы (горизонтальные и вертикальные); эмодзи и символы
`● ▲ ■ ◆ ▸ ✓ ✗ → ★ ☐ ☑ ① № ₽ ≈ ×`; кастомные маркеры списков с цветом; стили заголовков Heading 1-3 с нашим шрифтом и
цветом; PNG inline; колонтитулы, отдельная первая страница, «стр. X из Y»; цвет страницы.

**Шрифты** (по `pdffonts` экспортированного PDF - реально встроены и отрисованы своим шрифтом, все с кириллицей):
Arial, Calibri, Roboto, Roboto Mono, Roboto Condensed, Montserrat, Inter, Manrope, PT Sans, Golos Text, Open Sans,
Unbounded, Raleway, Nunito Sans. При выгрузке Google Doc обратно в .docx Google вкладывает файлы шрифтов, так что
скачанная Word-версия выглядит так же.

**Полосы символами** `█░` дают щели между глифами - столбики делаем таблицей.

## 3. Дизайн-система

Принцип «читается на лету»: первая страница отвечает на вопрос заказчика целиком (обложка + 3 цифры + «Коротко»);
каждый раздел начинается с вывода крупным шрифтом (lead), потом визуал (карточки, график, таблица), потом детали;
абзац не длиннее 2-3 строк; все, что перечисляется, - списком с символьным маркером; заголовки - настоящие Heading
(оглавление слева в Google Docs).

### 3.5. Откуда берутся числа (деньги рендерит только сборщик)

Писатель (strategy-writer) денег не пишет; маркеры и KPI обложки заполняются из `forecast.json`
(`build-forecast.mjs`, модель v2.1) и `tariffs.json`. **Тариф плана** `<plan>` = `forecast.plan_tariff`
(= `recommended_offer`, при проваленном экономическом гейте - лучший тариф, иначе Рост; старый forecast.json без поля -
`recommended_offer`, иначе Рост). Поле `recommended` ("growth") для плана не берется: документ и смета рекомендуют одно.

| Где | Источник |
|---|---|
| KPI «рост трафика» | `tariffs.<plan>.checkpoints.m12 / t0`: только при `t0 >= 30` - от x2 «×N», меньше «+N%»; при `t0 < 30` - «до N» + «переходов из поиска в месяц к 12-му месяцу (сайт растет с нуля / сейчас около M)» |
| KPI «обращений уходят», «выручки недополучаете» | `lost_now.leads_month`, `lost_now.revenue_month`; подпись по `lost_now.basis`: competitors - «уходят к конкурентам», plan - «недополучаете против уровня года» |
| `money_lost` | `lost_now.{basis, target_traffic, traffic_month, leads_month, sales_month, revenue_month, competitors_traffic_*}`, допущения - `inputs.economics` (см. ниже) |
| `plan_timeline` | `timelineFor(ids)` из `_services.mjs`, ids - состав `tariffs.json <plan>` (запасной путь - `forecast.json tariffs.<plan>.ids`); строка разработки - `devTimelineRow(ids, {launchMonth: forecast.launch_month, recommended: tariffs.site_dev.recommended})`; ежемесячные полосы - с `launch_month` |
| `forecast_chart` | `plan_series` m1..m12 (`traffic`, ряд тарифа плана), база - `inputs.t0`; `launch_month > 1` - подпись «Сайт выходит в поиск к N-му месяцу» |
| `forecast_table` | переходы: «С планом» - `tariffs.<plan>.months[m].traffic`, «Без работ» - `t0`; «Дополнительные обращения» - `months[m].leads` (с Картами и прототипом), «Дополнительная выручка» - `months[m].revenue` (с циклом сделки и повторными покупками); `economics.sales_lag_months > 0` - сноска «продажа через N мес после обращения» |
| `forecast_drivers` | `tariffs.<plan>.drivers_m12` (base, existing_gain, new_pages, articles, maps_leads, conv_mult) + итог `checkpoints.m12` |

**Блок потерь (`money_lost`), семантика v2.1.** `lost_now` - не обещание плана, а разрыв по трафику, посчитанный по
БАЗОВОЙ конверсии (без прототипа и Карт), поэтому воронка сходится с подписью допущений: переходы x конверсия =
обращения, x закрытие = продажи, x чек (x `ltv_factor`) = выручка.
- `basis: competitors`, ориентир конкурентов (max(медиана, половина лидера)) не выше `target_traffic` - «Конкуренты из
  топа получают около N переходов из поиска в месяц, вы - около M (у вас переходов из поиска пока нет). Разница - это
  ~X обращений и ~Y выручки в месяц» (N = `target_traffic`, M = `t0`).
- `basis: competitors`, ориентир выше `target_traffic` (обрезан уровнем плана к 12 мес) - оценку конкурентов не печатаем
  (по локальным базам Keys.so она бывает завышена в разы): «Конкуренты из топа получают из поиска [в разы] больше
  переходов, чем вы. Даже до уровня, который реально взять за год (около N в месяц, сейчас около M), разница - это ...».
- `basis: plan` - «Столько выручки в месяц вы недополучаете против уровня, который реально взять за год: около N
  переходов из поиска в месяц, а сейчас около M (их нет)».
- Старый forecast.json (v2.0, `basis` - строка-описание) - подпись как у plan + предупреждение в лог «пересобери».
- Разрыва нет (`traffic_month` или `revenue_month` <= 0) - нейтральная выноска вместо суммы + предупреждение.
- Источник чека в допущениях: `client` - без пометки, `site` - «(по ценам на вашем сайте)», иначе - «(оценка)»;
  `ltv_factor > 1` - «с учетом повторных покупок за год ×N». Фразы про «текущих посетителей» нет.
- Сборщик сверяет `traffic_month x conversion_rate` с `leads_month` и предупреждает, если воронка не сходится.

Числительные согласуются с числом, которое видит читатель: «1 обращение / 5,2 обращения / 155 обращений», «до 571
перехода», у магазина (`model: one_step`) - «заказ / заказа / заказов» вместо «обращений».
Деньги: «1,2 млн ₽», «450 тыс ₽» (неразрывные пробелы); подписи столбиков «1,2k»; обращения до 10 - с одним знаком.
Абсолютной выручки «без работ» в документе нет (у сильных сайтов это десятки миллионов - подрывает доверие), только
прирост. Ни цен услуг, ни названий вариантов работ в docx нет - сборщик их не выводит. Подписи плана работ
(`TIMELINE` в `_services.mjs`) - без жаргона: «Вопросы-ответы и ключевые слова на страницах», «Тестовая статья (в
подарок)», «Ссылки с других сайтов», «Карточка в Яндекс Картах».

## 4. Объем: раздел - около страницы

Обложка с «Главным за одну минуту» - отдельная первая страница; 4 раздела идут потоком (п. 2.12), крупные визуальные
блоки (деньги, план работ, график, таблица прогноза) не рвутся и при нехватке места целиком переезжают на следующую
страницу. При 4-6 страницах A4 у раздела бюджет около одной страницы. Боевой прогон v2.1 (5 клиентов, рендер
LibreOffice): 6-7 страниц, почти пустых страниц нет; самый большой хвост пустоты - перед планом работ, когда он
переезжает целиком. Фикстура до v2.1 (каждый раздел с новой страницы, 6 страниц):
- «Где вы сейчас»: lead + kpi_row (4) + money_lost + subheading + issues (3 коротких) + bullets (2) - ровно страница;
- «Кто в топе»: lead + bars (4) + compare (5 строк) + table (4 строки) + короткий callout - страница;
- «Что нужно»: lead + 3 plan_item + plan_timeline (7 работ) + quick_wins (2) - ровно страница;
- «Прогноз»: lead + forecast_chart + forecast_table + forecast_drivers + абзац + conditions (2) - страница, next_step
  переходит на следующую.

Перебор (больше 3 карточек issues, длинные тексты карточек, второй список и выноска сверх этого) уводит хвост раздела на
следующую страницу почти пустым. Карточку проблемы держать в 1-2 строки текста, пункт списка - в 1 строку.

## 5. Правила для сборщика (чек-лист)

1. Только `WidthType.DXA`, `columnWidths` с суммой ровно `W`, `TableLayoutType.FIXED`.
2. Между таблицами всегда абзац (`spacer`). В `document.xml` не должно быть `</w:tbl><w:tbl>`.
3. Никаких `Textbox`, SVG, плавающих картинок и фигур, табуляций с лидером, `characterSpacing`, `allCaps`, `PERCENTAGE`.
4. Прописные - буквами; заголовки - `HeadingLevel` с `keepNext`; жесткий разрыв - только `pageBreakBefore` у первого
   H1 (не абзац с PageBreak), остальные разделы потоком; блок, который нельзя рвать, - в `keepTogether()`.
5. Шрифты только из Google Fonts или Arial/Calibri (экзотика вроде Segoe UI подменяется).
6. Все строки через `clean()`: длинное и среднее тире -> дефис, е-с-точками -> е.
7. Неизвестный блок не теряется молча: абзац / список / предупреждение в лог.
8. Визуальная проверка: `uploadFile` с `convertToGoogleFormat: true` в личный Drive -> `downloadFile` с
   `exportMimeType: application/pdf` -> `pdftoppm -png -r 70` (poppler есть в scoop) -> смотреть страницы -> `deleteItem`
   (в корзину). Быстрый локальный рендер потока страниц (без Drive) - LibreOffice из scoop:
   `~/scoop/apps/libreoffice/current/LibreOffice/program/soffice.com --headless --convert-to pdf <docx>`, затем
   `pdftoppm`; шрифт Montserrat локально не стоит (заголовки подменяются), разбивку на страницы показывает близко к
   Word. Финальная проверка - Docs. Word отображает все приемы штатно (стандартный OOXML).

## 6. Графики без браузера

В `node_modules` шаблона нет canvas, sharp, resvg, chart.js-node, vega, puppeteer (playwright без браузеров и по
ADR-035/045 не становится зависимостью клиентского клона). Поэтому графики - **таблицей** (вариант A): 0 зависимостей,
мгновенно, четкий текст, редактируется в Docs, цвет из токенов; минус - дискретность по высоте (9 уровней). Запасные
варианты, не используются: PNG своим кодом на `node:zlib` (гладко, но без текста); SVG/HTML -> PNG через установленный
Chrome `--headless=new --screenshot` (~20 с на кадр, зависимость от машины); npm-пакеты графиков (новая зависимость
в 100+ клонов).

## 7. Легаси

`seo-strategiya_content.json` без `format: "v2"` собирается старым рендером (`renderLegacy()` в том же сборщике): 6
разделов, `tariff` / `special` / `decomposition_table` (через `_forecast-money.mjs`), Arial, синяя шапка таблиц.
Изменено только: нормализация строк (тире, е-с-точками) и неизвестные блоки с `items` выводятся списком с
предупреждением. Пересборка старой стратегии дает тот же `document.xml` (проверено на `topdom_rf/strategies/001`).

## 8. Что еще можно, но не сделано

- Режим «без страниц» (pageless) в Google Docs через docx не задается - нужен Docs API
  (`documentStyle.documentFormat.documentMode`), а он выключен в Google Cloud проекте MCP gdrive-piotr.
- Поле оглавления (TOC) не проверялось: навигацию по Heading Docs показывает и так.
- Тарифные карточки в 3 колонки (`tariffCards` из дизайн-исследования: рекомендованный - голубая подложка и бейдж
  « РЕКОМЕНДУЕМ » через `TextRun.shading`) проверены, но в стратегии v2 не используются: варианты работ и цены - только
  в смете.
