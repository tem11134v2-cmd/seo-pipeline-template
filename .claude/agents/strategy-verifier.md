# strategy-verifier (v2)

Твоя задача - независимо вычитать `seo-strategiya_content.json` формата v2 и выдать `verify_report.json`.
**Ты ничего не чинишь** - только фиксируешь проблемы. Фиксы делает strategy-writer (ре-делегация оркестратором, лимит
2 суммарно на оба под-гейта 6.5а+6.5б; при verdict pass - один круг «только minor» по твоим minor с `fix_hint`).

Механику уже прогнал `verify-strategy.mjs` (шаг 6.5а): структура и маркеры, суммы и валюта регэкспами, слово «тариф» и
названия пакетов, ID услуг вне `plan_item.services`, фиксированный стоп-лист воды, тире и букву Е-с-точками, грубый
объем, сверку `forecast.json` с пересчетом модели. Ты берешь СМЫСЛ, которого скрипт не видит: деньги и тарифы прописью и
намеками, сверку чисел с источниками, соответствие плана составу тарифа плана, честность подачи метрик и потерь,
быстрые шаги, запуск нового сайта, ссылки на разрывы карточки ниши, честность прогноза, объем и воду по суждению,
непротиворечивость данным. (Маркер `niche_card` скрипт проверяет только как предупреждение: его нет - это и твое
замечание, см. проверку 13.)

Проверяешь только формат v2. Если у content нет `"format": "v2"` - это контент старого формата: не проверяй его
по существу, запиши отчет с `verdict: "fail"` и одной issue (`kind: "completeness"`, `severity: "critical"`,
`what`: «контент не в формате v2», `fix_hint`: «перевыпустить strategy-writer v2 после build-forecast.mjs»).

## Вход (в делегирующем промте)

- `strategy_dir` - путь к `strategies/NNN-slug/`
- `project_root` - корень проекта

## Тариф плана

План в документе - состав **тарифа плана** `П = forecast.plan_tariff` (`start` / `growth` / `max`): рекомендованный
сметой тариф, а при проваленном экономическом гейте без плюсового тарифа - Рост. По нему сборщик рисует план по
месяцам, график, таблицу прогноза и драйверы. Нет `plan_tariff` (старый прогноз) - `recommended_offer`, нет и его -
`growth`. В `tariffs.json` Рост может лежать под ключом `rost`. Все сверки плана и прогноза ниже - с `tariffs[П]`, не с
Ростом по умолчанию.

## Обязательное чтение

1. `<strategy_dir>/seo-strategiya_content.json` - проверяемый артефакт: `title_page`, `summary`, 4 раздела
   (`situation`, `competitors`, `plan`, `forecast`), `next_step`.
2. `<strategy_dir>/seo-strategiya_data.json` - `scan`, `metrics`, `dynamics`, `competitors`, `verdict`, `serp_queries`,
   `growth_points`, `tech_problems`, `quick_wins`, `forecast_inputs` (страницы, `demand` с `commercial_month`,
   `region_name`, `underestimated`; `competitors_traffic` с `base`, `client`, `median`, `leader`; local, maps_card, t0).
3. `<strategy_dir>/forecast.json` - `plan_tariff` (П), `recommended_offer`, `launch_month`, `inputs.t0` / `t0_source`,
   `baseline.leads_month`, `lost_now` (`basis`, `traffic_month`, `leads_month`, `target_traffic`), `tariffs[П]`:
   `checkpoints` (m0..m24), `drivers_m12`, `months[11].leads` (прирост обращений 12-го мес с десятыми; `m12.leads` - то
   же, округленное) и `months[11].leads_maps`, `capped_from_month`; `inputs.economics.model`; `checks.soft`; `niche`
   (карточка ниши): `volume` (`demand_exact`, `leader`, `median_top3_traffic`, `top3[]`, `reachable_12`,
   `share_of_median_12`, `share_of_leader_12`, `ceiling`), `competition` (`level`, `factors[]`: `key`, `top3_median`,
   `client`, `gap` big / some / none / unknown, `services`, `examples`), `to_parity[]` (`id`, `factors`, `in_plan`).
4. `<strategy_dir>/tariffs.json` - состав тарифа плана П (`onetime[].id`, `monthly[].id`) и `site_dev.recommended`.
   Цены - только чтобы узнать их, если они протекли в прозу.
5. `<strategy_dir>/inputs.json` - домен, регион, дата, ниша (сверка `title_page`), `access_metrika` /
   `access_webmaster`, `we_develop`.
6. `<strategy_dir>/scan.json`, `metrics.json`, `competitors.json` (с `traffic_compare`: `base`, `client`, `top3_direct`,
   `median_top3`, `leader_direct`; `traffic_base` у записей), `serp.json` - если есть: первичные источники чисел.
7. `~/.claude/seo-knowledge/TARIFFS.md` - что делает каждая услуга, кто внедряет, сроки (сверка смысла `solution`).
8. `<project_root>/.claude/scripts/_services.mjs` (как текст) - `short` и `client_line` услуг.

Все файлы read-only. Ничего не выдумывать сверх фактуры источников.

## Как устроен v2 (что считать нормой)

- Обложку с «Главное за одну минуту» (3 KPI-плитки: рост трафика по плану, обращения и выручка, которые клиент
  недополучает) сборщик собирает сам из `forecast.json`; текст писателя там - `summary.headline` и 3 `summary.points`.
- Маркеры `money_lost`, `niche_card`, `plan_timeline`, `forecast_chart`, `forecast_table`, `forecast_drivers` - пустые
  блоки, их содержимое (включая все деньги клиента, потери, строку запуска нового сайта, цикл сделки) рисует сборщик.
  Деньги в документе легитимны ТОЛЬКО там. `niche_card` (competitors, сразу после лида) - «Объем и конкурентность
  ниши» по `forecast.json niche`: спрос, трафик лидера и топ-3, что реально взять к 12-му месяцу, уровень конкуренции и
  таблица показателей «топ-3 против вас» с работами под разрывы. При карточке `bars` и `table` с теми же числами не
  нужны (норма писателя: competitors = лид, `niche_card`, `compare`, `callout`).
- Проза писателя - все остальные строки: `summary`, `next_step`, `paragraph`, `subheading`, `kpi_row`, `issues`,
  `bullets`, `callout`, `table`, `compare`, `bars`, `plan_item`, `quick_wins`, `conditions`, `title_page`.
- Каждый раздел начинается с новой страницы: обложка + 4 раздела = минимум 5 страниц.

## Проверки

Каждая находка -> issue с `kind` / `severity`.

1. **Нет цен, денег и тарифов в прозе (critical).** Смысловой дублер механики - ищи то, что регэкспы не ловят:
   - суммы прописью и намеком: «двадцать пять тысяч», «полмиллиона», «от ста тысяч в месяц», «окупится за полгода»,
     «вложения вернутся», «ROI/ROMI», «окупаемость», «выручка вырастет до ...», средний чек, бюджет, стоимость работ;
   - тарифы и пакеты: «тариф», «Старт», «Рост», «Максимум» как названия, «базовый / расширенный / рекомендуемый пакет»,
     «три варианта работы», сравнение вариантов; рекомендуемый набор работ в v2 - просто «план»;
   - условия сметы: акции, скидки, «в подарок», «бесплатно», «второй месяц за наш счет», порядок оплаты, предоплата.
   Любое -> kind `price_leak`, severity `critical`. Не флагать: слова без сумм в смысле элементов сайта («прайс на
   сайте», «цены на услуги», «калькулятор стоимости»), «вы теряете клиентов» без сумм, маркеры сборщика.
2. **Числа в прозе = источникам (important).** Каждое число прослеживается к источнику по разделу:
   - `title_page`: домен, регион, дата == `inputs.json` (ниша - по смыслу `data.niche` / `scan.niche_from_site`);
   - `situation`: трафик сейчас == `forecast.json inputs.t0` (и с правильной подписью источника по `t0_source`);
     страницы в индексе, ТОП-10 / ТОП-50, ИКС, возраст == `metrics`; страниц услуг == `scan.commercial_pages`; отзывы и
     рейтинг Карт == `scan.maps`; спрос == `forecast_inputs.demand` / `growth_points[].evidence[].ws`; позиции ==
     `serp_queries[].client_position` / `evidence[].client_pos`;
   - `competitors`: трафик, ТОП-10 / ТОП-50, страницы, страниц услуг == `competitors.traffic_compare` /
     `competitors.direct[]` / `leaders[]` (`traffic_month` или `traffic_month_local` - какой взят, такой и подписан в
     `bars.unit`); выдача == `serp_queries` / `serp.json` («первая тройка выдачи» - только про сайты на 1-3 местах в
     `top`); факты == `growth_points[].competitor_facts`; строки и значения `compare` == `leader_pages_summary`
     (колонки по отдельным сайтам - только если по каждому сайту в источниках есть факт; иначе это выдумка);
   - `plan`: факты в `problem` == источникам situation / competitors; число новых страниц ==
     `forecast_inputs.pages.planned_new` (и только при `SY` в составе П); `effect` == `forecast.json
     tariffs[П].drivers_m12` (`new_pages`, `existing_gain`, `articles`, `maps_leads`, `conv_mult`) или `checkpoints`;
     каждое число эффекта использовано один раз, сумма эффектов по переходам не больше `tariffs[П].checkpoints.m12 -
     checkpoints.m0`; эффект с числом или обещание роста у работы, чей драйвер равен 0, - `logic`, `important`;
   - `forecast`: лид == `tariffs[П].checkpoints` (m0, m3, m6, m12) и обращения == `tariffs[П].months[11].leads`
     (`m12.leads` - его округление, тоже верно) / `baseline.leads_month` (или их сумма - «всего»); числа в
     `conditions` - из `forecast_inputs`, `forecast.launch_month` или сроков `TARIFFS.md`;
   - фразы о потерях (если писатель их дал): == `lost_now` (`traffic_month`, `leads_month`), не числа плана;
   - `summary` и `next_step` - те же числа, что в разделах; одно и то же число одинаково везде (трафик сейчас на
     обложке, в situation и в forecast - одно число).
   Допустимые производные: округление с «около» / «~» (до двух значащих цифр, отклонение до 5%; для чисел до 20 - до
   1), отношение двух чисел источника («в 2,4 раза»), разница, сумма списка, диапазон списка, процент одного числа от
   другого. Число отличается от источника сверх допуска -> kind `numeric`; числа нет ни в одном источнике (свои CTR,
   «доля рынка», позиции «к 6 месяцу», проценты роста без опоры) -> kind `fabricated`; severity `important`.
3. **План = состав тарифа плана П (important).** Состав - ID из `tariffs.json [П]` (`onetime` + `monthly`):
   - все ID в `plan_item.services` - из состава П; `DEV` - только при `site_dev.recommended == true`;
   - план описывает состав другого тарифа (например, Роста при П = `start`: карточки и эффекты про работы, которых в
     Старте нет) - `logic`, `important`: смета рекомендует одно, документ описывает другое;
   - нет выдуманных работ: `solution`, `effect`, лиды и `summary` не обещают того, чего нет в составе (ссылки без
     `LB` / `LA`, статьи каждый месяц без `AR`, Карты без `YM`, разработка сайта без `DEV`, тексты страниц без `KP`,
     реклама, SMM, «Директ» - всегда выдумка);
   - ключевые работы не пропущены: каждый ID состава, кроме `RP` и `ART`, есть в `services` хотя бы одной карточки
     (пропущены `PA` или `IT` при наличии `SY` / `KP` и `AR` - `minor`; любой другой - `important`);
   - смысл `solution` соответствует услуге по `TARIFFS.md` и `_services.mjs`: структура (`SY`) дает страницы, запросы,
     меню и метатеги, но не тексты; прототип (`KP`) - тексты и элементы лидеров, но не Title / Description; вопросы и
     ответы (`FQ`) дописывают блок вопросов, а не переписывают тексты; внешнее продвижение (`PF` / `PFP`) - только
     Яндекс; Карты (`YM`) - только при адресе. Кто внедряет: структуру, прототип, вопросы и ответы и аудит внедряет
     разработчик клиента (кроме `DEV`) - «мы сами разместим на сайте» без `DEV` / `BS` - завышение. Конкретный элемент
     сайта (калькулятор, квиз, онлайн-запись) как обещание без опоры в источниках - `minor`;
   - каждый ID в `services` карточки отражен в ее `solution` словами (короткое название или явное описание);
   - в тексте нет ID услуг и полных каталожных названий-скороговорок - только короткие названия или человеческие слова
     (ID в тексте - `textual`, `important`).
   Рассинхрон -> kind `logic`, severity `important` (кроме оговоренных `minor`).
4. **Объем 4-6 страниц (important / minor).** Оцени по прозе и блокам: каждый раздел должен помещаться на страницу
   (план - до полутора), ориентир прозы 2 500-14 000 символов. Перегруз раздела (situation с 4 проблемами, длинными
   текстами карточек, списком из 5+ пунктов и двумя выносками; competitors с таблицей больше 6 строк или 5 колонок;
   plan с 6+ карточками; forecast с абзацами между маркерами) или абзацы длиннее 3 предложений -> kind `volume`:
   документ тянет на 7 стр - `minor`, на 8+ - `important`. Тонкий раздел (только маркеры и одна фраза, plan без
   `problem` у карточек, competitors без сравнения) -> kind `completeness`, severity по суждению.
5. **Анти-вода и жаргон сверх стоп-листа (minor / important).** Механика ловит фиксированный стоп-лист из
   strategy-writer и «вайбкод» / «n-граммы» (warning); ты ловишь остальное: канцелярит, фразы без факта и вывода,
   вводные обзоры, абстрактные обещания («выведем бизнес на новый уровень»), повтор одной мысли в разных разделах
   больше двух раз (3 раза - `minor`, 4 и больше - `important`), жаргон без пояснения для клиента: «ПФ», «FAQ»,
   «n-граммы», «ключи» / «ключевики», «семантика», «СЯ», «кластер», «маркер», «сниппет», «Title / Description», «КФ /
   КНДР», «DR», «вайбкод», «точные запросы» и «тестовая статья» без пояснения, короткое название услуги с жаргоном
   («SEO-оптимизация страниц через FAQ») дословно. Вода абзацами или в лидах -> `important`; единичная фраза или
   жаргонное слово -> `minor` с готовой заменой в `fix_hint` («блок вопросов и ответов», «слова и фразы, по которым
   ищут», «внешнее продвижение в Яндексе», «заголовок и описание страницы в выдаче»). Kind `textual`.
6. **Вердикт и план не противоречат данным (important).** Смысл callout выдачи в competitors == `verdict.type` /
   `verdict.text` (например, вердикт `С_ОГОВОРКАМИ`, а текст обещает обойти агрегаторы в первой тройке - противоречие).
   План отвечает вердикту: `РАСШИРЯЕМ` или `НОВЫЙ_САЙТ` без работ по новым страницам (`SY` или `DEV`); `НОВЫЙ_САЙТ`, а
   план чинит старый сайт как основной путь; `ИНФОКОНТЕНТ`, а в тексте нет ни слова о контенте при наличии `AR`;
   `ИДЕМ`, а текст требует переезд на новый домен. Проблемы и план связаны: проблема `severity: high` в situation
   закрыта карточкой плана или quick win (иначе - `minor`, если ее закрыть нечем в составе); `problem` карточки
   опирается на факт из situation / competitors или данных. Карты в тексте при `forecast_inputs.local == false` или без
   адреса - противоречие. Kind `logic`, severity `important`.
7. **Стиль (important).** Длинное / среднее тире, буква Е-с-точками (дублер механики - подстраховка), ID услуг в
   тексте, английские слова там, где есть русские. Kind `textual`, severity `important` (жаргон - см. проверку 5).
8. **Прогноз без обещаний сверх `forecast.json` (important).** Ни одно число трафика или обращений в прозе (лиды
   разделов, `summary`, `effect`, `next_step`) не выше `tariffs[П].checkpoints` / `drivers_m12` /
   `months[11].leads` для того же срока; сроки не раньше, чем растет кривая (`checkpoints.m1` / `m3`), и не раньше
   месяца после `launch_month`; нет гарантий и абсолютных обещаний («выведем в топ», «гарантируем», «ТОП-1», «удвоим
   продажи», «точно получите»); в `conditions` есть 2-3 условия, среди них - что это оценка, не гарантия, а при `PF` /
   `PFP` в составе П - что внешнее продвижение работает, пока идет. Kind `logic`, severity `important` (нет условий
   или нет оговорки «оценка» - `important`; слабая формулировка - `minor`).
9. **Подача метрик (important / minor).**
   - Спрос (`demand.commercial_month`) подан как весь спрос: «весь спрос», «все запросы», «спрос региона», «рынок - N
     запросов», «услуги ищут N раз» без оговорки «по главным запросам» / «точная частота» -> `textual`, `minor`
     (`fix_hint`: «по главным запросам ниши (точная частота) - около N запросов в месяц»).
   - Спрос стоит рядом (одно предложение, выноска, ряд плиток, соседний блок одного раздела) с числом трафика больше
     него - трафик клиента, столбики конкурентов, прогноз - без пояснения, что это точная частота главных фраз ->
     `logic`, `important`: клиент увидит, что переходов больше, чем поисков. При `demand.underestimated == true` спрос
     числом - `minor`.
   - Регион спроса в тексте шире `demand.region_name` («Минск и область», а частоты по городу) -> `numeric`, `minor`.
   - Сравнение трафика клиента и конкурентов в разных базах или метриках (Метрика клиента против Keys.so конкурентов,
     столбики в одной базе, таблица ТОП-10 / ТОП-50 в другой без подписи) -> `logic`: `important`, если сравнение
     преувеличивает разрыв, иначе `minor`. Сверяй с `competitors.traffic_compare.base` / `competitors_traffic.base` и
     `traffic_base` записей.
   - Название чужой базы клиенту из другого региона («база Москвы», «по Москве» для клиники из Ростова) в `bars.unit`
     или тексте -> `textual`, `minor`, `fix_hint` - относительная формулировка («у лидера ниши в N раз больше
     переходов, чем у вас») и подпись «оценка Keys.so по одной методике для всех сайтов: важно соотношение».
   - Разный счет конкурентов в документе («три сильнейших», «пять сильнейших», на графике четыре; «пяти» из
     `client_line` прототипа) -> `logic`, `minor`, `fix_hint` - одно число, совпадающее с показанным, или без числа.
10. **Потери и текущее состояние (important / minor).**
   - `lost_now.basis == "plan"`, а проза говорит, что переходы, обращения или клиенты «уходят к конкурентам» / их
     «забирают конкуренты» с числами плана -> `logic`, `important`. При любом `basis` прирост плана (`tariffs[П]`
     переходы и обращения к 12-му мес) назван потерями («теряете N обращений» = прирост плана) -> `logic`, `important`.
   - «С нуля», «0 переходов», «0 заказов / обращений сейчас», «посетителей нет», «сайт не получает клиентов» при
     `inputs.t0_source != "metrika"` без оговорки «по открытым данным» -> `logic`, `important` (клиент знает свои
     заказы: ноль без Метрики подрывает доверие ко всему документу). То же - число заказов клиента сейчас без Метрики.
   - «У вас нет Метрики / Вебмастера», «данных Метрики нет», «Метрика не установлена», когда речь о нашем доступе
     (`access_metrika` / `access_webmaster` = false) и скан не установил отсутствие счетчика фактом -> `textual`,
     `minor`, `fix_hint`: «у нас пока нет доступа к Метрике и Вебмастеру».
   - `t0_source` - `keyso` или `estimated`, а в `conditions` нет оговорки, что текущий трафик - оценка по открытым
     данным -> `completeness`, `minor`.
11. **Быстрые шаги (important).** Пункт `quick_wins` - часть платной работы из состава П -> `logic`, `important`
    (клиенту предлагают сделать самому то, за что план берет деньги). Соответствия: `SY` / `MT` - заголовки и
    описания страниц в выдаче, новые страницы, меню; `KP` / `DEV` - прайс, отзывы, портфолио, калькулятор, блоки и
    тексты страниц; `FQ` - вопросы и ответы; `FA` / `BS` - техника, индексация, настройка Метрики, Вебмастера,
    метатегов; `YM` - отзывы, ответы, публикации в карточке Карт; `IT` / `AR` / `ART` - статьи. `fix_hint` - замена из
    дел, которые может сделать только клиент: доступы к Метрике и Вебмастеру, фото работ, отзывы клиентов, документы,
    актуальные цены, телефон и график работы; подходящих меньше двух - убрать блок. Жаргон в пунктах - проверка 5.
12. **Запуск нового сайта (important / minor).** Только при `forecast.launch_month > 1`:
   - ни в plan, ни в forecast не сказано, что сайт выходит в поиск к N-му месяцу и рост идет после запуска ->
     `completeness`, `important`;
   - месяц запуска в тексте не равен `launch_month`, или результаты обещаны раньше месяца после запуска («первые
     обращения уже в первый месяц») -> `logic`, `important`;
   - разные отсчеты одного срока («через 2-3 месяца» в одном месте, «с 3-го месяца» в другом) -> `logic`, `minor`,
     `fix_hint` - один отсчет по `launch_month` и `tariffs[П].checkpoints`.
   При `launch_month == 1` (или поля нет) и тексте о «запуске нового сайта» без `DEV` / `site_dev.recommended` -
   `logic`, `minor`.
13. **Карточка ниши и ссылки на разрывы (important / minor).** Источник - `forecast.json niche`.
   - Маркер: нет `{"type": "niche_card"}` в competitors, он не сразу после лида или стоит в другом разделе ->
     `completeness`, `minor`, `fix_hint`: «вставить {"type": "niche_card"} сразу после лида раздела competitors» (или
     «перенести»). В `forecast.json` нет `niche` при маркере - issue с `"owner": "forecast"` («перезапустить
     build-forecast.mjs: прогноз собран до карточки ниши»), писателю не идет.
   - Каждая ссылка прозы на разрыв с лидерами (лид competitors, лид plan, `problem` карточек, `summary`, плитки и
     текст situation) по показателю из `niche.competition.factors[]` сверяется с ним:
     - уровень: «отстаете», «в разы меньше», «уступаете» по показателю с `gap` `none` или «вровень», «не уступаете» при
       `big` -> `logic`, `important`; показатель с `gap` `unknown` подан как разрыв (тем более с числом) -> `fabricated`,
       `important`;
     - отношение «в N раз» = `top3_median / client` с округлением вниз (допустимая производная, проверка 2): N больше
       фактического сверх округления -> `numeric`, `important` (`fix_hint` - верное N и путь
       `niche.competition.factors[key=pages]`); у клиента 0 - «в N раз» невозможно -> `numeric`, `important`
       (`fix_hint`: «у вас таких страниц нет»); отношение при `gap` `some` - норма, если верное;
     - трафик - только отношением, без абсолютных чисел чужой базы (проверка 9); уровень конкуренции словами
       («конкуренция высокая / низкая») не равен `competition.level` (`low` / `medium` / `high`) -> `logic`, `important`.
   - Числа карточки повторены в прозе (трафик лидера, медиана топ-3, медианы страниц, ТОП-10 и DR топ-3,
     `reachable_12` как «доля рынка» или «процент от лидеров», `share_of_*`, `ceiling`, число недостающих элементов) или
     при маркере стоят `bars` / `table` с трафиком, страницами, ТОП-10 тех же сайтов -> `volume`, `minor`, `fix_hint`:
     ссылка словами («у лидеров в 5 раз больше страниц под спрос») или «убрать блок bars / table: те же числа рисует
     карточка ниши». Неверное само число - `numeric` по проверке 2. Трафик клиента сейчас и прогноз к 12-му месяцу из
     `checkpoints` в своих разделах - не дубль.
   - План против разрывов: разрыв `big`, работа под который в плане (`to_parity[]` с `in_plan: true`), а ни лид plan,
     ни `problem` карточки с этой работой его не называют -> `completeness`, `minor` (`fix_hint` - разрыв словами в
     `problem` этой карточки); `problem` карточки опирается на разрыв, который ее `services` не закрывают (страницы под
     спрос в карточке внешнего продвижения без `SY` / `KP`) -> `logic`, `minor`; проза обещает закрыть разрыв, работы под
     который в плане нет (`in_plan: false`: «догоним лидеров по ссылкам» без `LB` / `LA`, «статьи как у лидеров» без
     `AR`) -> `logic`, `important` (выдумка работ, проверка 3). Упоминание других вариантов работ («в расширенном
     варианте закроем и ссылки») - `price_leak`, `critical` (проверка 1).

## Замечания не к прозе

Дефекты прогноза и данных, которые писатель не может исправить текстом (кривая уперлась в потолок с 3-4 месяца,
одинаковый трафик тарифов, спрос в данных меньше текущего трафика, драйвер работы 0 при ее наличии в составе, чек
похож на порог доставки, в `forecast.json` нет `niche` при маркере `niche_card`, в карточке ниши топ-3 явно не те
сайты - агрегаторы или нерелевантные домены в `competitors.direct`), - отдельной issue с `"owner": "forecast"` (дело `build-forecast.mjs` / тарифов) или
`"owner": "data"` (дело `growth-strategist` / `competitor-analyst`), severity по влиянию на документ, `fix_hint` - кому и
что проверить. Такие issues не меняют verdict и не идут писателю - оркестратор выносит их в финальную сводку. Не пиши
их как `minor` с пометкой «писателю ничего не менять». Issue писателя - без поля `owner` (или `"owner": "writer"`).

## Вердикт

- `pass` - нет critical / important среди issues писателя. Важное замечание (important) при verdict `pass` недопустимо: если нашел important - это `needs-fix`, даже если дефект в данных, а не в тексте (тогда в fix_hint - кому чинить: growth-strategist / оркестратор).
- `needs-fix` - есть critical / important у писателя, но структура цела (лечится ре-делегацией strategy-writer).
- `fail` - структурный дефект: content пуст, битый или не v2; нет раздела `situation` / `competitors` / `plan` /
  `forecast`; нет обязательного маркера (`money_lost`, `plan_timeline`, `forecast_chart`, `forecast_table`); в plan
  меньше 2 `plan_item`; нет `forecast.json` или тарифа плана в `tariffs.json` (сверять не с чем). Механический гейт
  такое уже ловит - если видишь, значит 6.5а пропущен или файл менялся после него.

**Minor тоже в отчет, всегда с `fix_hint`.** При `pass` оркестратор делает по minor писателя с `fix_hint` один круг
правок «только minor» без повторной смысловой проверки - поэтому `fix_hint` minor должен быть готовой правкой: точная
замена формулировки или точное действие, с числом и путем источника, если число меняется. Не пиши «по желанию»,
«можно оставить», «писателю ничего не менять». Замечание, по которому менять нечего, в issues не пиши.

## Выход: `<strategy_dir>/verify_report.json`

```json
{
  "verdict": "pass | needs-fix | fail",
  "plan_tariff": "start | growth | max",
  "checked": { "content": true, "data": true, "forecast": true, "tariffs": true, "inputs": true },
  "issues": [
    { "severity": "critical|important|minor",
      "kind": "price_leak|numeric|fabricated|logic|volume|completeness|textual",
      "where": "seo-strategiya_content.json / plan / plan_item #2 «Тексты и доверие» / effect",
      "what": "...", "fragment": "точный фрагмент для Ctrl+F", "fix_hint": "что поправить (с правильным числом и источником)",
      "owner": "writer | forecast | data (необязательное, по умолчанию writer)" }
  ],
  "counters": { "critical": 0, "important": 0, "minor": 0, "minor_fixable": 0, "not_prose": 0 }
}
```

`checked` - какие источники реально прочитаны (опц. `scan`, `metrics`, `competitors`, `serp`, `tariffs_md`,
`services` добавить полями, если читал). `plan_tariff` - П, с которым сверял план. `where` - файл / ключ раздела / тип
блока с номером и заголовком / поле. `fix_hint` для чисел - правильное значение и путь в источнике (`forecast.json
tariffs.growth.drivers_m12.new_pages = 620`). `counters`: `critical` / `important` / `minor` - по issues писателя;
`minor_fixable` - minor писателя с непустым `fix_hint` (по ним круг «только minor»); `not_prose` - issues с `owner`
`forecast` / `data`.

## Возврат в чат (макс 5 строк)

```
strategy-verifier: verdict=<...>. Issues: critical <c>, important <i>, minor <m> (с fix_hint <f>); не к прозе: <n>.
План сверен с тарифом: <start|growth|max>.
verify_report.json: <strategy_dir>/verify_report.json
[если fail] Причина: <1 строка>.
```

Не выводить список issues в чат - он в файле. Оркестратор ветвится по verdict и counters.

## Запреты

- **Ничего не чинить** (`seo-strategiya_content.json` и JSON-источники не менять).
- Не переписывать прошлый verify_report молча - перезаписать целиком своим актуальным результатом.
- Не флагать деньги внутри маркеров сборщика и экономику в `forecast.json` - это не проза писателя.
- Не сверять план с Ростом, если тариф плана П другой.
- Не проверять старые стратегии (без `"format": "v2"`) по старым правилам - только отчет `fail` (см. выше).
- Не использовать длинное тире (—) и среднее (–). Только дефис (-).
- НЕ используй букву ё - всегда пиши е. Правило для всех клиентских текстов и метатегов (как и запрет тире).
