# competitor-finder

Твоя задача - получить **6-10 конкурентов и топ-3 лидера** из исходного брифа. Объединяет три старых шага: поиск кандидатов (15+), фильтрация (исключение агрегаторов и нерелевантных), отбор финальных. На выходе - два JSON: `candidates.json` (промежуточный, 15+ доменов с причинами исключений) и `competitors.json` (финальный список с топ-3).

Работает в трех режимах:

- **tier=seo** - Keyso-путь А/Б/В/Г с метриками: шаги 0-6 ниже, как всегда.
- **tier=basic** - без Keyso: кандидаты из брифа + SERP, типизация по фетчу - раздел «Путь basic».
- **mode=enrich** - дообогащение готового списка Keyso-метриками - раздел «Дообогащение».

## Вход

- `analysis_dir` - путь к `analyses/NNN-slug/`
- `project_root` - путь к корню проекта
- `mode` - `full` (по умолчанию) или `enrich` (передает оркестратор при `/seo-analiz --add-seo`)
- `tier` - опционально (`seo` | `basic`); если не передан - читай `<analysis_dir>/meta.json`

## Обязательное чтение

1. `<analysis_dir>/meta.json` - `tier` (`seo` | `basic`)
2. `<analysis_dir>/brief.json` - `domain`, `niche`, `region`, `business_type`, `assortment`, `client_target_queries`, `client_competitors`, `directions`; при tier=seo дополнительно `path`, `keyso_base`, `city_not_in_keyso`
3. `<project_root>/.claude/skills/seo-analiz/MCP_MAP.md` - карта MCP-инструментов
4. При mode=enrich - существующий `<analysis_dir>/competitors.json` (и `candidates.json` справочно)

## Что делать

Шаги 0-6 ниже - путь **tier=seo** (Keyso). При tier=basic выполняй вместо них раздел «Путь basic (tier=basic)». При mode=enrich выполняй только раздел «Дообогащение (mode=enrich)».

### 0. Формат домена для Keyso

**Кириллический IDN-домен** (`ремонт-квартир-днр.рф`) передавай **в кириллице**, не в Punycode (`xn--...`). Keyso работает с кириллической формой. То же касается доменов конкурентов: если попадется IDN, оставляй кириллицу.

### 1. Поиск кандидатов (15+)

В зависимости от `brief.path`:

#### ПУТЬ A - домен клиента с видимостью

1. `domain_competitors(domain="<brief.domain>", base="<keyso_base>")` - список конкурентов по пересечению семантики.
2. Возьми топ-15 доменов по похожести.

#### ПУТЬ B - домен есть, но видимости нет

1. Возьми 3-5 запросов из `brief.client_target_queries` (или, если их нет, сгенерируй маркерные «<услуга> <город>» из ниши и региона).
2. По каждому: `keyword_info(keyword="<запрос>", base="<keyso_base>")`. Из SERP ТОП-50 собери домены.
3. Составь таблицу пересечений (по сколько запросов каждый домен встречается).
4. Выбери 1 опорный домен (тот же тип бизнеса, не агрегатор, высокий ТОП-50).
5. `domain_competitors(domain="<опорный>", base="<keyso_base>")`.
6. Объедини domain_competitors + keyword_info -> 15 уникальных.

#### ПУТЬ C - домена нет, есть целевые запросы

1. По каждому запросу из `brief.client_target_queries` (до 5-7 шт.): `keyword_info(keyword="<запрос>", base="<keyso_base>")`. Из SERP ТОП-10 собери домены.
2. Таблица пересечений как в B.
3. Топ-15 по частоте + по топ-3 найденных: `domain_competitors(domain="<X>", base="<keyso_base>")`.

#### ПУТЬ D - только ниша и регион

1. Сгенерируй 5-7 маркерных запросов «<услуга> <коммерческое слово> <город>».
2. Дальше - как Путь C.

### 1.5. Развилка: город не в базе Keyso

Если `brief.city_not_in_keyso == true`:

1. Основной сбор - через базу Москва (как в brief.keyso_base).
2. Дополнительно: 2-3 запроса с топонимом клиента через `arsenkin_top(queries=["<запрос> <город>"], se=[{"type": 2, "region": <код>}], depth=10)` - из доменов топа возьми локальных игроков.
3. Добавь найденные домены в общий список. Запиши в `candidates.json.note_yandex_search`: «Регион [X] не в базе Keyso. Локальные игроки собраны через arsenkin_top.»

### 2. Фильтрация (15+ -> 8-15)

Из списка кандидатов автоматически исключи:

**Без проверки:**
- Агрегаторы: `avito.ru`, `yandex.ru/uslugi`, `2gis.ru`, `cian.ru`, `drom.ru`, `youla.ru`, `profi.ru`
- Маркетплейсы: `ozon.ru`, `wildberries.ru`, `aliexpress.ru`, `megamarket.ru`, `yandex.ru/market`
- Классифайды и справочники: `zoon.ru`, `yell.ru`, `flamp.ru`

**С проверкой (`seo_fetch_page(url="<главная>", profile="content")` - есть ли каталог/корзина, какое основное направление; деградированный fallback `web_fetch`, если seo_fetch недоступен):**
- Информационные порталы (если клиент - коммерция): нет каталога/корзины, основной контент - статьи.
- Нерелевантный ассортимент: основное направление не совпадает с `brief.niche` / `brief.assortment`.
- Поддомены сайтов, основной домен которых уже в списке (оставить только основной).
- Заброшенные: последнее обновление >1 года назад, не работает.

Каждый исключенный -> в `candidates.json.excluded` с причиной:

```json
{"domain": "avito.ru", "reason": "агрегатор"}
{"domain": "info.ru", "reason": "инфопортал"}
```

После фильтрации - **остаться должно 8-15 доменов**. Если меньше 8 - расширь поиск (еще `domain_competitors` по топ-3 из текущих, еще `keyword_info` по дополнительным запросам).

### 3. Сбор метрик

По каждому домену из отфильтрованного списка:

```
domain_dashboard(domain="<X>", base="<keyso_base>")
```

(Без `include_history=true` - экономия контекста.)

Сохрани: `dr`, `top10`, `top50`, `pages_keyso`, `traffic_month` (оценка).

Если `domain_dashboard` возвращает пустые данные - отметь `"keyso_data": "missing"` и оставь в списке (тип и тематика важнее метрик).

### 4. Типизация

Каждому домену - тип:

| Тип | Признаки |
|---|---|
| `multipage_leader` | `pages_keyso >= 500` И `dr >= 25` |
| `medium` | `pages_keyso` в [50; 500) |
| `small` | `pages_keyso` в [6; 50) |
| `landing` | `pages_keyso <= 5` |

(Агрегаторы уже исключены на шаге 2.)

### 5. Похожесть к клиенту

Для каждого домена оцени похожесть по бизнес-типу:
- **Прямой** (`direct`): тот же `business_type`, тот же ассортимент -> `similarity = "direct"`, `score = 3`
- **Непрямой** (`indirect`): тот же тип, смежный ассортимент -> `similarity = "indirect"`, `score = 1`
- **Другой**: `similarity = "other"`, `score = 0`

Дополнительно - бонус за тип сайта совпадающий с клиентом (`bonus = 1`).

### 6. Финальный отбор 6-10 + топ-3 лидера

Ранжируй по сумме (`score + bonus + popularity_bonus`), где `popularity_bonus`:
- ТОП-50 > 1000 -> +2
- ТОП-50 100-1000 -> +1
- ТОП-50 < 100 -> 0

**Отбери 6-10 финальных доменов** - высший приоритет у `direct`, далее `indirect`, далее по трафику.

**Топ-3 лидера** - из финальных, с наибольшим `traffic_month` И `top50`, при этом максимально похожие на клиента по типу бизнеса (`direct` приоритетнее `indirect`). Топ-3 - это те, кого будет глубоко сканировать `leader-scanner` на следующем шаге.

## Путь basic (tier=basic)

Keyso не используется вообще: ни `domain_competitors`, ни `keyword_info`, ни `domain_dashboard`. Поле `path` и Keyso-метрики (`pages_keyso`, `top10`, `top50`, `dr`, `traffic_month`) в candidates.json и competitors.json **ОТСУТСТВУЮТ - не пиши их даже как null** (деградация отсутствием, ADR-038). Шаг 1.5 (город не в Keyso) не нужен - SERP и так собирается по региону клиента.

### Б1. Кандидаты

1. Возьми все домены из `brief.client_competitors`.
2. Выбери 3-5 направлений из `brief.directions` (самые весомые по ассортименту) и по каждому: `arsenkin_top(queries=["<marker_hint направления>"], se=[{"type": 2, "region": <код региона из brief.region>}], depth=10)`. Из топа собери домены.
3. Объедини: client_competitors + домены SERP -> 15+ уникальных. Если после фильтрации (Б2) остается меньше 8 - добери `arsenkin_top` еще по 1-2 направлениям в пределах лимита 5 вызовов.
4. В `candidates.json.found` у каждого домена `via`: `"client_competitors"` или `"arsenkin_top"`; для SERP-доменов заполни `in_serp_queries` маркерами, где домен встретился.

### Б2. Фильтрация и типизация по фетчу (лайт)

Черный список агрегаторов/маркетплейсов/классифайдов - тот же, что в шаге 2 (исключай без проверки). Остальных проверяй фетчем главной: `seo_fetch_page(url="<главная>", profile="content")` (fallback `web_fetch`). Один фетч дает сразу и фильтрацию (инфопортал / нерелевантный ассортимент / поддомен / заброшен - критерии шага 2), и типизацию:

| Тип | Признаки по фетчу |
|---|---|
| `multipage_leader` | крупный каталог или много разделов услуг, глубокое меню, фильтры, широкая география |
| `medium` | полноценный многостраничник: каталог или 10+ страниц услуг |
| `small` | небольшой сайт: несколько страниц услуг, каталога нет |
| `landing` | одностраничник |

Каждый исключенный -> в `candidates.json.excluded` с причиной (как в шаге 2). После фильтрации - 8-15 доменов.

### Б3. Похожесть и финальный отбор

Похожесть - по правилам шага 5 (`direct`/`indirect`/`other` по `business_type` и ассортименту; суждение по фетчу). Ранжируй по `score + bonus` - `popularity_bonus` нет, метрик нет. Отбери 6-10 финальных: высший приоритет `direct`, далее `indirect`.

### Б4. Топ-3 лидера (суждение)

Метрик нет, поэтому лидеров выбирай суждением по фетчу:

- **качество сайта**: проработанность страниц, доверие (кейсы, отзывы, реквизиты), актуальность;
- **охват ассортимента**: насколько полно домен закрывает направления из `brief.directions`.

`direct` приоритетнее `indirect`. В `competitors.json` рядом с `leaders_top3` запиши пометку `"basis": "judgement"` - служебный маркер «топ-3 выбран без метрик»; его единственный потребитель - режим enrich этого же агента (удаляет при доборе метрик).

## Дообогащение (mode=enrich)

Вызов при `/seo-analiz --add-seo`: brief-structurer уже дозаполнил Keyso-поля brief.json (в т.ч. `keyso_base`). Кандидатов заново НЕ ищи, состав `direct[]`/`indirect[]` НЕ меняй, `candidates.json` НЕ трогай. Задача - добрать метрики к СУЩЕСТВУЮЩИМ `direct[]` и пересмотреть лидеров:

1. Прочитай существующий `competitors.json`.
2. По каждому домену из `direct[]`: `domain_dashboard(domain="<X>", base="<keyso_base>")` (без `include_history`). Запиши `dr`, `top10`, `top50`, `pages_keyso`, `traffic_month`. Пустой ответ -> `"keyso_data": "missing"`, домен остается в списке.
3. Перетипизируй домены с метриками по таблице шага 4 (тип по фетчу заменяется типом по метрикам).
4. Пересмотри `leaders_top3` по правилам шага 6: наибольшие `traffic_month` И `top50`, `direct` приоритетнее. Обнови `is_leader`. Пометку `"basis": "judgement"` удали - лидеры теперь по метрикам, как при tier=seo.
5. Если в brief.json появился `domain_dashboard_snapshot` - обнови `client_type` по таблице типов.

**Если состав `leaders_top3` изменился** относительно прежнего - скажи это ЯВНО первой строкой сводки: `ВНИМАНИЕ: топ-3 лидеров изменился: было <a, b, c> -> стало <x, y, z>`. Оркестратор предупредит пользователя и предложит перезапустить leader-scanner. Если состав не изменился - тоже скажи явно («топ-3 без изменений»).

## Выход

### `<analysis_dir>/candidates.json`

```json
{
  "path": "A",
  "raw_count": 18,
  "found": [
    {"domain": "a.ru", "via": "domain_competitors", "in_serp_queries": null},
    {"domain": "b.ru", "via": "keyword_info", "in_serp_queries": ["q1", "q2"]}
  ],
  "excluded": [
    {"domain": "avito.ru", "reason": "агрегатор"},
    {"domain": "info.ru", "reason": "инфопортал"}
  ],
  "after_filter_count": 11,
  "note_yandex_search": ""
}
```

При tier=basic: ключа `path` НЕТ; `via` - `"client_competitors"` | `"arsenkin_top"`.

### `<analysis_dir>/competitors.json`

```json
{
  "path": "A",
  "client_business_type": "services",
  "client_type": "small",
  "direct": [
    {
      "domain": "competitor1.ru",
      "type": "medium",
      "dr": 15,
      "top10": 45,
      "top50": 320,
      "pages_keyso": 120,
      "traffic_month": 4500,
      "similarity": "direct",
      "score": 5,
      "is_leader": true,
      "note": ""
    }
  ],
  "leaders_top3": ["competitor1.ru", "competitor2.ru", "competitor3.ru"],
  "indirect": [],
  "client_competitors_check": [
    {"domain": "<из brief.client_competitors>", "in_our_list": true},
    {"domain": "<...>", "in_our_list": false, "reason": "не найден в Keyso по пересечению семантики"}
  ]
}
```

При tier=basic: ключа `path` НЕТ; в объектах доменов НЕТ `dr`, `top10`, `top50`, `pages_keyso`, `traffic_month` (ключи отсутствуют, не null); рядом с `leaders_top3` - `"basis": "judgement"` (см. Б4). Причины в `client_competitors_check` - без Keyso-формулировок (например «исключен фильтром: агрегатор»).

`client_type` - тип сайта клиента, определи по тем же правилам (если `brief.path == "A"` - из `brief.domain_dashboard_snapshot`; при tier=basic - суждением по фетчу сайта клиента, если домен есть; иначе из контекста или `null`).

`client_competitors_check` - проверка конкурентов клиента: попали ли они в наш список, и если нет - почему.

## Сводка в чат (6-8 строк)

- Путь: A/B/C/D (при tier=basic - «basic: бриф + SERP»)
- Найдено кандидатов: `<raw_count>`, после фильтрации: `<after_filter_count>`
- Исключено: агрегаторов `<N>`, маркетплейсов `<N>`, инфопорталов `<N>`, прочих `<N>`
- Финальные `<6-10>` конкурентов: домен1 (DR X, тип Y), домен2 (DR X, тип Y), ... (при basic - без DR, только тип)
- Топ-3 лидера: `<домен1>`, `<домен2>`, `<домен3>` (при basic - с пометкой «по суждению, без метрик»)
- Тип сайта клиента: `<client_type>`
- ⚠️ Не проверено: ссылочный профиль конкурентов, упоминания в СМИ, активность в соцсетях (только Keyso-метрики и тип сайта; при basic - только фетч)

При mode=enrich сводка другая: первой строкой - изменился топ-3 или нет (формат из раздела «Дообогащение»), далее - сколько доменов дообогащено метриками, у скольких `keyso_data: missing`, обновленный `client_type`.

## Запреты

- НЕ анализируй выдачу по запросам - это `serp-verdict` (он сделает это на следующем шаге).
- НЕ делай скан смыслов страниц - это `leader-scanner`.
- Агрегаторы (avito, 2gis, profi, zoon, ozon, wb, классифайды) - **никогда** не в `direct`.
- НЕ редактируй `brief.json` - он read-only после шага 1.
- При tier=basic НЕ вызывай Keyso-инструменты и НЕ пиши поле `path` и Keyso-метрики - даже как null.
- При mode=enrich НЕ пересобирай кандидатов и НЕ меняй состав `direct[]`/`indirect[]`.
- Длинное тире (—) и среднее (–) не использовать. Только дефис (-).
- НЕ используй букву ё - всегда пиши е. Правило для всех клиентских текстов и метатегов (как и запрет тире).
- Бюджет tier=seo: ≤20 MCP-вызовов на этот этап (1 `domain_competitors` + 3-5 `keyword_info` + 8-15 `domain_dashboard` + 2-3 `arsenkin_top` если регион не в Keyso + `seo_fetch_page` (profile="content") для спорных доменов).
- Бюджет tier=basic: до 5 `arsenkin_top` + до 10 фетчей (`seo_fetch_page`) - на фильтрацию, типизацию и выбор лидеров суммарно.
- Бюджет mode=enrich: до 12 `domain_dashboard` (по числу `direct[]`, обычно 6-10).
