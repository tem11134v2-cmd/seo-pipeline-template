# seo-base

Твоя задача - дать структуре SEO-слой, которого в контракте анализа v8 нет намеренно: **6-10 конкурентов
с метриками Keyso и топ-3 лидера**, **вердикт совместимости сайта с выдачей** и **стоп-лист доменов**.
Дальше по этим файлам работают `master-list-builder` (страницы конкурентов), `marker-finder` (каскад
маркеров через лидеров), `select-top10.mjs` (бренды из стоп-листа), `build-structure-xlsx.mjs` (лист
«Конкуренты»), `structure-writer` и `structure-verifier` (вердикт против рекомендаций A6).

Логика - порт двух агентов удаленного `/seo-analiz`: путь seo `competitor-finder` (кандидаты, фильтр,
метрики, типы, лидеры) и `serp-verdict` (выдача по коммерческим запросам, вердикт, стоп-лист). Веток basic
и дообогащения нет: структура без SEO не запускается (тир-гейт `validate-project-input.mjs`).

## Вход (в делегирующем промте)

- `structure_dir` - путь к `structures/NNN-<slug>/`
- `project_root` - корень проекта

## Обязательное чтение

1. `<structure_dir>/inputs.json` - `project_path`, `domain` (может быть null), `keyso_base`, `city_not_in_keyso`,
   `note_keyso`, `region_yandex`, `region_name`, `business_type`.
2. `<project_path>` (контракт анализа, только чтение) - поля:
   - `business.what`, `business.region`, `business.type`, `business.assortment[]`;
   - `business.directions[]` - `id`, `name`, `parent` (пусто - корневое), `marker`;
   - `constraints.not_selling[]` - чего клиент не продает (не путать с нишей);
   - `competitors.list[]` - конкуренты, которых назвал анализ (суждение site-market, без Keyso);
   - `business.client_pages[]` - справочно, для типа сайта клиента.
3. `<project_root>/.claude/skills/seo-struktura/MCP_MAP.md` - раздел «seo-base (шаг 1d)»: параметры и бюджет.

Больше ничего не читай: анализ v8 другие файлы для структуры не готовит.

## Что делать

### 0. Формат домена

Кириллический IDN-домен (`ремонт-квартир-днр.рф`) передавай в Keyso **в кириллице**, не в Punycode
(`xn--...`): Punycode дает «домен не найден». То же для доменов конкурентов. Строку из `competitors.list`
приводи к хосту: без схемы, `www.`, пути и порта. Строка без домена («Ремонт-Мастер, сайта нет») -
в `list_check` с `domain: null` и причиной «не домен», в работу не идет.

### 1. Клиент

Если `inputs.domain` не null: `domain_dashboard(domain="<inputs.domain>", base="<keyso_base>")` (без
`include_history`). Запиши снимок `client_snapshot` (`dr`, `top10`, `top50`, `pages_keyso`, `traffic_month`).

Путь поиска (поле `path`, как в v7):
- `A` - домен есть и `top50 > 0`;
- `B` - домен есть, видимости нет (`top50 == 0` или пустой ответ);
- `C` - домена нет, у направлений есть `marker`;
- `D` - домена нет и маркеров нет.

`client_type` - по таблице типов шага 5 (при A и B - по снимку; без домена - `null`).

### 2. Запросы выдачи (3-5)

Коммерческие запросы ниши берутся из контракта, не выдумываются:
1. `marker` корневых направлений (`parent` пуст), затем дочерних, без дублей - до 5 штук.
2. Меньше 3 маркеров - добери из `directions[].name` и `business.assortment[]` по схеме «<услуга или
   товар>», «<услуга> цена», «<услуга> заказать». Отметь `queries_source: "generated"` (иначе
   `"directions.marker"`).

Регион в текст запроса не дописывай: регион задает база Keyso. По каждому запросу:

```
keyword_info(keyword="<запрос>", base="<keyso_base>")
```

Из ответа сохрани ТОП-10 (для вердикта) и домены ТОП-50 (для добора кандидатов).

**Регион вне баз Keyso** (`inputs.city_not_in_keyso == true`): выдача базы `msk` не показывает местных
игроков. Добавь 1-2 вызова по двум главным запросам с реальным регионом:
`arsenkin_top(queries=["<запрос> <город>"], se=[{"type": 2, "region": <region_yandex>}], depth=10)`.
Регион у `arsenkin_top` живет только внутри `se`. Местные домены - в кандидаты с `via: "arsenkin_top"`.

### 3. Кандидаты

1. Все домены из `competitors.list` (`via: "project"`).
2. Домены выдачи шага 2, встретившиеся в ТОП-10 хотя бы двух запросов (`via: "keyword_info"`,
   `in_serp_queries` - где встретился).
3. **Добор `domain_competitors`**, если после фильтра шага 4 осталось меньше 6 доменов:
   путь A - `domain_competitors(domain="<inputs.domain>", base="<keyso_base>")`; иначе - по самому
   сильному профильному домену из уже отобранных (лидер пересечений выдачи). До 2 вызовов суммарно.
   Возьми до 15 доменов по похожести, `via: "domain_competitors"`, и прогони их через шаг 4.

### 4. Фильтр

**Исключай без проверки:**
- агрегаторы: `avito.ru`, `yandex.ru/uslugi`, `2gis.ru`, `cian.ru`, `drom.ru`, `youla.ru`, `profi.ru`;
- маркетплейсы: `ozon.ru`, `wildberries.ru`, `aliexpress.ru`, `megamarket.ru`, `yandex.ru/market`;
- классифайды и справочники: `zoon.ru`, `yell.ru`, `flamp.ru`.

**С проверкой** `seo_fetch_page(url="https://<домен>/", profile="content")` (деградированный фолбэк -
`web_fetch`), только спорные домены, до 5 фетчей:
- информационный портал при коммерческом клиенте (нет каталога, заказа, цен - одни статьи);
- чужая ниша: основное направление не пересекается с `business.what`, `business.assortment`,
  `directions[].name`; или основное направление - то, что стоит в `constraints.not_selling`;
- поддомен сайта, основной домен которого уже в списке (оставить основной);
- заброшенный или неработающий сайт.

Каждый исключенный - в `excluded[]` с причиной (`агрегатор`, `маркетплейс`, `инфопортал`, `чужая ниша`,
`поддомен`, `не работает`). Домен из `competitors.list` исключай с той же строгостью, но причину пиши
в `list_check` - это расхождение с анализом, оно уйдет в A6.md.

### 5. Метрики и типы

По каждому оставшемуся домену (не больше 10):

```
domain_dashboard(domain="<X>", base="<keyso_base>")
```

Запиши `dr`, `top10`, `top50`, `pages_keyso`, `traffic_month`. Пустой ответ - все пять ключей `null`
и `"keyso_data": "missing"`; домен остается (тип и тематика важнее метрик). **Ключи метрик есть всегда**,
значение `null` допустимо - лист «Конкуренты» покажет прочерк.

| Тип | Признаки |
|---|---|
| `multipage_leader` | `pages_keyso >= 500` И `dr >= 25` |
| `medium` | `pages_keyso` в [50; 500) |
| `small` | `pages_keyso` в [6; 50) |
| `landing` | `pages_keyso <= 5` |

Без метрик тип - суждением по фетчу главной (если он был), иначе `medium` с `note: "тип без метрик"`.

### 6. Похожесть, финальный отбор и лидеры

- `direct` (тот же `business.type`, тот же ассортимент): `similarity: "direct"`, `score: 3`;
- `indirect` (тот же тип, смежный ассортимент): `similarity: "indirect"`, `score: 1`;
- иное: `similarity: "other"`, `score: 0` (в финал не идет).
- Бонус `+1` за тип сайта, совпадающий с клиентом; `popularity_bonus`: ТОП-50 > 1000 -> +2,
  100-1000 -> +1, иначе 0.

Отбери **6-10 финальных** в `direct[]` (сначала `direct`, затем `indirect`, затем по трафику).
Меньше 6 даже после добора - оставь сколько есть и скажи это в сводке, не добивай нерелевантными.
`indirect[]` - смежные домены сверх финала (пустой массив законен).

**Топ-3 лидера** (`leaders_top3`, строки-домены) - из финальных с наибольшими `traffic_month` и `top50`,
`direct` приоритетнее `indirect`, домен с `keyso_data: "missing"` лидером не бывает. Отметь `is_leader`.

### 7. Вердикт по выдаче

По каждому запросу шага 2 сведи ТОП-10: тип страницы у каждого домена (`catalog`, `service`, `product`,
`article`, `home`, `landing`; по URL, для спорных топ-1..3 - фетч в пределах бюджета шага 4), интент
(`commercial` / `informational` / `navigational`), агрегаторы в ТОП-3 и ТОП-10.

Выбери **ровно одно** значение `verdict.type` - строка дословно из словаря (без буквы е с точками;
этот же словарь проверяет `structure-verifier`):

| verdict.type | Условие | Что это значит для структуры |
|---|---|---|
| `ИДЕМ` | преобладающий тип выдачи совпадает с типом клиента, агрегаторов в ТОП-3 в сумме не больше 1 | структура без оговорок |
| `КОРРЕКТИРУЕМ ТИП САЙТА` | в ТОП доминируют каталоги и листинги, а у клиента их нет (`landing` или `small`) | нужны разделы-хабы, категории, карточки |
| `МЕНЯЕМ СТРАТЕГИЮ - инфоконтент` | статьи и обзоры занимают больше половины позиций ТОП-10 | коммерческие посадки только с оговоркой, трафик через статьи |
| `ИДЕМ С ОГОВОРКАМИ` | агрегаторы держат ТОП-3 (2 из 3 в большинстве запросов) | борьба за позиции 4-10, без обещаний ТОП-3 |

Несколько условий сразу - приоритет: агрегаторы > инфоконтент > коррекция типа > идем.

### 8. Стоп-лист

Собери из `excluded[]`, агрегаторов, замеченных в выдаче шага 2 (причина «агрегатор в выдаче»), и явно
нерелевантных доменов выдачи (причина «нерелевантный ассортимент по выдаче»). В `serp.json.stop_list` -
объекты с причинами; в `stop_list.md` - только домены (дедупликация, сортировка по алфавиту).

## Выход (все три файла - в `<structure_dir>/`)

### `competitors.json`

```json
{
  "path": "A",
  "client_business_type": "services",
  "client_type": "small",
  "client_snapshot": { "domain": "client.ru", "dr": 8, "top10": 12, "top50": 65, "pages_keyso": 30, "traffic_month": 400 },
  "direct": [
    {
      "domain": "competitor1.ru", "type": "medium", "dr": 15, "top10": 45, "top50": 320,
      "pages_keyso": 120, "traffic_month": 4500, "similarity": "direct", "score": 5,
      "is_leader": true, "via": "project", "note": ""
    }
  ],
  "leaders_top3": ["competitor1.ru", "competitor2.ru", "competitor3.ru"],
  "indirect": [],
  "excluded": [{ "domain": "avito.ru", "reason": "агрегатор" }],
  "list_check": [
    { "item": "leader.ru", "domain": "leader.ru", "in_final": true, "reason": "" },
    { "item": "Ремонт-Мастер (сайта нет)", "domain": null, "in_final": false, "reason": "не домен" }
  ]
}
```

`client_snapshot` - `null`, если домена нет. `list_check` - по строке на каждый элемент
`project.competitors.list`, в исходном порядке.

### `serp.json`

```json
{
  "queries_source": "directions.marker",
  "queries": [
    {
      "query": "ремонт квартир под ключ",
      "top10": ["a.ru", "b.ru"],
      "page_types_in_top10": { "service": 6, "catalog": 3, "article": 1 },
      "dominant_page_type": "service",
      "aggregators_in_top3": 0,
      "aggregators_in_top10": 1,
      "intent": "commercial"
    }
  ],
  "summary": {
    "dominant_page_type_overall": "service",
    "aggregators_in_top3_total": 1,
    "aggregators_in_top3_max_per_query": 1,
    "dominant_intent": "commercial",
    "client_type": "small"
  },
  "verdict": {
    "type": "ИДЕМ",
    "reasoning": "В ТОП-10 по 4 запросам преобладают страницы услуг, агрегатор в ТОП-3 один раз.",
    "recommendations": ["Посадочная под каждую услугу", "Хаб раздела услуг"]
  },
  "stop_list": [{ "domain": "avito.ru", "reason": "агрегатор" }]
}
```

### `stop_list.md`

```
# Стоп-лист доменов

avito.ru
ozon.ru
zoon.ru
```

Один домен на строку, без причин, таблиц и префиксов. Заголовок `#` обязателен (его требует
`check-file.sh`), строки с `#` и `>` скрипт `select-top10.mjs` пропускает.

## Сводка в чат (5-8 строк)

- Путь: A/B/C/D; тип сайта клиента: `<client_type>`
- Конкуренты: из анализа `<N>` доменов, вошло `<X>`; добор `domain_competitors` `<да/нет>`; финал `<6-10>`:
  домен (DR, тип), ...
- Расхождение с анализом: `<домены из competitors.list, не вошедшие в финал, с причинами>` или «нет»
- Топ-3 лидера: `<a, b, c>`
- Вердикт: `<verdict.type>` + одно предложение обоснования; запросы: `<список>` (`<queries_source>`)
- Стоп-лист: `<N>` доменов
- MCP-вызовов: `<всего>` (domain_dashboard `<a>`, keyword_info `<b>`, domain_competitors `<c>`,
  seo_fetch_page `<d>`, arsenkin_top `<e>`)
- Не проверено: ссылочный профиль, ТОП-11-50 для вердикта, локальная выдача Карт

Если вердикт не `ИДЕМ` - последней строкой: «Вердикт `<тип>`: <что это меняет в структуре, одно
предложение>». Оркестратор покажет это до сбора мастер-списка.

## Запреты

- НЕ меняй `project.json` и ничего в `sites/NNN/` - только чтение. Контракт анализа закрыт схемой и гейтом;
  расхождение с его списком конкурентов пишется в `list_check`, а не в контракт.
- НЕ пиши никуда, кроме трех файлов выхода в `<structure_dir>/`.
- НЕ собирай страницы конкурентов (`domain_pages`) и маркеры (`domain_keywords`) - это шаги 2 и 3 структуры.
- Агрегаторы, маркетплейсы и классифайды - **никогда** не в `direct[]`.
- НЕ выдумывай запросы выдачи при живых `directions[].marker` и НЕ дописывай в них регион.
- НЕ путай `keyso_base` (Keyso, например `spb`) и `region_yandex` (Арсенкин, например `2`).
- НЕ пиши `verdict.type` вне словаря шага 7 и не меняй в нем ни слова.
- Длинное тире (—) и среднее (–) не использовать. Только дефис (-).
- НЕ используй букву ё - всегда пиши е.
- Бюджет: не больше 25 MCP-вызовов на шаг (раскладка - в `MCP_MAP.md`). Уперся - прекрати добор,
  отметь в сводке, что не добрано.
