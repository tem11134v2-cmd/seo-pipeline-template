# site analiz

Предпроектный анализ. Запускается в worktree-сессии. Выход - контракт `project.json`,
цитаты фактов `parts/facts-src.json`, при `tier basic` состав страниц `structure_data.json`
и два документа заказчику. Дальше по тиру: `seo` -> `/seo-struktura <NNN>`,
`basic` -> `/site-tekst --site <NNN>`.

## Чего этот скил НЕ делает

- не пишет тексты страниц, метатеги и прототип - это `/site-tekst`;
- не пишет статьи;
- не строит SEO-структуру: при `tier seo` состав страниц делает `/seo-struktura` по
  `project.json`;
- не трогает `/seo-faq` - согласованная работающая машинерия;
- не выдумывает. У проверяемого утверждения есть источник (бриф, созвон, документ, сайт)
  и дословная цитата. Источника нет - строки нет, вопрос уходит в документ 2.

## Раскладка

```
sites/NNN-<slug>/
├── queue.json            # три ответа оператора, гейт, журнал исключений
├── input/                # вводная, снимки сайта, operator.md при пустом входе
├── parts/facts.json      # шаг 1  фактура, источник у каждой строки, вопросы gaps[]
├── parts/facts-src.json  # шаг 1  цитаты фактов, живут весь срок задачи
├── parts/market.json     # шаг 2  ЦА, профиль ниши, оффер, лексикон, конкуренты
├── project.json          # шаг 3  контракт по project.schema.json
├── structure_data.json   # шаг 3b состав страниц без SEO (tier basic)
├── docs/understood.html  # шаг 4  документ 1 «Что мы поняли о вашем бизнесе»
├── docs/ask.html         # шаг 4  документ 2 «Что нам от вас нужно»
└── answers.txt           # шаг 5  ответы заказчика
```

## Состояние выводится из содержимого

```
node .claude/scripts/site/queue.mjs state
```

| чего нет | шаг |
|---|---|
| каталога и `queue.json` | 0 init |
| `tier`, `type`, `site_kind` в queue.json | 0b три вопроса оператору |
| `parts/facts.json` | 1 фактура |
| `parts/market.json` | 2 смыслы и разведка |
| `project.json` | 3 сборка контракта |
| `structure_data.json` (только tier basic) | 3b состав страниц |
| документов и ссылок в queue.json | 4 документы и Drive |
| отметки гейта | 5 ответы заказчика |

Из файлов не выводится только согласование с человеком: его ставит
`queue.mjs gate --by "<кто>"`, и только после дифф-листа.

## Шаг 0. init

```
node .claude/scripts/site/queue.mjs init <slug> [--tier seo] [--type services] [--kind multipage]
```

Создает каталог, `parts/`, `docs/` и `queue.json`. Повторный запуск печатает состояние.

## Шаг 0b. Три вопроса оператору

Тридцать секунд, **оператору, не заказчику**:

1. SEO куплено? -> `tier`: `basic` либо `seo`.
2. Услуги, магазин или и то и другое? -> `business.type`: `services`, `shop`, `both`.
3. Лендинг или многостраничник? -> `business.site_kind`: `landing` либо `multipage`.

Ответы идут флагами `init` в `queue.json`; сборка контракта ставит их выше догадки агента.

**Вводной папки нет вовсе** - три вопроса одним сообщением задает этот скил, до
`site-intake`: у субагента диалога нет. Дословные ответы - в `input/operator.md`:

1. Что продаем, кому и в каком городе.
2. Что уже есть: сайт, прайс, лицензии, фото работ, отзывы.
3. Телефон и юрлицо, ИНН и ОГРН, если под рукой.

Ответа нет - работаем тем, что есть: в `source[]` встает `operator_guess`, недостающее
уезжает вопросами в документ 2.

## Шаг 1. Фактура - агент `site-intake`

Читает `input/` (бриф, созвон, документы, снимки сайта, `operator.md`). Кладет
`parts/facts.json`: `business` (с `site`, `client_pages`, `assortment`, `pages_hint`),
до 40 фактов с `label`, `value`, `kind`, `src`, `q[]`, при наличии `artifact`, и вопросы
`gaps[]`. `publish` при засеве **всегда** `no`. Рядом `parts/facts-src.json` - дословная
цитата каждого факта: файл живет весь срок задачи, из него тексты берут `source_quote`.

Фактов меньше 15 - предупреждение, а не брак: 15 придуманных строк хуже 9 настоящих.

## Шаг 2. Смыслы и разведка - агент `site-market`

Кладет `parts/market.json`: 2-4 сегмента (боли, страхи, возражения с готовым ответом и
ссылкой `facts` на факты, критерии выбора), профиль ниши `profile` (аудитория,
прогретость, чек, цикл), оффер, лексикон и разведку. Глубина одна для любого сайта:
3-5 главных лидеров - обещания, цифры рынка, дыры и `page_types` (какие страницы стоят в
меню). Разбор блоков лидеров по типам страниц делает `/site-tekst`. При `basic` платные
инструменты не вызываются.

Основа портретов и возражений - **рассуждение агента по промту**; парсинг отзывов и
форумов - право, а не условие. Развернутое досье умирает в проходе, в файл едет сводка.
`words[].src` - ярлык: `persona` штатно, в кавычках на сайте только `forum` либо `client`.

## Шаг 3. Сборка контракта

```
node .claude/scripts/site/build-project.mjs <каталог>
node .claude/scripts/site/verify-data.mjs <каталог> --seed
```

Склейка двух `parts/` по белому списку полей. `gates`, `facts[].q`, `directions[].serves`,
`sig` и `gaps[].weight` считает скрипт; `kind`, забытый агентом, выводит мостом `q -> kind`
и печатает строку. Направление без сегмента - предупреждение с именем. При `basic` и
лендинге сборка сама пишет `structure_data.json` из одной главной.

`verify-data` сверх схемы проверяет: цитата каждого факта дословно есть в `input/` или в
листе ответов (нормализуются е, тире, кавычки, пробелы), в значении факта нет служебной
пометки вроде «не разворачиваем в этой версии», ссылки `objection[].facts` ведут на
существующие факты, `structure_data.json` в формате `import-structure.mjs`. Нарушение -
exit 2 с перечнем.

Exit 2 - файл не записан. Exit 1 - предупреждения. После гейта пересборка отказывает:
нужна правка - `--force` и новый гейт. `gates.ready=false` не брак: тексты будут короче.

## Шаг 3b. Состав страниц без SEO - агент `pages-planner`

Только при `tier basic` и `site_kind multipage`. Лендингу состав пишет сборка, при
`tier seo` состав строит `/seo-struktura` - планировщик не зовется.

Делегировать `pages-planner` с `task_dir` и `project_root`; маркер
`.claude/tmp/expected-pages-planner-<run_id>.txt` = `<каталог>/structure_data.json`.
Вход - только `project.json`, выход - `structure_data.json` в формате `/seo-struktura`:
адреса без слеша на конце, шесть русских типов, хаб - «Категория» и `role: "навигация"`,
`section: "dir:<id>"`, `queries: []`, до 40 страниц. Затем:

```
node .claude/scripts/site/verify-data.mjs <каталог>
```

Exit 2 - повторный вызов планировщика с перечнем нарушений; правка файла руками вместо
агента не идет.

## Шаг 4. Два документа и Drive

```
node .claude/scripts/site/build-doc.mjs <каталог>
node .claude/scripts/site/queue.mjs docs --understood <url> --ask <url>
```

**Документ 1** - полный, без плейсхолдеров и открытых вопросов. Решения печатаются
принятыми с дефолтом: «Мы исходим из того, что ... Если это не так - скажите сейчас».
У каждого код `d1`-`d9`, по нему ответ возвращается ровно в свое поле; `d9` - состав
сайта списком страниц. У утверждения виден источник. Последняя строка: «Если вы ничего не
поправите, мы работаем по этому документу».

Документ полон не потому, что придумали больше, а потому, что говорим меньше и все
сказанное - правда. Причина без доказательства в документ не попадает - она становится
вопросом.

**Документ 2** - одна страница, **не больше 10 вопросов**, только фактура и развилки.
Порядок по `gaps[].weight` считает скрипт. Последняя строка: «Ответите на первые три -
тексты станут заметно сильнее. Не ответите - сайт все равно будет, просто короче».

Объем сверх порога - предупреждение с именем раздела; режется контракт, а не документ.
Оба документа заливаются в Drive, ссылки - в `queue.json`.

## Шаг 5. Гейт: ответы заказчика

Основной путь - лист с галочками `answers.txt`. Проза, комментарии и голосовые разбирает
агент в тот же лист, дословную фразу заказчика ставит после `<<`.

```
node .claude/scripts/site/apply-answers.mjs <каталог>           # дифф-лист, файл не тронут
node .claude/scripts/site/apply-answers.mjs <каталог> --apply   # тот же дифф-лист и запись
node .claude/scripts/site/verify-data.mjs <каталог>
node .claude/scripts/site/queue.mjs gate --by "<кто согласовал>"
```

**Прямой записи в контракт без дифф-листа не бывает**: поле, было, стало, фраза заказчика.
Молчание по решению - принятие дефолта строкой журнала. Молчание по факту - `publish="no"`
и вопрос в `gaps[]`. Факт из ответа получает источник `ответ` и цитату - строку листа в
`parts/facts-src.json`; служебная пометка фактом не становится. Ответ по `d9`
(«убрать 7, /otzyvy; вернуть /komanda») меняет только `target_status` в
`structure_data.json`: новая страница - новый проход планировщика.

После гейта: `tier seo` -> `/seo-struktura <NNN>`, затем `/site-tekst --site <NNN>
--structure <MMM>`; `tier basic` -> `/site-tekst --site <NNN>`.

## Журнал исключений

```
node .claude/scripts/site/queue.mjs log waiver "цены не публикуем" --ground "запрет заказчика на созвоне"
node .claude/scripts/site/queue.mjs journal
```

Виды: `waiver`, `violation`, `gap`, `dropped`. Без `--ground` запись не принимается.

## Инварианты

- `project.json`: 22000 знаков - предупреждение, 32000 - ошибка. Каталожный IBG весит около
  25500 со всеми полями; толстый массив называет скрипт.
- Полей-обоснований в файлах нет: `rationale`, `why`, `note`, `confidence`, `evidence`,
  `status`, `function_why`, `client_why`.
- Длинное и среднее тире запрещены - только дефис. Буква е-с-точками запрещена - всегда е.
- Пустая фактура законна: недобор дает короткий сайт и вопрос заказчику.
- Словарь блоков `pages.yml` живет в этом скиле: по нему считаются `q`, вес вопросов и
  признаки ниши. Блок без факта снимается или идет по своему FALLBACK.
