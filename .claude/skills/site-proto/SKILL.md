# site proto

Слой письма v8. Вход - согласованный `project.json` (гейт `/site analiz` пройден) и
`pages.yml`. Выход - страницы и один `site.html`: открывается двойным щелчком и показывает
весь сайт. `--page <слаг>` сужает шаги 5, 9 и 10 до одной страницы.

**Страница - это упорядоченные ответы на вопросы читателя.** Заголовок раздела - ОТВЕТ,
а не ярлык секции. Над разделом стоит метка `<!-- q:<id> closes:<fNN,oN.M> -->`: по ней
конвейер получает покрытие фактов и заготовку FAQ. Метки нет или она неизвестна -
предупреждение и позиционный фолбэк, никогда не отказ: опечатка не валит хороший текст.

## Чего этот скил НЕ делает

- **не пишет статьи.** Типа `article` в `pages.yml` нет, и `plan.mjs` физически не может
  породить такое задание. Статьи - `/seo-statya`;
- **не трогает `/seo-faq`** и `faq-builder`: согласованная с SEO-сервисами машинерия, она
  в v8 не переписывается. Метки `closes:` - сырье для нее, и только;
- **каталог и товары - следующий срез.** Тут путь письма для `landing`, `service`, `home`,
  `info`. `category`, `facet`, `product` живут в контракте и получают адреса, но замера и
  письма у них нет: `plan.mjs` уводит их в `later`. Заглушек нет намеренно;
- **не согласовывает состав.** Состав - арифметика шести правил по замеру; с заказчиком
  согласуется манера на готовом тексте (гейт B), а не таблица блоков;
- **не выдумывает.** Числа только из `facts[]` с `publish: "yes"`, цифры лидеров ядовиты,
  адреса и метатеги делает формула.

## Раскладка

```
sites/NNN-<slug>/
├── project.json          # вход, гейт /site analiz пройден
├── pages.json            # 1  адреса и слаги, redirects.csv при переезде
├── leaders/<cluster>.json# 2-3 замер рынка по типу страницы
├── plan.json             # 4  состав страниц арифметикой
├── tasks/                # 5  задания автору и meta.json с метатегами
├── theses.md             # 5  тезисы ВСЕХ страниц, одни у всех авторов
├── pages/<slug>.md       # 6 и 8  написанные страницы
├── verify.json, lift.json# 9-10 отчет проверки и список усиления
├── judge/<slug>.md       # 11 вердикты по рубрике
└── site.html             # 12 сборка
```

## Состояние выводится из содержимого

Списка состояний нет. Следующий шаг виден по тому, чего на диске нет:

| чего нет | шаг |
|---|---|
| `pages.json` | 1 список страниц |
| `leaders/` | 2 замер лидеров |
| `leaders/<cluster>.json` | 3 разметка блоков |
| `plan.json` | 4 план |
| `tasks/` и `theses.md` | 5 задания |
| хоть одной страницы в `pages/` | 6 эталонная страница |
| отметки гейта B в журнале | 7 гейт B |
| страниц меньше, чем заданий | 8 веер остальных |
| `verify.json` либо он старше страниц | 9 проверка |
| `lift.json` либо он старше страниц | 10 усиление |
| `judge/<slug>.md` на каждую страницу | 11 судья |
| `site.html` | 12 сборка |

Усиление пишет текст ПОСЛЕ проверки, поэтому 9 и 10 идут кругом: тронул страницу -
прогон обоих заново. Отметка времени и есть состояние.

## Шаг 1. Список страниц

```
node .claude/scripts/site/pages.mjs <каталог>
```

Слаги и адреса из `business.directions[]` и `client_pages[]`. Существующий адрес не
пересоздается, смена дает строку в `redirects.csv`. Лендинг - ОДНА страница: направления
становятся блоками. Каннибализация ловится тут, до письма.

## Шаг 2. Замер лидеров, глубина по типу сайта

```
node .claude/scripts/site/recon.mjs plan <каталог>   # что мерить и где, дальше снятие страниц
```

Заказчик не присылает ничего, все снимает конвейер. `business.site_kind`:

- `landing` - замер минимальный: блоки лендингов однородны, скелет из `pages.yml`, замер
  только подтверждает его;
- `multipage` - полный замер по каждому типу страниц: кластер = тип страницы, потому что
  на главной и на услуге рынок ставит разные блоки, а общая куча не меряет ничего.

При `tier: basic` платные инструменты не вызываются вовсе, адреса - из `competitors.list`.
Кэш по маркеру и региону живет 14 дней; записанный замер заморожен, иначе план перестает
быть воспроизводимым.

## Шаг 3. Разметка блоков

```
node .claude/scripts/site/map-blocks.mjs <файл|каталог>   # приметы -> sections.json
агент leader-mapper                                      # имена блокам, батч на кластер
node .claude/scripts/site/recon.mjs parse <каталог>      # покрытие, порядок, tainted
```

Порядок обязателен: `leader-mapper` читает `sections.json`, который пишет `map-blocks.mjs`,
а `recon.mjs parse` читает уже названное.

Блок опознается по DOM-приметам (таблица с ценами, форма на 2-4 поля, шесть картинок в
секции, аккордеон), словарь заголовков - ВТОРОЙ сигнал.



**Живость:** из `main` за вычетом навигации и разделов, повторяющихся на двух адресах
домена, снято от 3 заголовков И от 800 знаков. Покрытие - от ЖИВЫХ страниц, не от попыток.
Живых меньше трех - `measured: false`, R1 и R2 не применяются.

**Чужие числа ядовиты:** ложатся в `tainted[]` и грепаются по сборке. Форму и состав с
рынка берем, цифры - никогда.

## Шаг 4. План: состав страницы арифметикой

```
node .claude/scripts/site/plan.mjs <каталог>
```

Шесть правил, седьмого нет. R1 покрытие от 0.6 - блок в ядро. R2 покрытие до 0.2 и блок
опционален - снять, но признак у двух живых лидеров демотирует в `tmpl`, и бюджет R4 эту
защиту не отменяет. R3 `core` не снимается, блок без рынка остается отстройкой и такой
один. R4 объем - ЧИСЛО БЛОКОВ (медиана живых в вилке типа, потолок 12; знаки вторичны) и
блоков функции В не больше половины. R5 порядок - медианный ранг. R6 деградация: число ->
условие -> состав, действие -> состав, затем шаблон, затем снятие с вопросом заказчику.
Один и тот же замер обязан давать байт-в-байт тот же план.

## Шаг 5. Задания и тезисы

```
node .claude/scripts/site/build-tasks.mjs <каталог>
```

`tasks/<slug>.md`, `tasks/meta.json` (метатеги, автор их не пишет) и `theses.md`. Два
потолка раздельно: ИНСТРУКЦИИ (`site-author.md` + `AUTHOR.md` + задание) не больше 12000,
из них запретов не больше 2500; МАТЕРИАЛ (`project.json` + тезисы + лидеры) не больше 16000.

**Машинный инвариант: материала больше, чем ЗАДАНИЯ** - задание пишет сам конвейер, и в v7
автору приезжало 32982 знака собранного задания. Exit 1, чинится усушкой входа. Материала
меньше, чем ВСЕХ инструкций с методичкой, - предупреждение с причиной: методичка у всех
страниц одна, значит тонкий контракт. Это факт о проекте, и сайт от него короче, а не
несобираемый.

## Шаг 6. Эталонная страница

Агент `site-author`, ОДНА страница целиком, один проход, один файл. При `landing` она
единственная, при `multipage` - первая услуга плана. Автор видит `theses.md` и знает, что
скажут соседи, до своей первой строки.

## Шаг 7. ГЕЙТ B: манера и канон на готовом тексте

Заказчику уходит ОДНА написанная страница, а не три варианта главной в трех тонах: старый
тон-гейт стоил 3,35 млн токенов, а решали по тексту, который потом переписывали. Два
вопроса: манера и канон. Ответ идет в `offer.tone` и `lexicon.canonical`, отметка - в журнал:

```
node .claude/scripts/site/queue.mjs log waiver "гейт B: манера принята" --ground "<кто и чем ответил>"
```

Правка манеры переписывает эталон, а не весь сайт.

## Шаг 8. Веер остальных страниц

Тот же `site-author` на остальные задания, ПОСЛЕ гейта и с общим `theses.md`: в v7 писали
вслепую, и цельность потом чинилась вычитанием самоповторов. Канон повторяется ДОСЛОВНО,
перефразировать «чтобы не повторяться» запрещено.

## Шаг 9. Проверка

```
node .claude/scripts/site/verify-page.mjs <каталог>
```

Реестр правил - `rules.yml`. Все греповое (числа не из фактов, арифметика на лету,
смягчители, надписи кнопок, жаргон, типографика, ядовитые числа, адрес в тексте) живет
тут, а НЕ в промте: место в промте дорогое, машина проверяет дешевле. Блокирующие правит
`site-editor` и **только названное**. Недобор знаков - предупреждение: верстка собирается
под текст. Отчет ложится в `verify.json`.

## Шаг 10. Усиление

```
node .claude/scripts/site/lift.mjs <каталог>
```

Адресный список по шести маркерам: неиспользованный факт `publish: "yes"`, ответ на
возражение сегмента мимо его страницы, `reasons[].claim` вне текста, первый экран без
числа при непустых фактах, вопрос с нулевым покрытием, запрос страницы вне текста.

Список пуст - шаг НЕ ВЫЗЫВАЕТСЯ, 0 токенов, нормальный исход, объяснений не требует.
Непуст - агент `site-strengthener`, четыре действия, ВСЕ на добавление, потолок +10% к
объему. **Резать он не может**: симметрия качества, роль без реза. После него страница
прогоняется через шаг 9 заново.

## Шаг 11. Судья

Агент `site-judge` по `docs/v8/rubric.md`, постранично, в `judge/<slug>.md`. Выносит
вердикт и **не чинит**: иначе оценка подстраивается под свою же правку.

## Шаг 12. Сборка и сдача

```
node .claude/scripts/site/assemble.mjs <каталог>
node .claude/scripts/site/verify-build.mjs <каталог>
```

Один self-contained `site.html`: стартовая страница-список, секции с неймспейсом,
hash-роутер, меню из состава, wireframe без цветных тем, попапов и анимаций. Адреса
переводятся в маршруты, метатеги берутся из `tasks/meta.json`. **Служебный хвост в вывод
не попадает** - он адресован конвейеру, а не читателю.

`verify-build.mjs` - восемь правил: блок плана собран либо объявлен в журнале; чисел
лидеров нет; маркеров нет; id не повторяются; типографика чистая; хвоста нет; `lift.json`
не старше страниц; `verify.json` не старше страниц.

Сдача: `site.html` заказчику, вопросы снятых блоков и строк `недостает:` одним списком
(`assemble.mjs <каталог> --ask`), отступления - `queue.mjs journal`.

## Пустая фактура: три исхода и ни одного четвертого

Ответ без числа возможен - отвечаем условием, порядком работы, составом или границей.
Ответа нет вовсе - блок в шаблон или снимается строкой `снят:`. Вопрос массовый, а ответа
нет - нулевое покрытие и строка `недостает:`, вопрос всплывет в FAQ. Разбор с образцами -
`AUTHOR.md`, раздел 4. **Страница становится КОРОЧЕ, а не оборонительнее:** блоков функции
В не больше половины, и это арифметика.

**Запрещенная деградация** - брак, а не «лучше чем ничего»: чужая цифра; «около», «более»,
«от N» без подтверждения; срочность без реальной даты или остатка; персона, поданная как
отзыв; выдуманные границы.

## Как снимается правило

Снимает правило человек, ОДНОЙ строкой с непустым основанием. Снятый блок `verify-build`
узнает по имени страницы И словам «блок <id>», формат ровно такой:

```
node .claude/scripts/site/queue.mjs log waiver "<что сняли>" --ground "<почему>"
node .claude/scripts/site/queue.mjs log dropped "страница <имя>: блок <id> снят" --ground "<почему>"
node .claude/scripts/site/queue.mjs log violation "<что не сошлось>" --ground "третья попытка, идем дальше"
```

По строке `снят:` из хвоста `dropped` пишется сам. Без `--ground` запись не принимается.
Третья неудача на одном месте - принятое нарушение, а не повод крутить цикл: оно видно в
журнале и в сдаче. Молча обойденных правил нет.

## Инварианты

- Автор ОДИН. Ни `block-planner`, ни `slot-mapper`, ни `blueprint` не существует.
- В `AUTHOR.md` приемов и образцов больше, чем запретов: запрет вносится только вместе с
  образцом. В v7 на один образец приходилось 125 «не».
- Жестких лимитов знаков ровно два: метатеги (70 и 160) и интро категории (500). Остальные
  нормы - предупреждение ПОСЛЕ письма.
- Бюджеты: правил плана ровно 6, правил `verify-page` не больше 12 в разделе, блоков в
  `pages.yml` не больше 30, скриптов не больше 20, агентов конвейера не больше 8 по списку
  `AGENTS_V8` (глоб `site-*` мерил бы и агентов v7). Новое - вместо старого.
- Длинное и среднее тире запрещены - дефис. Буква е-с-точками запрещена - всегда е.
- Полей-обоснований (`rationale`, `why`, `note`, `confidence`, `evidence`) нет нигде.
