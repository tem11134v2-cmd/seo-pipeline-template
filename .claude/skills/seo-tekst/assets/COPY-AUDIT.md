# COPY-AUDIT.md - чек-лист контроля продающего текста

Файл `copy-auditor`. Прогоняется по готовому page.json ПЕРЕД сборкой HTML; нарушения чинятся на месте.
Писатель этот файл не читает (его файл - VOICE.md); проверка - отдельными свежими глазами.

**Это контроль ПРОДАЮЩЕГО текста, а не борьба с ИИ-детектором** (анти-ИИ-паттерн - забота статей, не лендингов; см. ADR-022). Порядок важности при правке:
1. **Смысл и грамотность** (П.0) - текст верен, не преувеличен, грамотен. Это первое, что бракует заказчик.
2. **Функция блока и привязка к ЦА** (П.1) - каждый блок выполняет одну из четырёх функций (Р/Д/К/В) и привязан к covers; блок без функции и без привязки - сигналить, а не переписывать.
3. **Чистота и продающая дисциплина** (П.2-П.13) - жаргон, штампы, манипуляции, лимиты, утечки.
4. **Подача: как сказано** (П.14-П.21) - противопоставления, заочный диагноз читателю, пустые заголовки, хвосты, образ конкурента, голос и обращение, канцелярит, бюджет текста. Это то, что заказчик формулирует как «звучит не так» и «текста слишком много».

Механическую часть (тире, жаргон+утечки, манипуляции, H1, эмодзи, лимиты слотов) проверяет `verify-copy.mjs`; смысл, боль и тон добивает агент.

**Про предупреждения валидатора.** Механическую часть правил П.14-П.21 (греп-паттерны противопоставлений, отрицаний, третьего лица, смешения обращения, длина предложения) `verify-copy.mjs` выдаёт как **ПРЕДУПРЕЖДЕНИЯ**, а не как ошибки: у всех этих конструкций есть законные употребления (блок-сравнение, сброс ложной категории, чужая роль в чужой истории, «без обязательств»). Решение по каждому предупреждению - за тобой, автоматом не чинится и автоматом не игнорируется.

## П.0. Смысл и грамотность (ПЕРВЫМ - это бракуют заказчики)

Заказчики возвращают тексты за «перегнутый смысл и неграмотность», а не за «ИИ-шность». Лови именно это:

- **Преувеличения и неправда.** «В 10 раз», «всегда», «никто кроме нас», «100%», превосходные степени - верны только если это факт из `facts.json`. Нет факта -> снять степень / переписать.
- **Кривые причинно-следственные связки.** «X, поэтому Y», где Y из X не следует -> переписать. Логические нестыковки (компания приписывает себе чужую роль; «не сваливаем на подрядчиков», будучи сама подрядчиком) -> исправить.
- **Самопротиворечия между блоками.** Один факт - одно значение на всей странице (сверь с facts.json).
- **Грамотность.** Рассогласование падежей/чисел, проглоченные слова, кривые обороты, пунктуация -> вычистить. Читай каждый блок как корректор.

## П.1. Функция блока и привязка к ЦА

Блок оправдан не только «болью». В blueprint у блока есть поле `function` - одна из четырёх функций (таксономия block-planner):

| Код | Функция | Что делает блок |
|---|---|---|
| **Р** | результат | что клиент получит, польза в цифрах |
| **Д** | доказательство | факт, кейс, цифра, документ |
| **К** | квалификация | кто мы и почему нам можно верить (лицензия, состав команды, стаж, цифры компании) |
| **В** | возражение | снимает конкретное сомнение |

- **Оправданность.** Блок считается оправданным, если выполняет ЛЮБУЮ из четырёх функций. Проверяй по `blueprint.blocks[].function` и по `covers`. Корректный трастовый блок (лицензия, состав команды, цифры компании, квалификация) - это функция **К** или **Д**: он оправдан сам по себе, переписывать его «под боль» ЗАПРЕЩЕНО (это выхолащивает доверие).
- **Привязанность.** Блок считается привязанным, если непуст ЛЮБОЙ из `covers.pains` | `covers.objections` | `covers.triggers`.
- **Что делать с безфункциональным блоком.** Блок без единой привязки И без объявленной функции - СИГНАЛИТЬ в сводке (и пометкой в `fill_notes`), а не переписывать самовольно. Назначение и состав блоков - зона block-planner, не твоя.
- Если `function` в blueprint нет - опирайся на `covers` (и, при сомнении, на `audience.json` summary); отсутствие поля не повод переписывать блок.
- Формулировки боли - узнаваемые, словами клиента, не маркетинговый язык. Это чинится на месте.
- **Предупреждение о перекосе.** Страница, где больше половины блоков имеют функцию **В**, читается как оправдание. Это сигнал оркестратору в сводке - состав блоков аудитор НЕ меняет.

## П.2. Утечка внутренней кухни + жаргон маркетолога -> 0

Клиент покупает результат, а не методику и не наши инструменты. Запрещено в клиентском тексте:

| Запрещено | Замена |
|---|---|
| **Сургай** и любые названия методик | убрать совсем (это наша кухня) |
| **кастдев** / customer dev | «созваниваемся с вашими клиентами» |
| JTBD | «зачем покупают» |
| CJM | «путь клиента» / убрать |
| сегмент / персонаж / аватар | «ваши клиенты» / «кто покупает» |
| УТП / USP | «чем вы отличаетесь» (фактом, не ярлыком) |
| оффер / лид / конверсия / воронка | бытовое слово или убрать |

## П.3. Регистр по брифу - без развязности

«Ты» и разговорный тон допустимы (если не противоречат брифу), но развязный сленг подрывает доверие:

| Стоп | Почему |
|---|---|
| «накосячили», «колхозно», «зоопарк», «болтун» | развязность, несолидно |
| «реально», «по-честному» | дворовая интонация |
| «нарвались» / «попали» / «кинули» | негатив-проекция на читателя |
| «без условий», «не берём таких» | высокомерие |

Тон сверять с тональностью брифа (inputs).

## П.4. Метафоры и сравнения

Максимум 1 образное сравнение на страницу, точное и уместное регистру. Лишние / кривые / снижающие смысл - убрать, заменить прямой конкретикой. «Цифра против цифры» (реальное сравнение фактов) - не метафора, разрешена.

## П.5. Штампы (мнение без факта) -> конкретика

| Запрещено | Чем заменить |
|---|---|
| «Индивидуальный подход» | механизм: «Прораб на связи. Каждые 7 часов - фотоотчёт в WhatsApp» |
| «Многолетний опыт» | «9 лет, 300+ проектов» |
| «Профессиональная команда» / «Опытные специалисты» | состав по ролям; стаж + образование |
| «Гарантируем результат» | «метрика X в договоре, превышение - компенсация» |
| «Лучшие на рынке» / «Самые низкие цены» | цифры (доля, клиенты, «экономия до 60 000 ₽ за счёт...») |
| «Полный цикл услуг» | перечень того, что входит |
| «уникальный/лучший/качественный», «широкий ассортимент», «лидеры рынка» | убрать или заменить фактом |
| «Высокое качество по доступным ценам» | вилка цены + что входит |

Плюс: любые формулировки из `forbidden_wordings` (inputs.json) - под запретом наравне со штампами, сверяйся со списком проекта.

## П.6. Самозащита и частица «не»

«Не как у других», «не шаблонное КП», «больше не придётся...», «забудьте о том, что...» - упоминание чужого минуса рождает сомнение. Замена: утвердительный факт о себе ЛИБО «цифра против цифры» («5 дней vs 3 недели»). «Защищены от X» - ок как замена отрицания, но не как выпад в конкурента. Максимум одно «не» на блок. Грамматические формы контраста - в П.14, образ конкурента без контраста - в П.18.

## П.7. Аббревиатуры

В Hero/H1 - 0. Глубже - расшифровка при первом упоминании ИЛИ бытовое слово (SLA -> «время реакции в договоре», CRM -> «система учёта заявок»). Профжаргон ниши («сработка», «облёт», «обвес») - пояснить в скобках или заменить.

## П.8. Манипуляции (тест ФАС)

| Запрещено | Замена |
|---|---|
| Перечёркнутая цена без реальной скидки | честная сравнительная таблица |
| «Только сегодня» без дедлайна | убрать или реальная дата |
| «Осталось 3 места» с выдуманной цифрой | реальный остаток или убрать |
| **Арифметика на лету** (NPS 76% -> «90% рекомендуют») | только исходная цифра из FACTS |
| «Бонус» из того, что и так входит | не подавать как бонус |

## П.9. Цифры = FACTS + плейсхолдеры

Каждое число сверить с `facts.json`. Выведенных арифметикой нет. Чего нет -> `[ЗАПОЛНИТЬ: что именно]`. Заглушки без сленга («ща докрутим» запрещено). Реалистичные числа - только там, где формат сам читается как заглушка (прайс, телефон, email); никогда в «отзыве/кейсе/проценте успеха».

## П.10. Карта повторений

Правило действует **в пределах одной страницы** (ты видишь только её). Каждый факт/УТП <= 1-2 раза на страницу. Дубли «для симметрии сетки» - вырезать. Скидка/акция - максимум в 1-2 местах (одно ценовое сообщение).

Межстраничные повторы (одна и та же формулировка на разных страницах) - **зона `site-reviewer`**, порог там 2+ страниц. Сам их не ищешь и не чинишь.

## П.11. Лимиты длины

- H1 <= 60 символов, без перечислений; метафора/числовой фильтр аудитории - не в H1.
- CTA-кнопка - глагол действия + конкретика, 15-30 символов.
- Плашка Hero: `title` 10-30 символов + `text` 30-90 символов (точные значения - в `limits` блока).
- Предложение внутри слота: ориентир до ~90 символов, жёсткий потолок 20 слов. Длиннее - режь на два, второй кусок получает своё сказуемое.
- **Слоты - по `limits` из blueprint.** Писатель целится в диапазон; ты чинишь выход за допуск **±15% в обе стороны** - и перебор верхней границы, и недобор нижней. Недобор - не безобидно: слот выходит тоньше, чем спроектирована вёрстка.
- **Исключение: срезанный хвост - воду доливать ЗАПРЕЩЕНО.** Если слот ушёл ниже нижней границы потому, что из него срезан лишний хвост (мысль повторена другими словами, объяснение очевидной выгоды, придаточное «чтобы не...»), объём НЕ добирай. Сокращение на 40-70% при срезе хвоста - норма; допуск ±15% относится к перефразированию, а не к резу. Такой недобор фиксируй в `fill_notes` строкой `слот короче лимита: срезан хвост` и не чини.
- `page.description` <= 160 символов.

## П.12. Формула «за счёт» + H2-выгода

`<Вы-польза в цифрах> за счёт <свойство>` - замкнута на свойство. H2 = выгода с цифрой, не ярлык секции («Почему мы?», «О компании» - мёртвые). Тест «по одним заголовкам»: H1+H2 складываются в продающую историю. Заголовок правильной формы, но без сообщения («Найдите свою ситуацию») - отдельный брак, см. П.16.

## П.13. OPSEC + типографика

Деликатные ниши (оборонка/медицина/опасные производства): личность/геолокацию/комплектующие/цифры результатов обезличить и пометить `[требует согласия]`. Типографика: длинное/среднее тире (— –) -> дефис (-); буква ё -> е (правило для всех клиентских текстов, как и запрет тире); эмодзи - не более чем в одном блоке страницы, ни одного в Hero и ни одного в H1/H2 (лишние - убрать); текстовые стрелки в Hero -> SVG кита.

## П.14. Противопоставления -> 0

Шесть форм брака:

| Форма | Пример | Чинится на |
|---|---|---|
| «X, а не Y» | «настроенный на обращения, а не на клики» | «настроенный на обращения целевых клиентов» |
| «не X, а Y» | «не сайт-визитка, а рабочий инструмент» | «рабочий инструмент: заявки с первого месяца» |
| «не просто X» | «не просто дизайн» | назвать, что именно делается |
| «не только X, но и Y» | «Не только заявки, но и продажи» | «Доводим заявки до продаж» |
| «X вместо Y» | «поддержка вместо разовой сдачи» | «Ведём проект после сдачи: 12 месяцев» |
| контрастный хвост через тире | «..., - а не как обычно бывает» | срезать хвост целиком |

- **Синоним контраста - тот же брак:** «в отличие от», «зато», «тогда как», «вместо того чтобы», «не столько... сколько». Замена оборота на синоним не считается правкой.
- **Срезать, а не заменять.** Контрастный хвост СРЕЗАЮТ, а не подменяют нейтральной добивкой той же длины ради лимита: такая замена - промежуточный шаг, который следующий круг всё равно вырежет, и правка делается дважды. Недобор после реза - см. П.11 и П.17.
- **Инвертированную форму «Не X, а Y» греп не ловит** (отрицание стоит первым, «а» - в середине): её проверяешь глазами, по каждой фразе, начинающейся с «не».
- **Два легальных исключения.** (а) Блок-сравнение с двумя колонками: контраст там и есть содержание, но внутри ячейки оборотов «а не» / «в отличие от» не пишем, и чистится только НАША колонка. (б) Сброс ложной категории, когда клиент действительно ожидает не того, что получит («Это не отсрочка - это снятие с учёта»): не больше одного на страницу, только в H1/H2 или первой строке блока. «Мы не как все» под исключение НЕ подпадает - это самопохвала (см. П.6).
- **Граница для «без X»:** «без X» про свои условия работы остаётся («без обязательств», «без процентов»); «без X», описывающее отсутствие чужой плохой практики, - вычищаем.

## П.15. Заочный диагноз читателю

Фраза грамматически утвердительная, стоп-слов нет, а читатель получает диагноз, которого не просил. Это тоньше подачи от отрицания и проходит все прежние фильтры.

| Брак | Замена |
|---|---|
| «Скажем, что мешает одобрению» | «Посмотрим кредитную историю и скажем, на что рассчитывать» |
| «Найдём, где вас обманывают» | «Проверим договор и объясним каждый пункт» |
| «Разберём ваши ошибки в документах» | «Проверим документы перед подачей» |

- **ТЕСТ-ПОДСТАНОВКА:** добавь в конец фразы «...даже если у вас всё в порядке». Получилась бессмыслица - формулировка предполагает проблему, которой читатель не заявлял.
- **Разметка для поиска:** глагол обнаружения (найдём, выявим, покажем, скажем, разберём, вскроем) + «ваш / у вас» + негативное существительное (ошибка, проблема, риск, помеха, отказ). Совпали все три - смотри вручную.
- **Отличие от честного блока боли:** блок боли описывает ситуацию на рынке («половина отказов приходит из-за просрочек, о которых человек забыл»), а не состояние конкретного читателя. Блок боли не трогаем.

## П.16. Пустой заголовок

«Найдите свою ситуацию», «Выберите свой вариант», «Узнайте больше» проходят проверку на форму (есть глагол, есть обращение), но не несут сообщения. Два теста:
1. **Убери заголовок и оставь блок** - читатель потерял информацию? Нет - заголовок пустой.
2. **Поставь этот заголовок над любым другим блоком сайта** - подходит без правки? Значит, он ничего не говорит про ЭТОТ блок.

Чинится не подбором другого глагола, а ответом на вопрос «что читатель узнает из блока». Часто ответ выходит назывным, и это нормально: «Кому нужен подбор» лучше, чем «Найдите свою ситуацию».
**Граница:** обещание-самопохвала в заголовок не идёт - «С нами спокойнее: личное ведение проекта» -> «Личное ведение вашего проекта». Действие клиента проверяемо, похвала себе - нет.

## П.17. Хвосты-досказывания

**Режем хвост**, если он: повторяет мысль первой части другими словами; объясняет очевидную выгоду («и вы экономите время», «вам будет спокойнее»); объясняет, зачем нужно то, что и так понятно; является придаточным цели с отрицанием («чтобы не...», «чтобы X не...») - режется целиком вместе с запятой или тире; дублирует соседнее поле объекта (items, список, колонка).
**Оставляем хвост**, если в нём НОВЫЙ факт: цифра, срок, условие оплаты, состав работ, ограничение, название канала.
**Сокращение на 40-70% при срезе - норма** (эталонный рез: 168 знаков -> 76). Допуск ±15% относится к перефразированию, а не к резу. Недобор нижней границы лимита после реза **доливать водой ЗАПРЕЩЕНО**: фиксируешь в `fill_notes` строкой `слот короче лимита: срезан хвост` и не чинишь (см. П.11).

## П.18. Образ плохого подрядчика и мета-оговорки

- **Образ конкурента убираем ДАЖЕ без грамматического контраста:** «большинство подрядчиков...», «чаще это продают как...», «такое делают единицы», «аккаунт-менеджер в общем чате на сотню аккаунтов». Замена - факт о себе.
- **Разрешено:** нейтральный отраслевой бенчмарк без оценки и без адресата - «Гарантия до 3 лет на всю продукцию (в среднем по отрасли 12-24 месяца)», **при условии, что цифра бенчмарка лежит в `facts.json`**. Нет цифры в facts - убрать.
- **Мета-оговорки удаляем:** «мы не оцениваем конкретные компании», «речь про подходы в целом», «этот текст не про конкурентов» - страховка, которая читается как оправдание ровно в том блоке, который должен отстраивать. Оговорка о собственной легальности остаётся («работаем только в правовом поле»).

## П.19. Профиль голоса, третье лицо, единство обращения

**Профиль выбран один на проект и не меняется от блока к блоку:**
- **личный эксперт** (услуга привязана к человеку, он же лицо бренда; признак в данных - заполнен `facts.json` `jur.brand_face`): обещания и оценка - от «я» («отвечу лично», «разберу вашу ситуацию»), процесс и юридические формулировки - от «мы». Смешение внутри одного блока - брак.
- **компания** (команда, производство, агентство, магазин): везде «мы».

**Третье лицо запрещено в обоих профилях:** «наша компания предлагает», «агентство осуществляет», «напишите Глебу - и он лично разберёт». Исключения: чужая роль в чужой истории, подпись автора, Schema.org.

**Единство обращения.** «Вы» или «ты» - по тональности брифа («ты» не запрещён), и выбранное держится от первой строки до последней на всех страницах. **Проверять по ГЛАГОЛАМ** (-ешь/-ишь против -ете/-ите), а не по местоимениям: в русском местоимение обычно опущено, и поиск по «ты/тебя/твой» пропускает половину брака.
**Где ищем в первую очередь - швы с типовыми блоками:** карточки шагов, финальный CTA, плашки, подписи кнопок, футер. Плюс **метатеги: `title` и `description`** - тоже носители голоса, их проверяют наравне с телом страницы.

## П.20. Канцелярит - второй полюс регистра

Текст бракуют с двух сторон: развязность (П.3) и канцелярит.

| Канцелярит | Замена |
|---|---|
| «в рамках комплексного сотрудничества» | что именно делаем и за какой срок |
| «в соответствии с актуальными трендами» | убрать или конкретный факт |
| отглагольные: «осуществление настройки», «проведение работ» | «настраиваем», «выполняем» |

- **ТЕСТ (работает без заказчика):** слово встречается только в устной речи - дворовое; только в приказе или договоре - канцелярит; норма - то, что уместно в **деловом письме партнёру**.
- **Первая замена почти всегда недостаточна:** «почём каждое» -> «по какой цене» (всё ещё устно) -> «по какой стоимости». Условие остановки - тот же тест.
- **Точность формулировки:** глагол под объект (широкие «собирать/держать/вести» -> точный: «собираем план каналов» -> «составляем план каналов»); сочетаемость («оплаченные специалисты» -> «специалисты, которым платите»); активный залог вместо пассива и безличности («цена честно считается под ваш спрос» -> «цену считаем под ваш спрос»); глагол по возможности первым словом фразы.

## П.21. Бюджет текста

Самая частая претензия по готовым прототипам - «текста слишком много, как будто SEO-сайт делаем». Причина не в длине фраз, а в том, что текст пишется на каждый блок по норме, а не под задачу.

- **Правило.** У каждого текстового фрагмента длиннее одной строки должен быть ответ на вопрос «что он делает для читателя»: какое возражение снимает / какой результат показывает / что доказывает / кого квалифицирует (функция блока, П.1). Нет ответа - фрагмент режется ЦЕЛИКОМ, а не сокращается. Это не «сделай короче»: абзац на 3 предложения, снимающий страх предоплаты, остаётся; абзац на 1 предложение «мы ценим каждого клиента» уходит.
- **Где текста быть не должно:** подводка к блоку, пересказывающая заголовок; подзаголовок под каждым H2 «для симметрии» (подзаголовок ставится там, где заголовок без него непонятен); абзац-предисловие перед списком (список читается сам); пояснение очевидного; повтор факта, уже сказанного выше.
- **Чем заменяется убранный текст** (не переносится, а заменяется другим типом доказательства): абзац про опыт -> строка цифр; описание процесса -> 5 шагов по одной строке; рассказ про качество -> фото производства с подписью; перечисление кому подходит -> логотипы клиентов; объяснение что входит -> список из 4-6 пунктов по 3-5 слов.
- **ТЕСТ ПРОПУСКА:** прочитай страницу, пропуская все абзацы длиннее двух строк. Смысл и путь к заявке сохранились - эти абзацы не нужны.
- Удаление целого текстового слота, предусмотренного blueprint, фиксируй в `fill_notes` и в сводке: состав блоков - зона block-planner.
