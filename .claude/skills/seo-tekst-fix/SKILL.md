# seo-tekst-fix

Точечная правка готового HTML-прототипа. Запускается **в worktree-сессии**. Скелет - как `/fix-article`: разрешить цель -> делегировать фиксеру -> вернуть дифф (не весь файл). Делегат - агент `prototype-fixer` (порт PHASE-7 + паттерн article-fixer).

## Аргументы
```
/seo-tekst-fix <NNN> [<page-slug>] "<описание правки>"
```
- `<NNN>` - номер задачи `texts/NNN-*/`.
- `<page-slug>` - какая страница; если в задаче одна страница - можно опустить.
- `"<правка>"` - описание (может быть расшифровкой голосового, сумбурной).

## Алгоритм
1. **Проверка worktree** (как в /seo-tekst, предупредить если main).
2. Найти `texts/<NNN>-*/`. Если `page-slug` не задан и страниц несколько - спросить какую. Записать `.claude/tmp/current-task.txt = texts/<NNN>-*/`.
3. Убедиться, что `pages/<slug>/manifest.json` и `prototype.html` существуют (иначе подсказать сначала прогнать /seo-tekst).
4. Делегировать `prototype-fixer`: `texts_dir`, `page_slug`, `fix_description`. (expected-маркер `pages/<slug>/prototype.html` - один файл, hook штатно проверит.)
5. Фиксер сам разбирает запрос (при неясности - спросит ДО правки), присваивает каждому пункту метку цены, правит manifest/page.json, пересобирает (`build-prototype.mjs` + `verify-prototype.mjs`), возвращает дифф.

   5a. Если фиксер вернул "полная переделка - нужен page-writer": проверь `texts/<NNN>/blueprints/<slug>.json`. Нет (задача создана до ADR-020) - сначала делегируй `block-planner` (texts_dir, project_root, mode), он создаст `blueprints/`. Затем `page-writer` (texts_dir, project_root, page_slug, mode, page_url для mode B) -> `copy-auditor` + `verify-copy.mjs` -> `prototype-builder` (`build-prototype.mjs` + `verify-prototype.mjs`).
   5b. **Шлюз: тексты правок тоже проходят валидатор.** Правка задела `page.json` - до пересборки прототипа обязателен прогон копи-валидатора:
```
.claude\scripts\_node.cmd .claude\scripts\verify-copy.mjs texts/<NNN>/pages/<slug>/
```
   Exit 2 - прототип не пересобирается. Дальше смотри, ЧТО именно в списке нарушений: строка, начинающаяся с `пол F1`/`пол F2`/`пол F3`/`пол F4`, - это продающий пол, у него свой разбор (5e). Всё остальное - правится ТЕКСТ (фиксер по списку нарушений; три неудачи подряд - `copy-auditor` этой страницы). Фиксер делает прогон сам, оркестратор проверяет, что он был, и повторяет его после ЛЮБОЙ правки текста - **на каждой итерации, а не только перед первой сборкой** (в ветке 5a это штатный шаг цикла). Без этого тексты, написанные на правках, копят ровно те ошибки, ради которых шлюз и делался.

   5c. **Диктовка в продающий слот - только со встречным предложением.** Заказчик продиктовал готовую формулировку в H1, подзаголовок Hero, надпись кнопки или заголовок формы - **оркестратор** (не фиксер) кладёт рядом второй вариант и даёт выбрать: «ваш текст / переписанный по формуле, с той же фактурой». Второй вариант - та же мысль по `blueprints/<slug>.json.page_offer` (нет поля - по `strategy.json.offer_formula_recipe`), без новых цифр и без новых обещаний. Диктовка принимается, но не молча: без этого шага каждый круг правок превращает реплику заказчика в закон без обратного хода. Выбрал свой вариант - дальше по 5d; выбрал переписанный - в `locked` он НЕ попадает (это наша формулировка, `origin: "формула"`).
   Продающий слот - это и есть пол: подзаголовок Hero несёт обещание (F2), надпись кнопки называет, что человек получит (F3). Продиктованный вариант, который пола не проходит, принимается по 5e (б) - с waiver и проговоренной ценой, а не молча и не через правку текста.

   5d. **Вход в `facts.json.lexicon.locked` после сдачи - по основанию.** Пишет **оркестратор**, фиксер `facts.json` не правит. Правка по прототипу попадает в `locked` только по основанию (в) [ADR-037](../../../docs/adr/037-selling-floor.md) п.8: заказчик в круге правок **явно потребовал** сохранить эту формулировку дословно. Формат `{phrase, source}`, где `source` называет и основание, и круг правок с датой: `"клиент-требование, правки по прототипу 21.08"`. Просто прозвучавшая в правке фраза - не основание; реплика из транскрипта созвона - **никогда автоматически**. Основания (а) юридическая или реквизитная формулировка и (б) слоган, самоназвание, торговая марка, авторская врезка работают и здесь.

   **`locked` не пробивает машинные инварианты.** Лимит H1 <= 60, правило «все числа только из `facts.json`», типографика (дефис вместо тире, «е» вместо «ё») действуют и на locked-строку. Не влезает или содержит неподтвержденное число - оркестратор возвращает вопрос заказчику («вот ваша фраза в лимите, подтвердите») и **не легализует нарушение** в `accepted_violations`. Правило «Заказчик важнее свода» этим не отменяется - ограничивается вход и площадь, а не иммунитет.

   5e. **Нарушение продающего пола на круге правок - три исхода, а не один.** Продающий пол ([ADR-037](../../../docs/adr/037-selling-floor.md)) - минимум, ниже которого коммерческая страница не сдается: F1 первый экран, F2 оффер в первом экране, F3 целевое действие, F4 обещание подкреплено. Фиксер такие находки НЕ чинит самовольно - он выносит их в сводку с пометкой, какое решение требуется. Решает **оркестратор**:
   - **(а) текстовое нарушение пола** - подзаголовок Hero без обещания (F2) или надпись главной кнопки из стоп-листа (F3), и правка заказчика этого не требовала: чинится как обычный текст по 5b (фиксер, три неудачи подряд - `copy-auditor` этой страницы).
   - **(б) пол снесен ПРАВКОЙ ЗАКАЗЧИКА** - убрал форму со страницы (F3), снял цену или обещание с первого экрана (F2), потребовал описательный первый экран (F2), снял блок доказательства (F4). Это **не брак, а решение**, и чинить его текстом нельзя: ни фиксер, ни `copy-auditor` состав блоков не меняют. Оркестратор пишет строку в `texts/<NNN>/meta.json`:
```json
"selling_floor_waivers": [
  {"page": "<slug>", "rule": "F3", "why": "<одна строка>", "source": "decisions.<key>.chosen"}
]
```
   `rule` - **одно** правило из `F1`, `F2`, `F3`, `F4`; одна строка waiver = одно правило (перечисление `"F1|F2|F3|F4"` не разбирается). `source` непустой всегда и берется из закрытого списка оснований ADR-037 п.3: решение заказчика (`decisions.<key>.chosen`), дыра в материалах (`strategy.materials_missing[<пункт>]`), ложное срабатывание (`ложное срабатывание: <правило> не применимо к <тип страницы или рецепт>`). Решение принято не на гейте, а в этом круге правок - оркестратор сначала заводит его как решение: пишет `strategy.json.decisions.<key>` (это его файл, `owner: оркестратор`) с дословной цитатой пункта и датой круга (`"убрать форму со страницы, правки по прототипу 21.08"`), и уже на него ссылается `source`. Ссылка в никуда - тот же тихий обход, что и пустой `source`. **Waiver без непустого `source` невалиден** - `verify-copy.mjs` его игнорирует и оставляет нарушение; с валидным правило понижается до предупреждения с пометкой `waiver: <why>`. Ставится он только ПОСЛЕ того, как заказчику проговорена цена, отдельной строкой и до пересборки: «Убираем <что> - страница перестает звать: обещания в первом экране нет / кнопка не называет, что человек получит. Трафик будет тот же, а заявок с этой страницы МЕНЬШЕ. Это ваше право, но подтвердите размен сейчас.» Подтвердил - waiver, пересборка, пункт идёт в сводку и в текст коммита как ЕГО решение. Не подтвердил - слот возвращаем. Waiver ложится в `meta.json` ДО пересборки HANDOFF.md (шаг 6): записка печатает снятые правила пола, и без строки дизайн увидит пустое место без объяснения.
   - **(в) структурное нарушение не по вине заказчика** - первого экрана нет вовсе (F1), ни одного места с CTA (F3), нет ни одного блока функции Д в режиме `рабочий` (F4): это **возврат на предыдущий шаг** (ветка 5a через `block-planner` по этой странице, см. «Эскалация»), а не правка текста и не waiver. Приземлять нечем (F2, в `facts.json` ни публикуемой цифры, ни названного адресата) - вопрос по фактуре заказчику по таблице «обещайте конкретно» (ADR-037 п.6), круг правок не запускается.

   **Нарушение пола НЕ уходит в `accepted_violations`** - это разные сущности (ADR-037 п.3): `accepted_violations` - ложное срабатывание валидатора **вне пола**, `selling_floor_waivers` - осознанный отказ от продающего минимума либо названное ложное срабатывание самого пола. Считаешь находку пола ложной (правило не применимо к этому типу страницы или рецепту) - это тоже waiver, с третьим основанием, и такую строку обязательно вывести человеку в финальной сводке шага 8: снятая жесткая проверка - то, что человек должен увидеть.
6. **Пересобрать HANDOFF.md** - прототип стал новой версией, документ передачи устарел (KIT-SPEC §6.2, ADR-035): порядок блоков и список открытых плейсхолдеров теперь другие, старый HANDOFF уведёт дизайн не туда.
```
.claude\scripts\_node.cmd .claude\scripts\build-handoff.mjs texts/<NNN>-<project-slug>/
```
   Путь - папка задачи целиком (та, что в `.claude/tmp/current-task.txt`), не папка страницы. Шаг пропускается только если прототип так и не пересобрался (шлюз 5b не пройден).
7. Финальный коммит:
```bash
git add -A && git commit -m "Tekst <NNN> fix (<slug>): <короткое описание>"
```
8. Вывести дифф + **финальную сверку правок пункт-в-пункт** + что проверено (вкл. «HANDOFF.md пересобран») + **каждую строку `selling_floor_waivers`, добавленную в этом круге** (правило, причина, основание) - снятый продающий минимум заказчик должен видеть словами, а не находить по падению заявок. Подсказать: ещё правка `/seo-tekst-fix ...` или `/handoff`.

   **Про сверку.** Фиксер возвращает таблицу «внесено / не внесено / отложено» с дословной цитатой по КАЖДОМУ пункту исходного запроса (его шаг 10). Передавай её заказчику как есть, не сокращая и не подменяя пересказом диффа: главное в ней - строки `не внесено` и `отложено`, из-за их молчаливой пропажи и берутся вторые круги правок (в референсном случае из 22-минутного голосового так потерялись три пункта). Проверь по исходному тексту правки, что пунктов в таблице не меньше, чем в запросе; таблицы нет или пунктов меньше - верни фиксеру на досверку, сам её не досочиняй.

## Ответ заказчику: цена правки и порядок исполнения

Правки приходят пакетом и без иерархии - «у Софии фамилия Логинова» и «калькулятор повыше поставить» в одном голосовом. Разницу в цене называем мы.

- Метки (`минута` / `час` / `пересборка`) ставит фиксер у каждого пункта разбора. В ответ заказчику они идут **как есть**, не сглаживаются.
- Смысл меток: увидев `пересборка` рядом с пунктом, заказчик часто отвечает «а, тогда не надо» - это лучший исход. Ответил «все равно надо» - ожидание по срокам уже выставлено ДО работы, а не после.
- **Порядок исполнения пакета:** сначала все `минута` и `час`, `пересборка` - последней. Иначе дешевые правки придется вносить дважды. Ветку 5a не запускай, пока дешевые пункты пакета не внесены.
- Пункт, который заказчик продавил после объяснения (исход «объясняем и держим» у фиксера), выноси в сводку и в текст коммита как ЕГО решение: в следующем круге он часто возвращается к тому, что сам просил убрать.
- Формулировку, продиктованную в продающий слот, не принимай молча - показывай пару «ваш текст / по формуле» (шаг 5c). Заказчик выбирает сам, но выбирает **из двух**, а не подтверждает единственный.

## Эскалация: когда это не правка прототипа

Фиксер вернул один из этих диагнозов - не переспрашивай его и не запускай новые точечные правки, переключай шаг конвейера:

- **«Тексты хорошие, но не тот тон»** - вычиткой не лечится. Это возврат к выбору регистра ([ADR-034](../../../docs/adr/034-text-register.md)): проверь `decisions` задачи, выбирался ли регистр вообще. Не выбирался - прогони гейт выбора регистра из `/seo-tekst` (три первых экрана заказчику), потом уже правки.
- **«Прототип получился пересказом брифа»** - возврат на предыдущий шаг, а не правка текстов страницы. Адресат называет фиксер ([ADR-037](../../../docs/adr/037-selling-floor.md)): нет обещания в первом экране (F2) - `offer-strategist` за формулой оффера, затем `block-planner` -> `slot-mapper` -> `page-writer` по этой странице; нет целевого действия (F3) или нечем подкрепить обещание (F4) - `block-planner` с `pages_subset` = эта страница; приземлять нечем (цифры `publish:"no"`, сплошные `[ЗАПОЛНИТЬ]`) - вопрос по фактуре заказчику, круг правок не запускается. Адресат не назван - верни фиксеру за ним, сам не угадывай.
- **«Пол снесен правкой заказчика»** (фиксер назвал правило F1-F4 и цитату пункта) - НЕ возврат на предыдущий шаг: это исход (б) шага 5e. Оформи `selling_floor_waivers` с непустым `source`, проговорив цену, и веди пересборку дальше.

## Запреты
- Пиши только в `texts/<NNN>/pages/<slug>/`. Kit и чужие страницы - read-only. (Исключения, все внутри папки задачи - pre-commit пропустит: `texts/<NNN>/blueprints/` в ветке полной переделки 5a через block-planner, `texts/<NNN>/facts.json` на шаге 5d, `texts/<NNN>/meta.json` и `texts/<NNN>/strategy.json` на шаге 5e - их правит ТОЛЬКО оркестратор, и `texts/<NNN>/HANDOFF.md` на шаге 6.)
- Согласованные блоки не трогать без переспроса (правило anti-rollback).
- Правка текста не расширяется в структуру: «раз меняем H1, давай и блок переделаю» - это отдельный пункт с меткой `пересборка` и отдельным подтверждением заказчика, а не побочный эффект текущей правки.
- Прототип не пересобирается, пока `verify-copy.mjs` по затронутой странице не прошел (шаг 5b).
- **НЕ отключай продающий пол молча** (F1-F4, [ADR-037](../../../docs/adr/037-selling-floor.md)): правка заказчика меняет ФОРМУ обещания и кнопки, а не их наличие. Обход один - строка `meta.json.selling_floor_waivers` с непустым `source` и проговоренной заказчику ценой (шаг 5e). Через `accepted_violations` нарушение пола не легализуется вовсе.
- **НЕ легализуй нарушение `locked` через `accepted_violations`**: не влезло в лимит H1 или содержит неподтвержденное число - вопрос возвращается заказчику (шаг 5d).
- В `lexicon.locked` не попадает формулировка без названного основания (шаг 5d): реплика в правке - сырьё, а не канон.
- Длинное/среднее тире (— –) запрещено - дефис (-).
- НЕ используй букву ё - всегда пиши е. Правило для всех клиентских текстов и метатегов (как и запрет тире).
