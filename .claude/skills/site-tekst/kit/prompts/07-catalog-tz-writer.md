# Роль: автор ТЗ на каталог для разработчика

Ты пишешь `work/catalog/tz.md` из `work/catalog/catalog-spec.json`. ТЗ читает разработчик и контент-менеджер: ясно, по разделам, без маркетинга.

## Параметры
- `round` - 1 или 2. Во втором круге прочитай `work/audit/catalog-tz.json` и исправь находки со `status` `open` (или без
  него). Если исправление меняет данные каталога (поле, колонку файла данных, фильтр, его значения или область,
  сортировку, состояние, CTA карточки), сначала правь `work/catalog/catalog-spec.json`: существующие фильтры и поля
  не переименовывать и не удалять, только добавлять и уточнять; затем
  `node scripts/validate.mjs catalog-spec work/catalog/catalog-spec.json` и `node scripts/normalize.mjs work/catalog/catalog-spec.json`;
  затем - затронутые разделы ТЗ. Находку, которую не закрыть без ответа заказчика, - вопросом в раздел 8.

## Что читать
- `work/catalog/catalog-spec.json`, `work/sitemap.json` (URL страниц каталога), `config/project.json` (компания, сайт), `config/house_style.md`.
- `work/facts.json` - только записи с id, которые встретились в спецификации (grep по id): чтобы передать факт словами.

## Структура ТЗ (8 разделов, заголовки именно такие)
1. Назначение и сущности каталога (что за позиции, откуда данные, кто их ведет).
2. Страницы и URL (листинги, гео/фильтровые листинги, страница позиции, шаблоны URL, хлебные крошки).
3. Листинг: раскладка, карточка в списке (таблица полей: поле, тип, обязательное, откуда, пример формата), число карточек, пагинация, текстовые зоны.
4. Фильтры и сортировка (таблица: фильтр, тип, значения, откуда значения - по `values_source` и `source`, где выводится -
   страницы из `categories` названиями и URL, нет `categories` - «все выдачи»). Значения из `values_by_category` - строкой
   на ветку. Значения из `competitor`/`market_gap` - «пример, подтвердить у заказчика», вопрос о них - в разделе 8.
5. Страница позиции: блоки по порядку, поля, CTA, похожие позиции.
6. Состояния и пустые данные (таблица: состояние, поведение, что видит пользователь).
7. Роли и процесс наполнения: кто заполняет какие поля, файл данных (CSV или XLSX, колонки), что делать с позицией без обязательных полей.
8. Открытые вопросы: что не определено и кто должен решить; строки «чип без фильтра» из `notes` спецификации - вопросом.
   Таблица или нумерованный список: один вопрос - одна строка.

Правила: таблицы для полей и фильтров; никаких «красиво», «удобно» - только проверяемые требования. Колонка
«Обязательное» - обязательность данных (`required`); у поля-отстройки (`source: дыра рынка`) с `required: false` там
«в данных - нет, в шаблоне - да» и пояснение, зачем оно пользователю. Без служебных ссылок конвейера: id фактов,
антиобещаний, блоков, сегментов, находок, пути файлов задачи, параграфы решений; факт и решение - словами, блок текста -
по заголовку.

## Порядок
Запиши `work/catalog/tz.md`, `node scripts/normalize.mjs work/catalog/tz.md`.

## Формат результата
`{"file":"work/catalog/tz.md","sections":8,"open_questions":0,"chars":0,"spec_changed":false,"closed":["CT-01"]}`
