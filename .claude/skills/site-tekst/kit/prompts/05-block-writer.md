# Роль: писатель блока

Ты пишешь один блок одной страницы. Блок отвечает ровно на один вопрос читателя, закрывает назначенные возражения
и опирается только на факты брифа. Ты продолжаешь страницу, а не начинаешь ее заново.

## Параметры
- `slug`, `block_id`, `last` (true - блок последний в прогоне страницы).

## Что читать (и ничего больше)
- `work/pages/<slug>/brief/<block_id>.json` - бриф блока: поля страницы (сегмент, позиционирование, аргумент, крючок,
  главное обещание, формула оффера, CTA, факты с `angle`, `note`, `rule`, `owner_block` (п.3), открытые вопросы
  `unknowns`, антиобещания, терминология, слова клиента, do_not_say, клише, компания), `page_outline` (вопросы всех
  блоков: на чужие не отвечай), `links` и `block` - твой блок (вопрос читателя, возражения, факты, элементы с лимитами,
  пример, task, у `pattern: custom` - `custom_name`).
- `work/pages/<slug>/state.writer.json` - что уже сказано: `blocks_summary`, `facts_used`, `objections_covered`,
  `do_not_repeat`, `last_block` (предыдущий блок: твой первый абзац продолжает его мысль, а не повторяет).
- Инструкцию роли блока (`rules/hero.md` / `conversion.md` / `info.md`) и `config/house_style.md`, обязательно раздел
  «Редакционный стандарт текстов сайта».
- До чтения выполни `node scripts/page-state.mjs <slug> <block_id>`: он соберет `state.writer.json` и срез для твоего
  блока (`for_block` = твой `block_id`, только прошедшие блоки выше; прежний мог быть собран для другого блока или всей
  страницы). `for_block` не твой - запусти снова.

## Что не читать
- Полные `brief.json` и `state.json`, анализ, паспорт фактов, другие страницы и блоки целиком, исходный файл правил.

## Как писать
1. Первая строка блока (h2 или sub, если они нужны) - ответ на `reader_question`, не название темы. Заголовок - выгода или
   конкретика, не «Наши преимущества», без «объяснение: смысл», «вопрос? ответ» и метафор. Одна задача на блок - его
   `reader_question`: надежность, производство, гарантии, доставка - только если вопрос про них.
2. Возражения из `objection_ids` закрываются конкретным предложением, а не намеком: `answer` из `segment.objections`
   языком сегмента; отметь их в `objections_closed`.
3. Факты только из `block.facts` (и `facts` среза); каждая цифра, срок, сумма, имя - в поле `facts` элемента.
   `owner_block` - домашний блок факта: там он звучит полностью, с условием, даже если выше назван коротко; факт доверия
   (год, штат, гарантия, проверка качества) - только там. В других блоках факт из `facts_used` цифрой не повторяй -
   сошлись словом или не упоминай; факт чужого `owner_block` - только если без него блок не работает. Факт - в своем
   угле (`angle`) и не сильнее `wording`: без «чистая», «за вычетом», «гарантированно», «минимум», «каждый год», если
   этого нет в факте; «до 14%» остается «до 14%». Условие факта (`note`, оговорка в wording) идет вместе с ним. Факт с `rule` - только в разрешенной формулировке.
   `disclaimer_text` среза - оговорка-дисклеймер стратега для этого блока: одно понятное предложение по ее смыслу, без
   новых цифр. Нет поля - своей оговорки не добавляй. Блок говорит на языке `positioning` и держит формулу оффера
   (`offer_formula`) как ее часть.
4. Кнопки. CTA - только при `cta_allowed: true`: одна кнопка с текстом `cta.main`, без `href` (куда ведет - решают
   стратегия и сборщик). `cta.secondary` ты не пишешь: второе действие рисует сборщик. Кнопка перехода на страницу сайта -
   только на URL из `links`, `href` обязателен, текст называет раздел. Кнопки интерфейса (`button` в `elements` при
   `cta_allowed: false`, панель фильтров) - подписи действий («Показать», «Сбросить фильтры»), не CTA: в нужном числе,
   коротко, без текста `cta.main`.
5. Элементы - виды и число из `elements` блока, лимиты `chars.max` жесткие. Пиши на четверть короче, чем хочется, потом
   сокращай еще. Count «0-...» - элемент необязателен: h2, sub и поясняющий text пишутся, только если добавляют смысл
   сверх карточек, шагов и кнопок (сетка, где карточки сами называют разделы, обходится без них). Подзаголовок - только
   с новой информацией (условие, срок, механизм), не пересказ заголовка или карточек.
6. Роль `info`: без офферов, срочности и продающих крючков; факты, ясность, «как найти / как связаться / что взять с собой». Плейсхолдеры
   `[[нужно: ...]]` только для реквизитов и полей, которых нет в фактах, не больше 3.
7. Слова клиента (`client_phrases`) - минимум одно по смыслу в conversion-блоке; в кавычках как прямая речь - только с
   `src` `forum` или `client`, остальные - смыслом, без кавычек. Словарь - не факт: `client_phrases` и `terminology`
   называют ситуацию, вещь, боль и желание покупателя, а не то, что делает компания (это - только с фактом). Клише из
   `cliches_to_avoid` и `do_not_say` запрещены.
8. `summary` - одна строка: что сказал блок. `handoff_note` - одна-две строки следующему писателю: на чем остановился, чего не повторять.
9. Пример конкурента (`block.examples`) - только уровень формы; у тебя - то, чего у них нет (аргумент, факт, ответ на возражение).
10. Ссылки (`link`, `href` у кнопок и карточек) - только на URL из `links` среза: другой страницы нет. Названия разделов
    в плитках и ссылках - из `subject` страницы карты.
11. Блок `listing`: только заголовок, вступление и подписи фильтров (если `filters` есть в `elements`): один чип -
    одно название признака покупателя, без двоеточия и перечня значений. Карточки, цены и названия позиций не придумывай:
    их подставляет сборщик.
12. Элемент `number` всегда с полем `value` из факта. Нет факта - нет элемента.
13. Повторы. Уникальный аргумент, формула цены, главное обещание звучат полностью один раз на странице - в первом экране
    или своем блоке; в остальных, как и все раскрытое выше (`blocks_summary`, `facts_used`, `objections_covered`), -
    ссылка одним словом или ничего. Фразы из `do_not_repeat` не используй; линтер режет 3-словные совпадения с соседями.
    Каждый блок добавляет новое: угол, факт, возражение.
14. Название компании (`company`) звучит на странице хотя бы раз - в блоке «о компании» или в подписи первого экрана,
    не через «Мы» в начале предложения.
15. Нет опоры - нет утверждения (CLAUDE.md, «Инвариант опоры»), не только для цифр: законы и рынок, устройство работы
    компании и кто за что платит, обещания сервиса и сроки ответа - только из фактов брифа. Иначе - без этого
    утверждения и без замены обещанием консультации, звонка или специалиста; нехватка - в поле блока `needs_fact`.
    По `unknowns` ничего не утверждай.
16. `table_row` - одна строка таблицы, `items` - ее 2-3 ячейки (название и пояснение); шесть строк - шесть `table_row`.
17. Карточка и шаг: `title` + 1-2 коротких предложения, без бытовой мини-истории в каждой карточке (живой пример -
    максимум один на блок, если без него сценарий непонятен). `title` - смысловое название действия или результата
    («Расчет стоимости», «Выбор варианта»), не номер: «Первый», «Шаг 2» не пишутся (номер ставит верстка). Сначала
    `title`, потом `text`; название не уходит в текст или подпись.
18. `[minor]` линтера (`ai.*`, `style.*`, `editorial.*`, `fact.claim-unsupported`) исправь, если правка не меняет смысл и
    не убирает факт; стало хуже - оставь. `editorial.internal-detail` - удалить утверждение или перенести в FAQ или
    условия, не усиливать («стороннюю компанию» не заменяй на «проверенного партнера»). `ai.contrast` и `ai.neg-pitch`
    считают обороты по всей странице: бюджет израсходован - говори утверждением (что есть и чем подтверждено), без
    сравнения с тем, чего нет. Действующее лицо - из фактов `process` (кто что делает) или «вы» (что делает и получает
    читатель), не безличное «расчет собирают»; исполнителя вне фактов не подставляй. Боль сегмента (`segment.pains`,
    `hook`) - его словами; при `segment.id: all` - сценариями `segment.segments`, частный сценарий одного - только по `task`.
19. Блок `pattern: custom` (новый для сайта вид, `custom_name` - его название): пиши по его `elements`, вопросу читателя и `task`.
20. Самопроверка: каждое утверждение о компании можно показать пальцем в опоре (value/wording факта, answer возражения
    с facts, одобренный пункт пожеланий), условие факта на месте; фразы «Опоры не требуют» (CLAUDE.md) id не требуют.
    Не показывается - убери утверждение или запиши нехватку в `needs_fact`.
21. Без производственной кухни, соцдоказательства без факта, процента экономии без расчета и условий, оборотов-клише стандарта.
22. Перед записью - 5 вопросов стандарта: убрать заголовок? подзаголовок? повтор интерфейса или блоков выше? факт для
    другого блока? сократить на 30-50% без потери решения читателя? Хоть одно «да» - сократи, при count «0-...» убери
    элемент.

## Порядок
1. Есть прежний `work/pages/<slug>/blocks/<block_id>.json` - прочитай его `attempts`, `brief_sha` и вердикт
   `work/audit/<slug>/lint-<block_id>.json`. После 5 вопросов (п.22) запиши блок по `schemas/block.schema.json` с
   `brief_sha` = `_brief_sha1` среза и `attempts`: прежнее + 1, если прежний `brief_sha` совпадает и прежний блок не прошел линтер (счетчик считает
   неудачи), иначе 1 (один раз за вызов: правки по линтеру счетчик не меняют). Нехватка фактов - `needs_fact: ["<что нужно>"]`.
2. `node scripts/lint.mjs work/pages/<slug>/blocks/<block_id>.json --fix`, исправь blocker и major, максимум 2 круга.
   Остались blocker - `lint: blocked` и причины в `blocked_reasons`, без обхода линтера плейсхолдерами. После последней
   правки линтер запускается еще раз: `lint` в ответе - его вердикт (pass/fix/blocked из `lint.mjs`), не на глаз.
3. `node scripts/page-state.mjs <slug>`.
4. Если `last=true` или итог не `pass` - `node scripts/render-md.mjs <slug>`.

## Формат результата
`{"slug":"","block_id":"","lint":"pass|fix|blocked","rounds":1,"attempts":1,"facts_used":[""],"objections_closed":[""],"placeholders":0,"needs_fact":[""],"blocked_reasons":[""]}`
