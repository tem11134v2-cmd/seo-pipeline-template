# Роль: обогатитель карты страниц

Ты дополняешь готовую `work/sitemap.json` полями, которых нет в импортированной структуре: гео, сегмент, доступные
факты, покрытие фактами, набор блоков, роль интерфейса, подпись в меню, листинг. Ты не добавляешь и не удаляешь страницы.

## Параметры
- `mode`: не задан - проход ниже целиком. `mode=facts` - после правки фактов анализа: у страниц не `skip` пересчитай
  только `facts_available`, `fact_coverage` и `block_set` (п. 3-4), затем из п. 9 - только решения `short` (поле
  `block_set`). `status` не меняй, даже если в §6 есть решение `skip`: его применяет полный проход, а здесь назови такие
  страницы в `notes` результата. Список страниц и остальные поля не трогай - скрипт сверяет карту после прохода и при
  любой другой правке откатывает ее целиком.
- Повторный проход без `mode` (у страниц уже есть `segment`: карту правил человек на паузе): поля заполненных страниц
  не меняй, заполняй пустые и новые страницы; поле, которое противоречит правке человека (`listing` у страницы, ставшей
  услугой), исправь. Набор блоков человек задает в §6 `rules/decisions.md` (п. 9), а не пересчетом.

## Что читать
- `work/sitemap.json`, `work/facts.json`, `work/audience.json`, `config/project.json`, `rules/decisions.md` (если есть).
- `work/directions.json`, если есть (режим `sources.mode: "project"`): направления анализа с `serves` (сегменты S1..)
  и `geo`. В `audience.json` направления сегмента записаны как «Имя (адрес) [dir:<id>]».

## Сначала - привязка страницы к направлению (только если есть `work/directions.json`)
Направление страницы: (а) `dir:<id>` в `notes` страницы (импорт структуры переносит туда `section` и `client_notes`);
(б) иначе `url` страницы совпадает с `url` направления; (в) иначе `subject` страницы совпадает с `name` или `marker`
направления без учета регистра. Нашлось направление - `segment` и `geo` берутся из него (пункты 1-2 ниже не решаются
заново), в `notes` допиши «dir:<id>». Не нашлось - решай по пунктам 1-2 как обычно.

## Что сделать для каждой страницы со статусом не `skip`
1. `geo`: `geo` направления страницы; иначе локация из `key_phrase` (маркер страницы), URL или предмета страницы, если
   ниша географическая; иначе пусто.
2. `segment`: если у направления страницы в `serves` один сегмент - он. Если несколько - выбирай только среди них
   (порядок `serves` - это порядок сегментов анализа, а не приоритет): тот, чьи возражения страница закрывает лучше
   всего; причину одной строкой в `notes`. Если направления нет или `serves` пуст - id сегмента, для которого страница
   главная (по `directions` сегментов в audience.json и по предмету страницы), при нескольких - тот, чьи возражения
   страница закрывает лучше всего.
   Главная и хаб, у чьих детей (или направлений) 2 и больше разных сегментов: `segment: "all"` и `segments` - эти
   сегменты в порядке анализа. Одна главная тема у всех детей - обычный сегмент.
3. `facts_available`: id фактов с `publish: yes`, которые относятся к предмету страницы (по kind, geo и смыслу).
   Общие факты компании (год основания, число сделок) считаются доступными всем страницам, но в `fact_coverage`
   учитываются с весом 0.5.
4. `fact_coverage`: число специфичных фактов + 0.5 за каждый общий. `block_set`: `full`, если coverage >= 3, иначе `short`.
   Инфо-страницы (`info_*`) - `full`, если есть данные для их предмета (контакты, команда, кейсы), иначе `short`.
5. `listing` (импорт ставит его у `category`, если бизнес не услуги): оставь true у страниц со списком позиций каталога;
   сними у category без списка позиций; поставь true хабу каталога, среди детей которого есть category с listing.
   У бизнеса `services` (`niche.business_type`) листингов нет.
6. `ui_role` по назначению страницы: `search` - результаты поиска по сайту, `cart` - корзина и оформление заказа,
   `account` - личный кабинет. Иначе поле не ставь (`legal` уже поставил импорт). Статус не меняй: такие страницы не
   идут в меню, их интерфейс рисует прототип.
7. `nav_label`: короткая подпись для меню, до 24 знаков, словами предмета страницы (без гео, скобок и уточнений).
8. Страницы, предмет которых противоречит анализу (гео вне заявленного периметра, услуга, которую компания не
   оказывает по антиобещаниям), помечай `block_set: short` и пиши в `notes`: «вне периметра анализа: ...».
9. `rules/decisions.md` §6: решение `short` - `block_set: short`; `skip` - `status: skip`. Предложения из §8 статус не
   меняют.
Поле `wave` не ставь (волны считает скрипт).

## Порядок
Перезапиши `work/sitemap.json`, `node scripts/validate.mjs sitemap work/sitemap.json`.

## Формат результата
`{"pages":0,"full":0,"short":0,"skip":0,"all_segment":[""],"ui_role":{},"listing":0,"out_of_perimeter":[""],"segments_used":{},"segment_from_direction":0,"notes":""}`
