# FAST.md - быстрый режим `/seo-statya --fast`

Отдельный короткий пайплайн для больших объёмов (30-100+ статей): текст +
метатеги + HTML, без фото/enhancer/schema.org/docx/Drive/Тильды и без
LLM-аудита. JM используется по минимуму - `jm_text_analyze` (анализ
конкурентов, ~5 лимитов + 5-6 мин, самое дорогое и медленное звено полного
конвейера) в этом режиме не вызывается вообще. Один агент (`fast-writer`)
пишет статью целиком за один проход вместо связки tz-builder +
section-writer(×N) + article-finalizer.

Вызывается из SKILL.md, шаг 0b, при флаге `--fast`. Этот файл читается
целиком и выполняется вместо шагов 0c-15 SKILL.md - к ним не возвращаться.

Полный state machine, `meta.json`, `update-meta.sh`, `batch-queue.mjs`,
`assemble-html.mjs`, `verify-article-metatags.mjs` этого режима не трогает -
всё переиспользуется как есть, только короче по числу шагов.

## Аргументы

```
/seo-statya <N | N-M | N,M,K | "тема текстом"> --fast
    [--query="<основной запрос>"] [--genre="<жанр>"] [--words=N] [--resume]
```

- `N` - номер/диапазон/список из `topics.xlsx` (как в full-режиме) ИЛИ
  свободный текст темы (определяется в SKILL.md шаг 0b по регэкспу
  `^[\d,\-\s]+$` - если не матчится, это свободная тема).
- `--query="<основной запрос>"` - только для свободной темы: явный целевой
  запрос. Если не передан, `main_query` = сама тема (для длинных
  формулировок это даст низкую/нулевую частотность в кластере JM - лучше
  передавать `--query`, но прогон не блокируется без него).
- `--genre="<жанр>"` - как в full-режиме для веток из xlsx; для свободной
  темы по умолчанию `"Экспертный разбор"`.
- `--words=N` - целевой объём статьи, слов. По умолчанию `1000` (допуск
  ±20%, то есть 800-1200).
- `--resume` - как в full-режиме: прочитать `meta.state`, продолжить с
  этого шага. Работает одинаково для обеих веток.

Диапазон/список (`N-M`, `N,M,K`) работает **только** для тем из
`topics.xlsx` - см. «Серийный режим» ниже. Свободная тема - всегда
одиночный прогон, не участвует в батче.

## Шаг 0. Определить источник темы, завести задачу

### Ветка A - тема из `topics.xlsx`

Полностью переиспользовать шаги **1, 1a, 1b** SKILL.md (full-режима) без
изменений: тот же `read-topics-xlsx.mjs --by-number N`, тот же
`topic_id = N`, та же логика коллизии жанра/площадки по `articles/_index.json`
(шаг 1a), та же схема папки `articles/<TTT>-<slug>-<rand3>/` (шаг 1b). Не
дублировать эту логику здесь - выполнить её как есть.

Отличие только в двух местах:
- `main_query = topic.main_query` (как обычно).
- Дальше выполняется этот файл (FAST.md), а не шаги 2-15 SKILL.md.

### Ветка B - свободная тема (freeform)

**Не выдумывать синтетический `topic_id` через `max+1`.** Это вернуло бы
гонку счётчика между параллельными worktree - ровно то, что архитектура
full-режима сознательно избегает (см. SKILL.md, шаг 1b: «номер папки =
номер темы, НЕ max+1»). Вместо этого:

- `topic_id = null`.
- `slug` - через существующую функцию `slugifyBase` из `_slug.mjs` (НЕ
  `buildSlug` - та обрезает коммерческие стоп-слова под URL посадочных
  страниц, не годится для темы статьи). Готовый паттерн вызова (уже
  используется в `custom-question/SKILL.md`):
  ```
  node -e "import('./.claude/scripts/_slug.mjs').then(m=>console.log(m.slugifyBase(process.argv[1])))" "<тема>"
  ```
- Папка: `articles/fast-<slug>-<rand3>/` (`rand3` - те же 3 случайные
  строчные латинские буквы, что в full-режиме, та же проверка на
  отсутствие коллизии перед созданием). Никакого числового префикса -
  темы нет в `topics.xlsx`, не притворяемся, что есть номер.
  - `resolve-article-dir.mjs` (используется только `--rebuild-docx`, в
    fast-режиме не задействован) матчит и по литеральному имени папки -
    для freeform это не проблема.
  - `assemble-html.mjs` при отсутствии `^(\d{2,4})-` в имени папки просто
    называет выходной файл `output-000.html` внутри этой же папки -
    безвредно, каждая статья в своей директории, коллизий с другими
    статьями нет.
- `main_query` = `--query="..."` если передан, иначе сама тема.
- `genre` = `--genre="..."` если передан, иначе `"Экспертный разбор"`.
  Коллизии жанров тут нет по определению - нет строки xlsx с несколькими
  вариантами, каждая freeform-статья самодостаточна.
- Создать `dir/` (без `sections/`, `photos/` - в fast-режиме их не будет).
- Freeform **не интегрируется** с `batch-queue.mjs` - только одиночный
  прогон. Если пользователь передал одновременно свободную тему и
  диапазон/список - это ошибка ввода, сообщить и остановиться, не гадать.

### Общее для обеих веток - `meta.json`

Тот же формат, что в full-режиме (SKILL.md, шаг 1b), плюс два новых поля:

```json
{
  "topic": "...",
  "topic_id": <N (число, ветка A) или null (ветка B) - JSON-литерал, без кавычек>,
  "query": "<main_query>",
  "slug": "...",
  "genre": "...",
  "platform_target": "site",
  "mode": "auto",
  "pipeline": "fast",
  "source": "topics.xlsx | freeform",
  "state": "init",
  "completed_steps": [],
  "started": "<ISO UTC>",
  "updated": "<ISO UTC>"
}
```

`pipeline: "fast"` - новое поле, отсутствие у старых статей = `"full"`
(обратная совместимость: `update-meta.sh`, `verify-article-metatags.mjs`,
`resolve-article-dir.mjs`, `batch-queue.mjs` полностью generic и не
валидируют состав ключей `meta.json`, лишнее поле для них прозрачно).

**Обязательно, как в full-режиме (SKILL.md шаг 1b) - иначе pre-commit
заблокирует коммит папки:**
- Дописать путь к `dir/` в `.claude/tmp/current-task.txt`
  (append-if-missing, НЕ перезапись - в серии там накапливаются папки
  всех тем батча). Ownership-скоуп pre-commit хука (`.claude/git-hooks/
  pre-commit`) работает по префиксу пути ИЗ ЭТОГО ФАЙЛА, не по
  числовому NNN - freeform-папка `fast-<slug>-<rand3>/` разрешается
  точно так же, как обычная `TTT-slug-rand3/`, если путь туда записан.
- Перезаписать `.claude/tmp/current-article.txt` одной строкой = `<dir>`
  (активный указатель для SubagentStop-хуков; в fast-режиме `fast-writer`
  не привязан к именному хуку, но указатель поддерживаем для
  единообразия и на случай будущих хуков).

`update-meta.sh <dir> init`.

## Шаг 1. JM-lite (если `state == "init"`)

Два независимых пути переиспользования кеша - **не путать между собой**:

**Путь 1 (уже существует в full-режиме, используем как есть)** - шаг 2
SKILL.md: совпадение по `topic_id` в `articles/_index.json` → копируются
ВСЕ 4 файла `jm/*.json` (`cluster.json`, `lsi.json`, `analyze.json`,
`stop-domains.json`) в `<dir>/jm/`. Работает только для ветки A (у
freeform `topic_id = null`, совпадений по построению не будет).

**Путь 2 (новый, для fast)** - совпадение по нормализованному
`main_query` среди **любых** записей `articles/_index.json` (full или
fast режима), у которых есть непустой `query` и существующий
`jm/lsi.json` по их `article_dir`:

1. `.claude\scripts\_node.cmd .claude\scripts\rebuild-index.mjs articles`
   (освежить индекс, дёшево).
2. Прочитать `articles/_index.json`. Нормализовать `main_query` этой
   статьи и `query` каждой записи индекса: lowercase, `ё`→`е`, схлопнуть
   пробелы, trim (та же нормализация, что `norm()` в
   `verify-article-metatags.mjs`).
3. Отфильтровать записи: **исключить запись самой текущей статьи**
   (`key == <dirName текущей папки>` - она уже попала в индекс через
   `update-meta.sh <dir> init` на предыдущем шаге, тривиально совпадёт
   сама с собой по `query`, но своего `jm/lsi.json` у неё ещё нет).
   Среди оставшихся совпадений по нормализованному `query` перебрать по
   порядку и взять **первую**, у которой физически существует
   `articles/<key>/jm/lsi.json` (не первое совпадение вообще - могут
   быть более старые записи без JM-данных).
4. При найденной - скопировать **только** `cluster.json` + `lsi.json` в
   `<dir>/jm/` (НЕ `analyze.json`/`stop-domains.json` - их может не быть
   у fast-источника, а full-источнику они fast-режиму не нужны).
5. `update-meta.sh <dir> jm-done`, к шагу 2.

**Если ни путь 1, ни путь 2 не сработали** - делегировать `jm-analyst` с
новым входным параметром `depth: "lite"`:

```
main_query: <...>
region_code: <как в full-режиме, из ЗАКАЗЧИК.md>
article_dir: <dir>
project_root: <...>
depth: "lite"
```

Маркер: `.claude/tmp/expected-jm-analyst-<run_id>.txt = <dir>/jm/lsi.json`.

При `depth: "lite"` агент выполняет только Шаг A (кластер 9 запросов) и
Шаг B (`text_generate`, ~15 лимитов) из своего обычного пайплайна и
останавливается - без Шага C (10-й запрос под анализ конкурентов), Шага D
(стоп-лист), Шага E (`text_analyze`). См. `jm-analyst.md`.

`update-meta.sh <dir> jm-done`.

## Шаг 2. Статья (если `state == "jm-done"`)

Маркер (**обязательно** - у `fast-writer` нет именного SubagentStop-хука,
как `check-section.sh`/`mark-finalized.sh` у section-writer/
article-finalizer; без маркера общий `"*"` → `check-file.sh` молча
пропустит проверку, `.claude/settings.json`):

`.claude/tmp/expected-fast-writer-<run_id>.txt = <dir>/article.md`

Делегировать `fast-writer`:

```
article_dir: <dir>
topic: <topic>
main_query: <main_query>
genre: <genre>
target_words: <--words= или 1000>
project_root: <...>
```

После возврата - **вручную** `update-meta.sh <dir> written` (у
`fast-writer` нет `mark-finalized.sh`-аналога, оркестратор проставляет
состояние сам, хук его не проставит).

## Шаг 3. Верификация (если `state == "written"`)

1. **Файлы существуют.** Маркер `check-file.sh` в шаге 2 сторожит только
   `article.md` (это указано в маркере), НЕ `metatags.json`/`report.md`.
   Проверить, что все три файла - `<dir>/article.md`, `<dir>/metatags.json`,
   `<dir>/report.md` - записаны. Если какого-то нет: ре-делегировать
   `fast-writer` с пометкой «article.md/metatags.json/report.md - все три
   обязаны быть записаны через Write по абсолютным путям» (лимит 2
   ре-делегации; при исчерпании - стоп, попросить пользователя проверить
   вручную).
2. `.claude\scripts\_node.cmd .claude\scripts\verify-article-metatags.mjs <dir>`
   - переиспользуется как есть (самодостаточен: читает только
   `metatags.json`+`article.md`).
   - exit 2 → ре-делегировать `fast-writer` с точечной пометкой что
     поправить (лимит 2 повтора; при исчерпании - предупреждение в чат,
     продолжить).
   - exit 1 → `metatags.json` не записан И в `report.md` нет секции
     «## Метатеги» (у fast-режимного `report.md` там только «## Плитка
     тегов», это ожидаемо - fallback не сработает). Это тот же случай,
     что п.1 «файлы существуют» пропустил бы, если `metatags.json` возник
     позже - вернуться к п.1, не считать за отдельный неопределённый сбой.
   - exit 0 → дальше.
3. `.claude\scripts\_node.cmd .claude\scripts\verify-fast-style.mjs <dir>`
   - новый скрипт: буква `ё`/`Ё` или тире `—`/`–` в `article.md`. exit 2
   → ре-делегировать `fast-writer` на точечное исправление (лимит 2,
   дальше - предупреждение и продолжить). exit 0 → дальше.

## Шаг 4. Сборка HTML (если верификация шага 3 прошла)

```
.claude\scripts\_node.cmd .claude\scripts\assemble-html.mjs <dir>
```

Без изменений в самом скрипте - он уже переносит отсутствие
`enhancements.html`/`faq.html`/`schema.json`/`photos/urls.json` как пустые
блоки. Минимальный `report.md` от `fast-writer` (раздел «Плитка тегов»)
даёт блок внутренней перелинковки в футере HTML.

`update-meta.sh <dir> assembled`.

## Шаг 5. Финал

`update-meta.sh <dir> completed`.

Короткое сообщение (без большого баннера full-режима):

```
✓ Быстрая статья готова
Тема: <topic>
Жанр: <genre>
Объём: ~<N> слов

📄 Текст: <dir>/article.md
🌐 HTML:  <dir>/output-*.html
```

**В серийном режиме** (батч) - не печатать баннер, вывести одну строку и
вернуться в цикл (по аналогии с full-режимом, SKILL.md шаг 14).

## Серийный режим (`--fast` + диапазон/список)

`/seo-statya 11-20 --fast` работает по тому же циклу `batch-queue.mjs
init/next/set/status`, что full-режим (SKILL.md, раздел «Серийный
режим») - движок полностью generic по `topic_id`, не завязан на
конкретные состояния статьи. Разница только в теле цикла: вместо шагов
1-14 SKILL.md для каждой темы выполняются шаги 0-5 этого файла.

Серийный финал (SKILL.md шаг 15 / REFERENCE.md `#serial-final`)
переиспользуется без изменений: `build-articles-xlsx.mjs` берёт данные из
`manifest.json`, который строит `export-articles.mjs` из `meta.json` +
`metatags.json` - `report.md` в этой цепочке не участвует вообще, так что
минимальный fast-режимный `report.md` ничего не ломает.

Только числовой spec участвует в батче - свободная тема всегда одиночный
прогон (см. Ветка B выше).

## Запреты

- Все запреты full-режима действуют и здесь: дефис вместо тире, «е» вместо
  «ё», не пропускать `update-meta.sh` на каждом шаге, не push, не
  публиковать HTML.
- Не вызывать `jm_text_analyze` в fast-режиме ни при каких условиях -
  анализ конкурентов сюда не входит (решение пользователя, см.
  ADR-030).
- Не путать путь 1 (копирование по `topic_id`, 4 файла) и путь 2
  (копирование по `main_query`, 2 файла) кеша JM - см. Шаг 1.
- Не ставить метки `[ФОТО:]`/`[ТАБЛИЦА:]`/`[ДИАГРАММА]`/`[ЦИТАТА]`/
  `[ИКОНКИ:]`/`[ТАБЫ:]` в fast-статьях - фазы 4 (фото/enhancer) здесь нет,
  метки нечем заполнить.
- Не выдумывать синтетический числовой `topic_id` для свободных тем (см.
  Ветка B) - только `null` + непронумерованная папка `fast-<slug>-<rand3>`.
