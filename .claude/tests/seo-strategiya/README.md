# Тесты `/seo-strategiya` - гейт, модель прогноза, смета, docx

Регрессионный набор скриптов стратегии: механический гейт `verify-strategy.mjs` (шаг 6.5а), модель
прогноза и экономики (`_forecast-model.mjs`, легаси `_forecast-money.mjs`), каталог услуг (`_services.mjs`),
шаг прогноза `build-forecast.mjs` (5.5), сборщики сметы `build-smeta-xlsx.mjs` и стратегии
`build-strategy-docx.mjs`. Два формата живут рядом (Р11 программы
`docs/upgrade-program-2026-10-06-strategy-v2.md`): старые стратегии пересобираются старыми путями, новые идут
по v2 - поэтому в наборе есть и легаси-кейсы, и кейсы v2.

104 теста в трех разделах.

## 3. v2 (программа 06.10.2026) + модель v2.1 (второй круг) - 77 тестов

Три фикстуры, все синтезируются в `run.mjs`:

- **Опорная** (`V2_FI`): сайт услуг с нормальной базой (400 визитов, 12 коммерческих страниц, структура даст еще 12),
  локальный бизнес с карточкой, конкуренты 1 800 / 6 000. Тарифы вложены по RULES.md: Рост = Старт + PA/SY/KP +
  Карты (MT заменен на SY), Максимум = Рост + FQ/IT/статьи/ссылки (PF -> PFP, ART -> AR), акция ПФ 1=2 во всех
  тарифах с ПФ, `site_dev` - многостраничник на 30 страниц. Гейт пройден, тариф плана - Рост.
- **Новый сайт** (`V2_NEW_FI`, по боевому прогону potolki-sochi): трафика и страниц нет, точный спрос 178,
  конкуренты 129 / 207, `domain: none`. Старт = PA + SY + KP + PF, Рост = Старт + FQ + LB, Максимум - PFP + LA,
  разработку рекомендуем, разработчик клиента -> запуск к 3-му мес. Рост за 12 мес в минусе -> гейт не пройден
  (exit 3), `recommended_offer` и `plan_tariff` = Старт.
- **Упор в потолок** (`CAP_FI`): точный спрос ниже текущего трафика, структура на 200 страниц во всех тарифах -
  кривые упираются в мягкий потолок к 3-му мес и почти совпадают.

Формулы сметы `exceljs` не считает, поэтому в наборе свой мини-вычислитель (SUM, MAX, MIN, COUNT, IF, AND, ROUND,
ROUNDUP, FIXED в русской локали, INDEX, SUMPRODUCT, склейка строк `&`, ссылки и диапазоны между листами): он
пересчитывает формулы прямо из xlsx и умеет подменять ячейки параметров. `exceljs` при чтении теряет кэш 0
(`<v>0</v>` -> `result` undefined), поэтому наличие кэша у каждой формулы проверяется по XML листов, а
`fullCalcOnLoad` - по `xl/workbook.xml`. Цикл сделки в модели задается `CAL.sales_lag_months` по типу бизнеса:
тест сметы на время сверки подменяет его и возвращает обратно. `document.xml` читается через `jszip`.

## Как запустить

Из корня проекта:
```
.claude\scripts\_node.cmd .claude\tests\seo-strategiya\run.mjs
```
Exit 0 = все ок. Exit 1 = хоть один тест упал (вывод покажет где). Прогон около 30 секунд.

Фикстуры синтезируются прямо в `run.mjs`, внешних файлов нет. Песочница -
`.claude/tmp/seo-strategiya-test/run-<pid>`: у каждого прогона своя папка, параллельные прогоны не стирают
друг другу файлы. Зеленый прогон убирает свою папку, красный оставляет для разбора (путь в конце вывода);
брошенные папки старше 2 часов убирает следующий прогон.

## Когда запускать

- После правок в `verify-strategy.mjs`, `build-forecast.mjs`, `_forecast-model.mjs`, `_services.mjs`,
  `build-smeta-xlsx.mjs`, `build-strategy-docx.mjs`, `_forecast-money.mjs`.
- После правок стоп-листа воды в `strategy-writer.md` (стоп-лист скрипта - дословная копия).
- После перекалибровки модели (`CAL`, `ECON_DEFAULTS`): пороги отношений Старт/Рост в тестах модели
  отражают замысел программы - если они падают, это вопрос к калибровке, а не к тесту. То же для фикстуры
  нового сайта: по замыслу Рост за 12 мес в минусе и гейт не пройден (план по Старту), а кривая растет до 12-го
  мес под мягким потолком по лидеру конкурентов.
- Перед PR / push.

## Что НЕ покрыто (живые агенты, проверяется вручную или агентом)

- Смысловая сверка чисел прозы с источниками (metrics/competitors/serp/data/`forecast.json`), вердикт против
  данных, «кто внедряет» - это `strategy-verifier`.
- Качество `forecast_inputs` (что агент правильно снял спрос, страницы, t0) - `growth-strategist`;
  сборка тарифов по правилам и круг пересборки после exit 3 - `tariff-architect`.
- Вид docx глазами (влезает ли раздел на страницу, как Google Docs конвертирует таблицы) - по
  `docs/design-strategy-docx.md`.
- Анти-вода сверх фиксированного стоп-листа - `strategy-verifier`.
